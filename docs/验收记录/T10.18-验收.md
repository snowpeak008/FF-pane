## 1. 对照 §7.4 和本单

**命令形态。** 项目 `.grok/hooks/ffpane-workbench.json` 的 command 只有程序的绝对路径。能直接启动的条件是：绝对路径，且没有空格、管道、`&`、`$`、重定向、引号、反引号、分号、括号。带这些符号的字符串写不进去，函数会拒绝。文件里没有 `args`，没有 `env`。

**路径里有空格。** 安装目录有空格、本地数据目录也有空格（或没有备用目录）时，不写钩子文件，这个窗口的投递标记是手动，启动参数里仍然有 `--trust`。安装目录有空格、但备用目录没有空格时，会把 exe 复制到那份没有空格的路径，钩子里只写复制后的路径。原来带空格的路径不会出现在文件里，也不会拼成交给 cmd 的命令。复制失败同样不写钩子。

**什么时候按回车。** Stop、StopFailure、StopCancelled 记成回合结束。没有未决权限、输入和输出都静过，才写入排队的那一行，回车单独再写一次。PermissionDenied 和 `permission_prompt` 记成权限等待，未决计数加上，立刻发送也被拒绝。权限还在时，后面的 Stop、StopFailure、StopCancelled 不放行。只有「这一轮因批准被拒绝或取消而结束」才会放开，然后才允许自动继续。其它通知（例如 idle）忽略，不当成说完了。

**没有信号。** 还没收到回合结束时，状态保持未知。把时间往后拨一分钟也不会写。输出静默只是回合结束之后的附加条件，不能单独把窗口判成空闲。

**令牌和对话编号。** 钩子文件里只有程序路径和超时。窗口令牌在这个 Grok 进程的环境里，钩子程序运行时读取，再经本机命名管道送回。文件和 exe 里没有写死的令牌值，也没有密钥。管道先按令牌认窗口；这个窗口自己的对话编号和上报的编号都有、且不一致时，这条事件丢掉，不会按回车。缺一边时不拿它否决，避免 Grok 没带上编号就把自动继续弄丢；这时仍然只会作用到持有该令牌的那个窗口。

**不写用户目录。** 钩子写在项目的 `.grok/hooks/`。目标落在用户的 `~/.grok`、`~/.claude`、`~/.cursor` 时拒绝，后面的写入不会执行。`--trust` 只是启动参数，由 Grok 自己在第一次运行时记住这个项目；这次检查没有启动 grok，所以没有新的写入。产品代码没有写 `~/.grok/config.toml` 的路径。

**使用说明。** 写了：说完以后排队的提醒可以自动继续；正在等批准时不替你按回车；第一次打开会记住这个项目可信；钩子程序的路径里有空格就装不上，要自己点立即发送；不会因为等了一会儿就把字写进终端。中英文界面上，没装上信号时的提示与此相同。
