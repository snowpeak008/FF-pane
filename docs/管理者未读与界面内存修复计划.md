# 管理者未读与界面内存修复计划（T11.0e）

> 状态：Tony 2026-11-06 报问题：管理者经常不能及时看、及时回未读消息，尤其在他回答和说话前后；项目会断开；内存还是很大。同日查完记录，Tony 选了要改的几项，已提交（1.0.22），待验收，见 [验收办法](./验收记录/1.0.22-管理者未读与界面内存-验收办法.md)。
>
> [内存优化](./内存优化计划.md)（T11.3）管的是「少开 CLI 进程」，仍暂缓；本计划只管界面进程一直涨。

## 1. 现场证据（2026-10-28 至 11-06，《海上生存日记》，只读）

### 1.1 内存

- 日志每 5 分钟一行：**界面进程每小时涨约 1GB**，一直涨到 14–18GB；主进程一直 100–400MB，显卡进程约 200MB。
- 11 月界面进程因内存耗尽被杀 4 次（`renderer gone: reason=oom`），自动重载：10-29 22:50、10-31 15:23、11-02 13:40、11-04 22:52（北京时间）。重载期间界面「断开」，终端在主进程里不受影响。
- 涨得快慢跟着终端输出走：没人干活的晚上几乎不涨。

### 1.2 管理者看未读

按 `index.jsonl` 每条发给管理者的消息，到管理者第一次读到（hook 附正文、`ffpane_read_inbox`、`ffpane_wait_events`）算延迟。重要的（卡住、失败、用户拍板、监管者汇报）共 943 条：

## 2. 原因

1. **WebGL 字形图集只涨不清。** `@xterm/addon-webgl` 0.19 的图集按字体、主题、缩放在所有终端之间共享一份，有终端开着就不释放，也从不自动清空（`clearTexture` 只有应用调 `clearTextureAtlas()` 才跑，FF-pane 从没调过）。每种「字 + 前景色 + 背景色」占一格，中文、代码高亮、diff 底色、渐变的「Thinking…」会让它一直涨；页满了 4 页合成一页两倍边长，上限是显卡的 `MAX_TEXTURE_SIZE`；合并掉的旧画布要等垃圾回收。实测见验收办法 §2。
2. **开发模式下每次挂载漏一份 WebGL。** `main.tsx` 开着 `StrictMode`，双击 `FF-pane.exe` 跑的是 `pnpm dev`：每个终端先挂一次再卸掉。`TerminalView` 异步加载 WebGL，加载完时第一份 xterm 已经销毁，插件照样装上去，从此没人释放，连带那份终端一起留在共享图集的持有者里。
3. **批准权限 / 回答提问后提醒停住。** 真 Claude 的 PermissionRequest 不带 `tool_use_id`，按摘要记账；PostToolUse 只按 id 销账。T10.15b（10-01）起摘要「只加不减」，于是批准过一次，窗口一直是「等批准」，所有提醒停到用户再发一句。管理者开的是 YOLO，平时不弹权限，只有 `AskUserQuestion` 的提问框会触发：记录里 7 次答完提问后停 5–32 分钟。
4. **用户自己说话时，管理者不知道有未读。** 只有平台打进去的 `[新消息]` 才附正文。用户发话后提醒要等这一轮结束、输入框空着 1.5 秒；来回说话时一直等不到。
5. **API 出错暂停时，用户的拍板也被记进待处理。** 暂停时平台不往终端打提醒（Tony 10-22 定的规则），连用户自己的拍板结果也一样：11-01 07:12、11-04 07:40 的拍板晚了 45–129 分钟。管理者没有上级，暂停的通知谁也收不到，界面上只有一个「上次出错」小标签。
6. **Claude 里换对话，平台不知道。** Codex 的编号由 notify 报来，Claude 没有对应的上报；界面也只在窗口显示着时才记新编号，写回布局还会把旧的盖回去。

## 3. 改什么

### 3.1 界面内存（1、2）

- 新模块 `renderer/.../webgl-pool.ts`（不碰 DOM，单测直接测）+ `terminal-webgl.ts`（真 addon 的装卸）。所有终端的 WebGL 由它装卸：
  - 图集超过 64MB，把所有终端的 WebGL 一起卸掉重装，旧图集随最后一个持有者释放；
  - 合并掉的页、释放后的图集画布当场清成 0×0；卸载时用 `WEBGL_lose_context` 主动释放上下文；
  - 装之前终端已经销毁（或又重装了一次），不再装上去。
- `TerminalView` 改用它，删掉原来的 `tryLoadWebgl`。
- 界面每 5 分钟在控制台写一行 `[renderer-mem]`（JS 堆、终端数、WebGL 数、图集大小、重装次数、DOM 节点数），重装时也写一行；主进程把这些行收进日志。以后界面再涨，分得清是哪一块。
- 日志不再每个钩子、每次工具调用写一行 `[wb-control] accepted`。

### 3.2 批准、回答后提醒自动恢复（3）

- `idle-deliver.ts` 的 `notePromptReady`：窗口是「等批准」，但只剩按摘要记的、无法配对的未决（按 id 配对的照旧不动），而且输出安静很久（8 秒）、屏幕上是空闲的输入框时，清掉这些未决，判为空闲，排着的提醒照常投。
- `prompt-ready.ts`：监视器也看「等批准」的窗口，和「忙」一样要安静 8 秒才看。确认框（`❯ 1. Yes`、`Do you want to`、`Esc to cancel`）认不成输入框，所以框开着时永远不会往里打字。
- 横幅文字改成「确认框关掉、窗口安静几秒后会自动接着发」。

### 3.3 用户发话时附一句未读（4）

- `mcp-tools.ts` 新增 `peekInboxNotice`：「[平台] 你的收件箱另有 N 条未读（来自 …），不在用户这句话里。先回应用户；回应完调用 ffpane_read_inbox 看完再结束这一轮。」不读正文、不标已读，没有未读返回空串。
- 控制通道新增 `inbox-peek`；`workbench-hook.ts` 的 UserPromptSubmit：平台提醒照旧取正文（`inbox-digest`），用户自己的话取这一句（`inbox-peek`）。
- 只有 Claude / DeepSeek 有这个 hook，Codex 没有。

### 3.4 暂停时拍板照常送达、明显提示（5）

- `remind`：来自用户本人（拍板结果）的消息，窗口暂停也照常打进终端，不记进待处理。用户的拍板就是「用户的指令」，不违反 10-22 的规则；别人的汇报仍按规则记进待处理。
- 运行状态多一个 `apiPaused`；标题栏暂停时显示黄色「已暂停：原因，等你发话」，代替红色「上次出错」。

### 3.5 记住 Claude 里换过的对话（6）

- `workbench-hook.ts`：Claude 的 SessionStart、UserPromptSubmit 上报 stdin 里的 `session_id`（只取这一个字段，格式不对不报）。
- `handlers.ts`：Claude / DeepSeek 窗口报来的编号和记的不一样，就记下（`claudeSessionOf`）并发「认领」；改模型、重启时续接用它。Grok 的编号核对照旧，只对 Grok 窗口。
- `WorkbenchFlushBridge`：一直挂着的桥收「认领」事件写进布局，窗口不在当前标签页也记得上，Codex 窗口原来的这个缺口也一起补上。`TerminalView` 只换自己续接用的编号。

## 4. 不做（Tony 2026-11-06 没选）

- 管理者的 Claude 进程自己退出时提示用户。
- 中转 503 这类临时故障的自动续接改成逐步拉长间隔（仍是 30 秒、最多 3 次，然后暂停）。
- 代码排查里发现、这次没改的：在线等事件被打断时下一条消息会丢、之后工具调用卡最多约 9 分钟；提醒没提交成功就不再提醒；Grok 窗口没有兜底；看屏幕判断输入框有字偶尔误判。

## 5. 风险

- 图集重装时所有终端会重画一次。实测极端输出下约 40 秒一次，平时应该很少；重装次数写在日志里。
- 屏幕识别依赖 Claude Code 2.1.302 的样子。Claude 改了输入框的画法，摘要记的权限闩就退回旧行为：等用户再发一句。
- 未读提示让管理者回应完用户后去读收件箱，这一轮会稍长。
