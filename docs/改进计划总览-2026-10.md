## 2. 已定的事

- **jcode 不用。** 它是另一个编程 agent，不是给 Claude Code 降内存的工具。换它要重做整套 CLI 适配，还要用订阅账号登录第三方程序。内存问题走内存优化计划（暂缓）。
- **只借思路，不抄代码。** cc-pane 是 GPL-3.0，superset 是 Elastic License 2.0，zf3d_agent 没有协议文件（默认保留所有权利）。三家的内容和我们的内容分开放；以后真要用哪一段，当第三方内容单独评估。
- **代码精简、独立、少依赖（Tony 2026-10-24）。** 每个任务的核心逻辑做成独立的纯函数模块，单测直接测；界面和 store 只调用它；能不加新库就不加。
- **规则靠代码，用法靠手册，能力靠工具。** 会出事的规则（并发、权限、子 agent）不写进按需手册，写进常驻说明书并用代码拦住。手册只放低频、长、需要判断、漏了也不致命的流程。重复的、步骤固定的事写成代码或 MCP 工具。
- **不留子 agent，执行也不留。** 子 agent 原来干的小活交给看得见的「调研小窗」：执行发请求，监管者（不在线时管理者）开只读的调研窗口，结论交回提请求的窗口。内容不脱离管理者；监管者有活干，不当挂件。
- **一个项目只有一个管理者。** 计划讨论由管理者主持，评审窗口只读，不开多个管理者互相指挥同一批文件。
- **标签栏 48px 高，标签 160px 宽。** Tony 要求长高都翻倍；superset 用的就是这组尺寸。
- **终端是每页固定 6 格，不上无限画布。** 横向 3 列 × 2 行，竖向 2 列 × 3 行；空格留着，关窗不挪别的；拖分隔线只改相邻的；「向右 / 向下分屏」落到右边 / 下面的空格，没有就开新页。
- **团队视图与状态提示不做。**
- **分工三层：** 能写死的规则由代码拦；监管者（便宜模型、low）只查「有没有」；要判断「对不对、值不值」的交管理者或临时的评审窗口。谁在线、谁掉线由平台每 30 秒检查，不靠 AI 互相汇报。
- **内存优化暂缓，放最后。** Tony 已换了设备。
- **不写用户目录。** hooks、手册、配置都按会话传给 CLI，不写 `~/.claude`、`~/.codex`。cc-pane 和 superset 都因为写全局配置出过事（误删用户 skill；hook 在别的终端里也触发）。
- **画板是项目图库。** AI 窗口可以删图，但只能删 Tony 确认不要的；Tony 也能删；两种都进回收站，彻底删除只有 Tony 能做。今天被删的图开发时按当时的情况找回，张数到时再定。
- **FF-pane 的 Codex 窗口不读也不写 Codex 全局记忆。** 只加会话级参数，不改 `config.toml`。用户个人记忆里来自 FF-pane 的总结：过期的清掉，没过期的保留并整理成项目记忆给管理者读。
- **输入框里有用户的字就不投递**，等用户发完再按顺序投，不做「绕过用户输入直接提交」。
