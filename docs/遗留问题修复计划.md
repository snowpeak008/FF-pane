## 2. 要修的（建议优先做）

### 2.1 关窗、重开前提醒还在跑的后台任务

- **现象**：11-13 重开 FF-pane 时，团队第十一轮 Unity 大跑（force11）被一起结束；force10 也是随旧会话关闭没的。关窗、退出时没有任何提示。
- **原因**：FF-pane 自己的设计。每个终端窗口的进程圈在一个 Windows Job Object 里（`terminal/manager.ts` 的 `assignProcessToNewJob`，`KILL_ON_JOB_CLOSE`，T8.2 起），窗口一关，里面所有进程一起结束，本意是不留孤儿进程。Claude 窗口用后台命令起的 Unity 也在这个 Job 里。
- **改法**：
  - 关窗、退出、关单个窗口前，查每个 AI 窗口 Job 里的进程（`JobObjectBasicProcessIdList` 取进程号 → 进程名），去掉 CLI 自己的进程树（claude / codex / node / bash / conhost 等），剩下的就是「后台任务」。
  - 有后台任务时弹框，列出窗口名、进程名、已跑多久、占多少内存，按钮「等它们跑完」「照样关」。「等它们跑完」只是取消这次关闭，不做排队。
  - 1.0.31 看门狗的强退不受影响：卡死时照样强退。
- **不做**：让后台任务脱离 Job 继续跑（Windows 不能把进程移出 Job；要在创建时带 `CREATE_BREAKAWAY_FROM_JOB`，命令行工具做不到）。
- 工作量：中。

### 2.2 窗口进程组内存超线报警（不做）

- 工作量：小到中。

### 2.3 终端输出流控实际上没起作用

- **现象**：主进程给每个终端设了流控（`terminal/output-flow.ts`：没回执的超过高水位就先攒着，攒太多就整体重发），但实际上从来不会触发。
- **原因**：输出事件广播给所有终端视图；不是自己的输出，别的视图也立刻回执（`TerminalView.tsx` 订阅 `terminal:output` 那段，「不是这个视图的也回执」）。一段输出被回执 N 次，`unacked` 一直贴着 0。
- **改法**：只有挂着这个终端的视图回执；没挂的终端由主进程那边按「没人看」处理（已有 attach 引用计数）。要配一条测试：界面卡住时主进程那边攒的输出不超过上限，恢复后整体重发。
- 工作量：小。

## 3. 小问题（顺手做）

- **3.1 视图卸载后还挂着订阅**：`TerminalView` 里接终端（`spawnTerminal` / `attachExisting`）是异步的，视图在等的时候被卸掉，之后仍会登记 attach、写已销毁的终端，主进程以为还有人看。快速切项目、开发模式双挂载时会碰到。改法：异步回来先看视图还在不在。
- **3.2 字形缓存不算进回收上限**：图集超过 64MB 就整体重装（`webgl-pool.ts`），但 xterm 的字形缓存是 JS 对象，不在这 64MB 里。隔离复现（256 色加随机汉字）150 秒 JS 堆涨 300 多 MB。现场没碰到。改法：`[renderer-mem]` 里加 JS 堆精确值（现在的 `performance.memory` 够用），超过 1GB 时也触发一次整体重装。
- **3.3 日志时间是 UTC**：比本地晚 8 小时，Tony 自己看日志容易看错。改成本地时间带时区（如 `2026-11-13 18:00:09+08:00`），日志文件按本地日期分（现在已经是）。
- **3.4 17:30 那份 GPU 崩溃是哪一份**：正在用的那份日志没有 GPU 异常，dump 却在它的数据目录里。下次碰到时看 dump 里的进程号对应哪个主进程；`[diagnostics]` 启动行里加上主进程号，方便对。

### 9.1 现在的问题

- **标题栏挤爆**：6 个窗口时窗口名被截成「Claude...」「监...」「修-...」，后面挂着一长串小标签。一个窗口最多同时挂：种类、`YOLO`、角色、`由你开启`、`技能 1`、`运行中`、`上线`、`已完成`、`空闲`、`0.4 GB · 2 个进程`、`· 中转 … · CLI 默认模型 · CLI 默认强度`。
- **意思重复**：「运行中」（进程在不在）、「空闲 / 忙」（在不在干活）、「在线监管中」、「上线 / 下线」按钮文字，一个标题栏里最多 4 个相近的状态。
- **每个窗口多出一两行**：会话栏（会话号、「续接当前对话」「开新对话」「从历史续接」）每个 AI 窗口都有；管理者窗口还有一行压缩设置，带三句说明。
- **终端上方的提示条很长**：待投递 + 等批准 + 说明 + 取消说明，合起来约 130 字；Grok / Cursor 手动模式那条 50–85 字，整个会话都在、关不掉。
- **顶部常驻**：「工作目录：完整路径」（和左边选中的项目重复）、「可用内存 … · 磁盘 C: …、D: …」整行、标签页的「团队：」前缀、「画板 · 待检查 1236」文字按钮。
- **没有悬浮提示**：运行状态徽章、模型路由、内存磁盘行全都没有，截断了就看不全。

### 9.2 原则

1. **一直显示的只留两类**：认窗口用的（种类图标、窗口名）和**要你动手的**（等批准、出错暂停、受阻、未读、待你拍板）。要你动手的照旧醒目，不藏。
2. **其余收进悬浮提示**：鼠标停在窗口名或状态点上，一个提示框里分行列全（角色、权限、谁开的、技能、模型路由、内存进程、持锁等锁、会话号、上次汇报）。一个标题栏只挂一个提示框，不再每个小标签各挂一个（11-13 查内存时，标题栏上成串的提示框组件正是重画最多的部分）。
3. **能用图标的按钮用图标加悬浮提示**；主要操作（如「新建项目」「续接上次会话」）保留文字。
4. **说明文字不常驻**：解释性的句子改成按钮或 ⓘ 图标的悬浮提示。
5. 终端里 CLI 自己打印的内容不归这次管。
