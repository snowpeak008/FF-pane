### B. 受管 HOME 隔离（本单最要紧之一）

**读码。** 替换位置 `command.ts buildIFlowEnv`（:76-84）：`USERPROFILE` + `HOME` 双设指向 `managedHome`（注释:70-74 明示 Node `os.homedir()` 在 Windows 读 USERPROFILE、POSIX 读 HOME，双设跨平台稳；iFlow settings 恒在 `os.homedir()/.iflow/` 不受 IFLOW_HOME 影响，调研坑 5）。受管 settings 落位 `adapter.ts:161-165 ensureManagedSettings`：`<managedHome>/.iflow/settings.json` 写 `IFLOW_MANAGED_SETTINGS_JSON`（幂等覆写）。settings 常量 `command.ts:99-103`：`{"selectedAuthType":"openai-compatible"}` 一行——**三件套不落盘**，全走 env。desktop 装配 `index.ts:161 iflowHomeDir: join(layout.rootDir, "iflow-home")` → `registry.ts:197 createIFlowAdapter({ managedHome: options.iflowHomeDir })`（进程级常量，非按 Profile）。

**独立复测（不经适配器代码，按实现同款 env 替换直接起真 iflow 0.5.19）。** 探针脚本按 `USERPROFILE=HOME=<临时受管目录>` 起 iflow，四判据：

> 复测踩坑登记（不影响结论，仅记方法）：headless 路径经 `spawnSync(..., {shell:true})` 会挂（模型端零调用、超时）——iFlow headless 在 `spawnSync` 同步阻塞下的 stdin/事件循环时序问题；改 `spawn` 异步 + `stdin.end()` 即 exit 0 正常走通。ACP 路径（适配器实跑通道）与异步 headless 均无此问题，故 B 项结论以 ACP + 异步 headless 两条各证一次为准。

## 2. 抽查发现

**未发现影响结论的缺陷，红线全部未破。** 以下如实登记：

1. **（live 复跑登记，§1-H 引用）live-iflow 四跑 2 过，挂住集中在 R1 起轮段。** 中断前实跑三次：首两跑 R1 挂住（起轮段无事件推进，轮次超时收尾），第三跑 11 判据 ALL PASS；本收尾续跑再复核一次，**一遍 ALL PASS**（全程 135 s，dist 重建后）。挂住形态与 §4.5 第五条（iflow `--experimental-acp` experimental 前缀的漂移/真机偶发风险）同域——真机 CLI 偶发起轮不举，复跑即绿，按名单纪律「触发则复跑绿即登记」处理，不影响结论；备查，若触发率上升再立单。
2. **（新 flake 形态，不在 §4.5 五条名单内）`grok-build.test.ts`「headless 模式不实现 respondPermission」用例在全量首跑 5 s 超时。** 本验收全量第 1 跑 2080/2081，唯一红条即该用例（`Test timed out in 5000ms`）；单独复跑该文件 **28/28 全绿**，随后全量连续三跑 **2081/2081 × 3** 均未复现——负载型 flake（全量跑时 transform/import 耗时膨胀，首跑该轮 transform 39 s / import 133 s，5 s 默认超时被环境噪声撞线），与 opencode env 指纹用例同型（后者已在 `09b28ec` 加 45 s 时序钉子）。与本单交付零关联（grok-build 是 T7.3a 存量用例，本单未触碰该文件——§1-G 改动面核实过）。建议下一单顺手加同款 timeout 钉子；列 §5 待裁定。
3. **（正面观察）坑 2 记账双入口，fail-closed 不留缝。** 回执 deny 的当场（`acp-turn.ts:306-310`）与 payload 不可映射的 fail-closed 分支（:277-286）**两处都** `registerDenied`——无论权限请求能否映射成统一 payload，拒绝都会进阻断清单参与 end 改判；轮次收尾时未决权限一律 resolve("deny")（:412-414），无悬挂请求泄漏。防线不是单点。
4. **（正面观察）失败路径共用一个记账出口，探针④一石四鸟。** noauth 第一道闸、-32000 兜底闸、set_mode 纪律闸、spawn 失败四条失败路径全部汇入 `mapper.registerError`（reason 恒 failed）——§3 探针④把该出口改判 completed 后四条用例同时红，「如实收尾、不把失败伪装成成功」（A 项精神）被四个方向同时钉死。
