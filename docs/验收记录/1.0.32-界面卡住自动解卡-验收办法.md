# 1.0.32 界面卡住自动解卡 —— 验收办法（T11.13）

> 计划：[`docs/主进程卡死与残留清理计划.md`](../主进程卡死与残留清理计划.md) §7。开发 2026-11-13，尚未验收。

## 前提

- 关掉 FF-pane 再双击打开（改动在主进程，重开后才生效）。打开后日志第一行是 `FF-pane 1.0.32 started`。
- 日志在 `~/.aiworkbench/logs/main-日期.log`（时间是 UTC，比本地晚 8 小时）。

## 步骤（真遇到界面卡住时验）

1. **GPU 进程卡死**（11-13 那种：内存耗尽后界面点不动）：卡住约 30 秒后，日志依次出现 `still unresponsive after 30s; gpu process: ...`、`gpu process used almost no cpu while the window hung; restarting it`、`killed gpu process`，**不弹框**，界面几秒内恢复，随后有 `window responsive again`。终端里的 AI 窗口不受影响。
2. **结束 GPU 进程也没缓过来**：再过 15 秒弹「界面已经 N 秒没有响应」，日志有 `asking whether to reload the unresponsive renderer`。选「重新加载界面」和 1.0.31 一样：先结束 GPU 进程再重载界面。
3. **弹框开着时界面自己缓过来**：弹框自动消失，日志有 `closing the unresponsive prompt`；之后正常关窗不受阻。

## 已做的检查（开发时）

- 现场证据：11-13 的界面、GPU 进程线程栈（配 Electron 44.0.0 符号），结论见计划 §7.2；现场结束 GPU 进程后界面 1 秒内恢复，证明这样能解开。
- 单测：`tests/diagnostics-policy.test.ts` 新增 `isGpuStuck`（同一进程 CPU 几乎没走判卡死；在干活、进程换了、拿不到数都不判）。全量单测 2880 条通过。
- e2e：`tests/e2e/diagnostics.spec.ts` 新增一条：发出「没响应」事件后约 30 秒自动结束 GPU 进程、换了新的 GPU 进程，15 秒后弹框，发出「恢复」事件后弹框自动收起，界面正常。说明：Chromium 只在有真实系统输入等着处理时才判没响应（合成输入不算），测试里直接发事件，没有动鼠标键盘。整份 diagnostics e2e 5 条通过。
- 探测：Electron 44 在 Windows 上 `getAppMetrics()` 的 `cpu.cumulativeCPUUsage` 有值。
