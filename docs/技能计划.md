## 1. Tony 定的事（2026-11-07）

1. **只做功能，不带技能。** FF-pane 不内置、不打包任何技能。用户自己下载技能，导入到 FF-pane 的技能库，库里的技能所有项目共用。
2. **每个项目单独选。** 每个项目自己勾要用哪几个技能。没勾的技能在这个项目里不生效，新项目一个都不勾。
3. **用不了要说清楚。** 技能导入后、或在项目里启用时，激活不了就说明原因。只适用于 Claude 或只适用于 Codex 的技能，要写明它适用于哪一家。
4. **可以改显示名。** 原名不变，AI 看到的也是原名。改的名字只用于界面显示和搜索。
5. **生图改走技能。** 设置里的「先不生图 / Codex 订阅 / 中转站」三种方案和 `ffpane_generate_image` 都去掉，项目要出图，就启用一个生图技能。
6. **生图技能用 codex-image-studio，不用 api-image。**（Tony 2026-11-07 后来定）配置由 Tony 自己填在技能里，和本机 Codex 的登录、配置互不相干。模型现在是 image 2，已经出了 2.6，以后还会换，改配置里的模型名就行，不改代码。

## 2. 现场核对（2026-11-07）

### 2.1 codex-image-studio 是什么

来源 `github.com/anklecrusher/codex-image-studio`，MIT 协议（核对的是 1363611，2026-07-23，副本在 `test-results/external/codex-image-studio`，没运行过）。

- 结构：`SKILL.md`、`scripts/generate_image.py`（只用 Python 标准库）、`agents/openai.yaml`（Codex 的界面信息）。作者说是给 Codex 写的，但只是一份说明加一个 Python 脚本，Claude 也能照着用。
- 配置三项：`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`IMAGE_MODEL`（默认 `gpt-image-2`）。换模型只改 `IMAGE_MODEL`，脚本不检查模型名。
- **现在还不是独立的**，原样拿来有三处不符合 Tony 要的「和本机互不相干」：
  1. 配置文件默认读 `~/.codex/secrets/image_api.env`，这一份是本机所有 Codex 共用的，不在技能里。
  2. 进程环境变量优先于配置文件。窗口环境里只要有 `OPENAI_API_KEY`（比如某条配置走 API 密钥），就会悄悄用那个账号出图。
  3. SKILL.md 让 AI 第一次用时去 `~/.codex/secrets/` 建模板。T11.8 以后，Claude 的写入检查和 Codex 的沙盒都会拦下这一步。
- **自带脚本只能出新图**（只调 `/images/generations`）。改图、参考图、蒙版要退回 Codex 自带的 `~/.codex/skills/.system/imagegen/scripts/image_gen.py`，那个脚本要装 `openai` 这个 Python 包（本机 3.12 装了，3.14 没装），还要求密钥在环境变量里。这样改图又依赖本机 Codex，也不独立。

### 2.2 本机现状

- 本机有 Python 3.12 / 3.14。`python` 指向 3.12。
- `~/.codex/auth.json` 是订阅登录，`OPENAI_API_KEY` 是 null。codex-image-studio 不读这个文件，所以没关系。

### 2.3 Codex 沙盒里命令到底能不能联网（2026-11-08 重测）

1.0.25 写的「沙盒里的命令连不上网」**不准**。2026-11-08 用真 Codex 会话（`codex exec`，和 FF-pane 全部权限一样的 `-s workspace-write -a never -c sandbox_workspace_write.network_access=true`，本机 `[windows] sandbox = "elevated"`）重测：

| 沙盒里跑的命令 | 结果 |
|---|---|
| Python `urllib` 访问 `https://example.com`、`https://www.bing.com`、`http://127.0.0.1:18999` | 都通 |
| `curl.exe` 访问 `https://example.com` | 不通：`schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS` |
| PowerShell `Invoke-WebRequest` 访问 `https://example.com` | 不通：「基础连接已经关闭」 |
| `curl.exe` 访问 `http://127.0.0.1:18999`（不加密） | 通 |
| 把 `network_access` 改成 `false`，Python 照样访问 | 也通。这台机器上这个开关实际不起作用 |

结论：

- **网络本身没被拦。** 拦住的是 Windows 自带的 HTTPS（schannel）：沙盒进程拿不到当前用户的凭据，`curl.exe`、PowerShell 这类走 Windows 自带加密的工具在沙盒里访问不了 `https://`。1.0.25 测的是这一类，所以得出了「不能联网」。
- Python 自带加密库，不走 schannel，所以 **codex-image-studio 在 Codex 窗口里能直接用**。Tony 的中转站在 `http://127.0.0.1:18318`，不加密，任何工具都能连。
- 写项目外照样拦：同一沙盒里往 `D:\WorkWork\Assist\` 写文件是「拒绝访问」。
- 所以**不需要工作台代跑**，原来写的 `ffpane_run_skill_script` 删掉（§5.5）。

以后有技能用 `curl.exe` 或 PowerShell 访问 `https://`，在 Codex 窗口里会失败。技能库只提示一句，不替它想办法。

### 2.4 Codex 的联网白名单（2026-11-08 试过，先不用）

Tony 问能不能给沙盒加白名单。Codex 0.166 有两样东西：

1. **联网白名单** `features.network_proxy`（实验功能，能用 `-c` 按会话传）：`-c features.network_proxy.enabled=true -c 'features.network_proxy.domains={ "example.com" = "allow" }'`。实测一打开，命令就被整个拦下：「example.com 被拦：本地或内网地址被沙盒策略禁止」。原因是本机开着 Clash（`127.0.0.1:7897`），用的是假 IP 模式，所有域名都解析成 `198.18.x.x` 这类内网地址（`example.com -> 198.18.0.21`），代理把它们一律当内网拒掉。Tony 的中转站在 `127.0.0.1`，同样会被拒。
2. **命令白名单** `~/.codex/rules/*.rules` 里的 `prefix_rule(..., decision="allow")`：官方说明是「不提示，直接在沙盒外跑」。只能放在 `~/.codex/rules/`，或者受信任项目的 `<项目>/.codex/rules/`，不能按会话传；而且在沙盒外跑的命令能写项目外，等于给 T11.8 开口子。

结论：现在网络本来就没拦（§2.3），技能不需要白名单。两样都先不用：

- 联网白名单是**收紧**，不是放行：打开以后，只有名单上的域名能连。等 Codex 把它做稳、能处理本机代理的假 IP 和本机中转站，可以再考虑「每个技能写明要连哪些域名，只放这些」。
- 命令白名单不做：要写用户目录或项目目录，还会让命令跑到沙盒外。

**顺带发现（T11.8 的口子，没动）：** 本机 `~/.codex/rules/default.rules` 里已经有一批以前点过「总是允许」留下的规则，比如 `git push`、`npm.cmd install`、`python -m pip install --user`，还有几条带 `Remove-Item` 的 PowerShell 长命令。照官方说明，这些命令在 FF-pane 的 Codex 窗口里也会在沙盒外跑，不受「不写项目外」限制。要不要处理、怎么处理，记进 [项目外写入限制计划](./项目外写入限制计划.md)，等 Tony 定。

### 2.5 用 Tony 的中转站实测（2026-11-08）

Tony 在 `image_api.env` 里填了 `http://127.0.0.1:18318/v1`、`gpt-image-2.6`，出图报「连接被拒绝」。排查：

- 本机的中转站是 SSH 隧道（`fuwuqi/Start-CPA-Tunnel.ps1`）：本机 `127.0.0.1:18317` 转到服务器上 CLIProxyAPI 的 `8317`。18318 上没有任何程序。`fuwuqi/CPA-Tunnel-使用说明.txt` 写的 OpenAI 兼容地址是 `http://127.0.0.1:18317/v1`。**`/v1` 要写，错的是端口。** 脚本只在地址后面接 `/images/generations`，不会自己补 `/v1`。
- 这个中转站上没有 `gpt-image-2.6`，返回 400，并列出能用的：`gpt-image-1.5`、`gpt-image-2`、`gpt-image-2.5`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`，另有 `grok-imagine-image` 几个。
- 不改 Tony 的配置文件，测试时临时换地址和模型：`gpt-image-2.5` 出新图 49 秒，拿它改图（`/images/edits`）104 秒，构图保留、改成了雷雨夜。图在 `test-results/skill-test/`。
- 要的是 1024×1024，两张都是 1672×941。这个中转站或模型不照 `size` 出图，以后要固定尺寸时得再看。
- 在真 Codex 会话的沙盒里（和 FF-pane 全部权限一样的参数），用同一份配置访问这个中转站，正常返回模型列表。
- 中转站要靠 SSH 隧道开着。隧道没开时，技能会报「连接被拒绝」；SKILL.md 已补一句：遇到这个就告诉用户中转站或隧道没开，不要反复重试；模型不支持时把可用名单报给用户，让用户改 `IMAGE_MODEL`，AI 不自己挑。

### 2.6 画板不用为技能改

`canvas-watcher.ts` 盯着 `<项目>/.ffpane/canvas/`，新出现的图会自动收进画板、标成待检查。技能只要把图存到这个目录里，画板照旧能收到。

## 3. 技能库

### 3.1 放在哪

`<应用数据目录>/skills/<原名>/`，另有一份 `skills.json` 记每个技能的信息：

| 字段 | 说明 |
|---|---|
| `name` | 原名，取自 SKILL.md 的 frontmatter，不能改 |
| `displayName` | 用户改的名字，可空 |
| `appliesTo` | `any` / `claude` / `codex`，自动判断的结果，用户可以改 |
| `source` | 从哪个目录导入的，只是记录 |
| `importedAt`、`hash` | 导入时间和内容哈希，重新导入时用来判断有没有变 |

不写 `~/.claude/skills`、`~/.codex/skills`。技能自己的配置文件（比如 codex-image-studio 的 `image_api.env`）就放在库里这份技能的目录下，由用户自己填，不在任何项目里，也不进 git。导入时**复制**进库，不链接原目录，这样用户之后改了原目录，各项目也不会悄悄跟着变。

### 3.2 导入

设置 → 技能 → 「导入技能」，选一个目录（里面要有 `SKILL.md`）。以后可以再支持 zip。

检查顺序，哪一步不过就停下说原因：

1. 有没有 `SKILL.md`，frontmatter 里有没有 `name`、`description`。
2. 原名合不合规：小写字母、数字、连字符，最长 64 个字符（Claude 和 Codex 都按这个规则）。
3. 库里有没有同名的。有的话问「替换已有的 codex-image-studio？」，并列出哪些项目在用。替换时**保留用户填过的配置文件**：旧目录里有、新目录里没有的 `*.env` 等配置文件原样搬过去，不覆盖。
4. 列出将要复制的文件，提示一句：**技能里的脚本会以窗口的权限运行，只导入信得过的。**

### 3.3 判断适用哪一家

格式上没有统一的字段，只能猜，所以猜完让用户改：

| 看到 | 判为 |
|---|---|
| 有 `agents/openai.yaml` | 给 Codex 写的 |
| 有 `.claude-plugin/`，或 frontmatter 有 `allowed-tools` 这类 Claude 才有的字段 | 给 Claude 写的 |
| 都没有 | 通用 |

「给 Codex 写的」不等于只能 Codex 用。codex-image-studio 就是 Claude 也能照着跑的那种。所以界面上分开写两件事：**谁写的**（猜的，只当提示）和**适用于**。**适用于默认是通用**（2026-11-08 开工时改）：默认按猜的定，codex-image-studio 会被悄悄挡在 Claude 窗口外面，可它在 Claude 里也能用（§10 第 5 步实测）。真只能在一家用的，用户自己改成「只用于 Claude / Codex」。

Grok 没有原生技能（[按需手册计划](./按需手册计划.md) §3）。Grok 窗口只能拿到「技能名 + 一句描述 + 路径」，让它自己去读。界面上对每个技能都标一句：Grok 只能按说明读。

### 3.4 当前无法激活

每个技能在库里显示一个状态，项目里启用时也再查一次：

| 状态 | 原因举例 |
|---|---|
| 可用 | — |
| 当前无法激活 | SKILL.md 坏了；`scripts/` 里有 `.py` 但本机找不到 `python`；有 `.js` 但找不到 `node` |
| 有限制 | 只适用于 Claude（这个项目的 Codex 窗口不会挂）；脚本里用 `curl.exe` 或 PowerShell 访问 `https://`，Codex 窗口里会失败（§2.3） |

FF-pane 只查自己查得到的：文件结构、要用的程序在不在。像 codex-image-studio 的配置填没填，这种技能自己的条件，FF-pane 不去猜，等技能运行时报错，原样交回给 AI 和用户。

提示只出现在设置页和窗口信息里。**不弹窗，不抢焦点**，和「AI 输出不打断」一个规矩。

### 3.5 改名

库里每个技能都能改显示名。列表显示「显示名」，下面一行灰字写原名；搜索框两个名字都能搜到。清空显示名就恢复用原名。

AI 和命令行永远只看到原名，窗口说明里写的也是原名，所以改名不影响已经开着的窗口。

## 4. 项目里启用

### 4.1 存在哪

`projects.json` 里每个项目加一项 `skills: string[]`（原名列表），和 `outsideWriteDirs` 放在一起，只有用户在界面上能改，AI 改不了，也不写进项目目录。

缺省是空列表，也就是一个都不启用。

AI 不能自己给项目启用技能，也不能改名单。需要某个技能时，用 `ffpane_request_decision` 请示用户。

### 4.2 挂给窗口

开窗口时，按这个项目勾的技能、窗口用的是哪家 CLI 来挂。2026-11-08 真机核对（Claude Code 2.1.302、codex-cli 0.166.0，用一个只会回答暗号的探针技能）：

| CLI | 怎么挂 | 核对结果 |
|---|---|---|
| Claude（含 DeepSeek 窗口） | 在 `<数据根>/skill-mounts/<窗口>/` 生成插件目录：`.claude-plugin/plugin.json`（名字 `ffpane-skills`）+ `skills/<原名>`，后者是指向技能库那份的**目录链接（junction）**，不复制；启动加 `--plugin-dir <目录>`（每个目录一对参数，不会吞掉开场白） | 能用。`-p` 模式不弹信任提示。技能在窗口里叫 `ffpane-skills:<原名>`。Claude 会照常顺着链接读，脚本 `Path(__file__).resolve()` 落到技能库，读到的是用户填的那份配置。`~/.codex`、`~/.claude/settings.json`、`~/.claude/plugins` 都没变；`~/.claude.json` 里 Claude 自己记了一笔用量（`skillUsage`、`pluginUsage`），这是它对所有技能都会做的，不去动 |
| Codex | **不能用 `-c skills.config`**：实测传目录、传 SKILL.md 路径都不出现，它只能开关已经发现的技能。Codex 只从 `~/.codex/skills`、`~/.agents/skills`、项目里的 `.agents/skills` 发现技能，都要写用户目录或项目。改成把「名字 + 说明 + SKILL.md 路径」接在 `developer_instructions` 角色说明后面，和 Codex 自己列技能的写法一样 | 能用。模型按路径读 SKILL.md，答出暗号 |
| Grok | 同 Codex，接在 `--rules` 后面 | 没登录，没真机核对 |

- 适用于 Claude 的技能不挂给 Codex、Grok 窗口；适用于 Codex 的不挂给 Claude、Grok 窗口。
- 技能清单最多 4KB、每条说明最多 400 字，免得 Codex 命令行过长。
- 删挂载目录先拆链接、再删目录（Node 的递归删除本来也不顺着 junction 删，单测里照样核对技能库里的配置文件还在）。关窗、退出时删；启动时清掉上次崩溃留下的。
- 窗口标题栏显示「技能 N」，鼠标停上去列出挂了哪些、没挂哪些和原因；有没挂上的就标黄。不弹窗。

### 4.3 什么时候生效

勾选、取消后，**下一次开窗口才生效**，已经开着的窗口不变。界面上就写这一句，不自动重启窗口，要立刻用可以用窗口上的重启按钮。

## 8. 工作台管什么（2026-11-07 Tony 问，11-08 改）

### 8.1 工作台只负责摆放技能

Tony 2026-11-08 定：工作台就是摆放技能的地方，只做三件所有技能都一样的事：

- **显示**：技能库、状态、适用于哪家、在用的项目。
- **改名**：只改显示名。
- **挂载**：按项目、按 CLI，把技能挂给窗口。

技能的配置由用户自己填在技能目录里，工作台只负责打开那个目录。

不替技能跑脚本，也不把一个个技能改写成工作台工具。工作台工具（`ffpane_*`）只放要用到 FF-pane 自己数据、或者要用代码拦住的事：画板、消息、锁、记忆、权限。技能可以随时换、随时更新，改写成工具后每换一个都要改 FF-pane 的代码、发版本。生图从三种方案改成技能，就是为了不再这样。

### 8.2 技能库放设置，启用放项目

| 做法 | 问题 |
|---|---|
| 只在工作台统一开关，所有项目一样 | 花钱的技能（生图、配音）每个项目都挂上；常驻的技能描述越来越多，AI 容易选错；两个都写着「有我就别用别的」的生图技能会打架；不同项目要的本来就不一样 |
| 库和启用都放在项目里 | 同一个技能每个项目各导入、各填一次配置，更新也要一个个改 |
| **库放设置，启用放项目（建议）** | 导入、配置、更新只做一次；看着项目的时候决定它用什么，和「项目外可写目录」这类项目边界放在一起 |

### 8.3 不设默认

Tony 2026-11-08 定：新建项目一个技能都不启用，用户自己在项目里加。没有「新项目默认启用」名单。

每个窗口挂的技能建议不超过 5 个（[按需手册计划](./按需手册计划.md) §7）。项目里开到第 6 个时，在开关旁边提示一句，不拦。

### 8.4 常见的技能类型

| 类型 | 举例 | 要联网 | Codex 窗口里 |
|---|---|---|---|
| 调接口生成素材 | 生图（codex-image-studio）、配音、音效和音乐、视频、3D 模型 | 是 | 脚本是 Python 的能用；用 `curl.exe`、PowerShell 访问 `https://` 的不行（§2.3） |
| 抓网页、截图 | 用浏览器打开网页截图、抓资料 | 是 | 要实测（浏览器在沙盒里能不能起来） |
| 往外发 | 上传到网盘、发布到平台、发消息 | 是 | 能连，但每次都会对外发东西，不建议放进默认名单 |
| 本地处理文件 | Word、Excel、PDF、图片裁切、拼精灵图、抠背景 | 否 | 能用 |
| 只有说明的流程 | 写计划、评审、提问清单 | 否 | 能用 |

表里只是类型。除了 codex-image-studio 和 grill-with-docs，具体用哪个技能，等 Tony 找到了再一个个看。
