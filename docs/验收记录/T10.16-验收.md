## 3. 执行者留下的三点

**都属实，没有破坏安全规矩。**

1. **「可改文件」和「可改+跑命令」的启动参数相同。** 两边都是 `--permission-mode acceptEdits`，续接也一样。只读是 `plan`，全放开是 `--always-approve`。Grok 没有单独禁命令的档，命令仍由它自己询问。下级仍不能超过上级：只读上级压得住全放开。这不是把更危险的权限偷偷放出去。
2. **没有不接最近一条的选择器。** 没有编号就不起进程，参数里不会出现空的 `--resume`，也没有 `--continue`。有编号才续接这一段。新开用软件指定的 `--session-id`，并行不排队。
3. **没有回合结束信号，所以要手动发送。** Grok 窗口的投递标记是手动。队列在还没收到回合结束时保持未知，不会因为等了一会儿就把字写进去。用户点「立即发送」才会写入排队的那一行和一次回车。这符合「没有可靠信号时只允许手动发送，永不超时强写」。

## 4. 建议（非阻断）

1. 使用说明的权限表仍把「可改+跑命令」写成需要它自己跑命令。对 Grok 来说，这一档和「可改文件」的启动参数相同，命令仍会询问。全放开才会跳过询问。说明里可以加一句，免得选的时候以为已经放开了命令。
2. Grok 窗口的黄条写了收不到回合结束、请点立即发送，也写了不会把对话正文写进终端。它没有像 Codex 那样写明：这个按钮会把排队的字和一次回车写进当前终端，画面上如果已经有确认框就不要点。行为是对的，这句话补上更不容易误点。

## 7. 给 Tony 的手动试用

先确认本机 PowerShell 里输入 `grok` 能对话。软件不会替你登录。

1. **设置 → 配置**，编辑默认配置，勾上 Grok。本机已经登录过就选本机登录。要走中转，来源选 **Grok 中转**，地址和密钥都填。保存。
2. 打开一个项目，新建窗口，选 **Grok**，权限先用 **可改文件**，角色用 **普通**，打开。窗口上应显示本机登录或中转。
3. 到这个项目文件夹里看 `.grok/config.toml`。应能看到你原来就有的内容，以及工作台那一段。令牌应是 `${FF_PANE_WINDOW_TOKEN}` 这种占位，不应是一长串明文。不要把 `.grok` 提交进仓库。
4. 关掉软件再看：这个文件还在。你自己用户目录里的 Grok 配置不应被改掉。Cursor 里的 Grok 聊天不受影响。
5. 再开一个 Grok 窗口。两个都应能打字，不用等另一个先说完。
6. 权限：只读应是计划模式。可改文件和可改+跑命令，改文件会放行，跑命令仍会问你。全放开才会跳过询问，而且要额外勾一次。用一个只读的管理者去开下级，即使用全放开，也应被压回只读。
7. 自配置开关保持关闭时，配置文件里不应出现 `ffpane-config`。打开之后要新开窗口才带上。普通窗口调用应被拒绝。管理者起草后，要你点确认才保存。
8. 知识库开关同样：打开后新开或重开窗口才带上。关掉后再开一次 Grok 窗口，文件里的知识库段应消失。
9. 对话编号能复制。接着聊应带原来的编号。另起一段会换新编号。没有编号时，不应悄悄接上最近一条对话。
10. 窗口上应有黄条：收不到回合结束信号。有待投递时点 **立即发送**。这个按钮会把排队的提醒和一次回车写进终端。画面上如果已经有确认框，先不要点。
