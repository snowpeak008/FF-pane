## 3. 向量路真机验收（T6.3 / T6.4）

> 本节是 Phase 6 唯一一处此前只有单测、没有真机证据的地方。

**背景**：T6.3 的验证全程使用 `node:http` mock 端点；T6.4 只实证了 sqlite-vec 扩展
在 win32-x64 下装得上；T6.5 的百级文件导入走的是纯 FTS 路径。也就是说
「导入 → 真发 `/embeddings` → 向量落 vec0 → 双路召回 → RRF 融合」这条完整链路，
截至本次验收前从未被真实嵌入模型跑过。

**嵌入来源的选定过程**（记录下来是因为它排除掉了几条看起来可行的路）：

| 候选 | 结论 |
|---|---|
| DeepSeek | ❌ 实测 `GET /v1/models` 只返回 `deepseek-v4-flash` / `deepseek-v4-pro` / `deepseek-v4-flash-vision-exp` 三个对话模型；官方仓库 issue #652 实测 `/v1/embeddings` 返回 404。「OpenAI 兼容」指格式兼容，不是端点清单一致 |
| codex CLI 订阅 | ❌ `codex --help` 无嵌入相关子命令；它是 Agent CLI 而非 API 网关，订阅买的是 Agent 轮次 |
| 参考项目 cc-pane | ❌ 全仓 2495 文件无 embed/vector/sqlite-vec；其 `cc-memory` 的检索路径是 `FTS5 MATCH → 降级 LIKE → 纯过滤`，即**根本不做嵌入**。无可参考 |
| 本地 Ollama | ✅ 采用。配成 `openai_compatible` + baseUrl 带 `/v1` 即走既有 openai 方言，**零代码改动** |

脚本 `apps/desktop/scripts/live-embedding.mjs`。

**判据设计**：核心是**语义检索必须赢过关键词检索**——取一条与目标文档零字面重叠的
中文查询，纯 FTS 应当找不到、开了向量之后应当找得到。否则「向量路跑通了」只等于
「没报错」，证明不了那些向量真的承载了语义（维度对、数量对、内容是噪声的情形完全可能）。

**本次结果：未能执行，向量路真机验收记为待验项。**

三条嵌入来源在本次验收窗口内全部落空：

| 尝试 | 过程 | 结论 |
|---|---|---|
| DeepSeek（用户提供 key） | 用该 key 实打 `POST /v1/embeddings` 与 `/embeddings`，模型名试了 `deepseek-embedding` / `embedding-2` / `text-embedding-v1` / `deepseek-v4-flash` 共 8 种组合 | **全部 404，响应体为空**——不是模型名不对，是端点不存在 |
| 本地 Ollama | `winget install Ollama.Ollama`。安装包 1.565 GB，源在 GitHub releases | **三轮均失败**：本机到 GitHub 20–100 KB/s 且每次卡在 97% 左右不动。中途手工 curl 续传补齐后 **SHA256 与官方清单不符**（winget 的 Delivery Optimization 是分块乱序下载，其 `.tmp` 不是合法顺序前缀，续传把字节接错了位），校验拦下、未执行该安装包、已删除 |
| 远端嵌入 API | 硅基流动 / 智谱 / 阿里百炼均可，且**代码零改动**（配 baseUrl + 模型名即可） | 用户选择不注册新账号 |

对照：同一时段 `api.deepseek.com` 响应 0.15 s——本机网络对 API 正常，是 GitHub 这条线被限速。

**因此以下判据本次未取得证据，全部记为待验：**

- 真发 `/embeddings` → 向量落 vec0 → 双路召回 → RRF 融合 这条完整链路
- 索引维度与模型维度一致、模型 ID 登记正确
- 语义检索赢过关键词检索（本次取得了**对照组**数据：查询「怎么把一堆资料喂给模型让它自己去翻」
  在纯 FTS 下 **0 命中**——这正是向量路本应补上的那一块，一旦有嵌入源，该查询应当命中知识库设计相关章节）
- 「用户刚配上嵌入模型 → 给旧文档补向量」这条升级路线
- 嵌入阶段的断点续传在真机上的表现

**补验方式**（任一嵌入来源到位后，一条命令）：

```
OLLAMA_BASE=<baseUrl> OLLAMA_MODEL=<model> node apps/desktop/scripts/live-embedding.mjs
```

脚本已写好并具备两态：探到嵌入端点就跑完整向量验收，探不到就转入纯 FTS 验收——
与产品自身的降级行为同构（§8.3.3），而不是把一个一等状态当成环境错误直接退出。

**风险评估**：该缺口不影响 v0.7.0 的功能完整性。§8.3.3 明确「向量检索是增强，不是前提」，
纯全文检索路径已全面实证（§2.1、§2.2 的 Worker 真机调用走的也是这条路）。向量层有
91 项单测覆盖（含两后端同一套用例、两千块规模一致性、20 条中文检索抽测），
缺的是「真实嵌入模型产出的向量确实承载语义」这一条端到端证据。
