## 1. 对照 §13

**只在管理者窗口。** 滑块画在命令行窗口上，并且角色必须是管理者。执行者、规划、检查、监管者、普通窗口，以及不是命令行的窗口，都没有这块。启动时先认登记表里的角色；登记表里不是管理者，就算请求里写成管理者，也不传压缩值。管理者开出来的下级窗口不带这个比例。

**50 到 90，不指定就不传。** 只接受这个区间里的整数。49、91、0、100、小数、`"70"`、`"500k"` 都当成没指定。布局读回来时同样丢掉。勾上「不指定」就从窗口上拿掉这个字段，启动时不传。取消勾选后，滑块先停在 70%，这不是默认，默认仍是不指定。

**记在窗口上，下次才生效。** 比例写在这个窗口的布局里。权威表同步时保留这个字段。启动、重启、续接都从已经落盘的窗口记录读取，不从界面当场塞进启动请求。改滑块只改记录，不改正在跑的那一次进程。

**各家怎么传。** Claude 用现有上下文表：认得出的 Claude 家族是 `200000`，DeepSeek 家族是 `128000`。两个环境变量一起设，窗口值是十进制整数，不写 `200k` 这类单位。百分比另走 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`。Grok 只给这一次进程设百分比；滑块可以画到 90，传出去不超过 85，避免比它自己大约 85% 的默认更晚。Codex 把百分比乘在已知窗口上，gpt-5 按 400000 算，70% 是 `280000`，90% 是 `360000`，用 `-c model_auto_compact_token_limit=` 放进这一次进程的参数数组，不写 `config.toml`。

**不写用户配置。** 压缩值只进这一次进程的环境变量，或 Codex 的 `-c`。Claude 的钩子设置写在临时目录。Grok 的工作台配置仍只写项目里的 `.grok/config.toml`，路径落在用户 `~/.grok` 时拒绝，里面也不写压缩比例。

**界面和使用说明。** 中文界面写了「到了这个比例它自己收一次」「改滑块要重开这个窗口才生效」「不能比原来更晚才压」，并写明压缩是命令行自己的摘要，不是监管者那一页四行近况。Grok 窗口另外写明再往右也按 85% 传。使用说明同一套话，并写了滑块只在管理者窗口、50% 到 90%、不指定就不传、不会写进本机 Claude、Codex、Grok 配置。
