## 2. A · 空闲投递安全（最高优先级）

实现在 `apps/desktop/src/main/workbench/idle-deliver.ts`。默认输出静默 1500ms 才写；忙则每 200ms 再看；从入队算起 8000ms 仍忙则 `forced = true` 照样写。正文与 `\r` 分两次 `write`。界面在延后强制成功时 toast「窗口仍在输出，已强制写入角色说明」。

`PtyManager.isIdle` 只比较 `now - lastOutputAt`。用户按键走 `terminal:write` → `manager.write`，会更新 `lastInputAt`，**不参与**空闲判断。自己的写入也会把 `lastOutputAt` 拨到当前时刻，所以下一条要重新静默；但同一条的正文和 `\r` 在同一次 `deliverOne` 里连着写，中间不看空闲。

单测 `超时仍忙则强制投递` 把这个行为锁死了。修的时候要改掉这条测试，不能留着当规格。

### 2.1 确认框上写字加回车会怎样

本机 Claude Code **2.1.220**。只跑了 `--help` / `--version` 和缺参数探测，没有开对话。

官方交互文档（code.claude.com/docs/en/interactive-mode，覆盖本机版本）：

- 权限提示是对话框。`Esc` 关闭对话框，不是批准。
- 左右方向键在权限对话框的标签之间切换。
- 文档的快捷键表没有单独写「回车 = 同意」。

公开问题单记录的是同一类菜单的实际按键（#27924、#28139，版本在 2.1.50 前后，早于本机 2.1.220，本轮没有用真对话复核按键）：

- 默认高亮是第 1 项，文案是 Yes。
- 回车确认当前高亮项。
- 数字键是选项快捷键。#27924 还记过一段回归：数字被打进输入行，提示仍按选项 1（Yes）收场。2.1.220 是否已修好，本轮没有实测，不能当成「数字键已经安全」。

因此：往确认框写一段中文，那些字不是 1/2/3，多半被菜单丢掉，或者灌进底下的输入行。紧跟着的 `\r` 仍是回车。回车在这类菜单上的语义是确认当前高亮项，默认是同意。效果就是替用户批准了这一次工具或命令。

同一类对话框还有工作区信任框。官方权限文档的两项是「Yes, I trust this folder」和「No, continue without these permissions」。启动后若画面停在这里且不再刷输出，8 秒强制写入同样会按到默认的 Yes。角色切换若发生在会话中段，更常见的是工具确认框，不是信任框。

Codex CLI **0.159.2** 的二进制里，审批文案与事件名挨在一起：`approval-requested`、`plan-mode-prompt`、`async-question`，以及 `Approval requested`、`Codex wants to edit`。外部 `notify` 不覆盖这些状态（见 §2.3）。TUI 审批框同样在等按键。往里面写 `\r` 与 Claude 是同一类风险：本轮没有开 Codex TUI 去点按键，不能把「Codex 的回车一定选 Yes」写成已实测；能确定的是它在等用户做选择，而强制写入会送出回车。

用户正在输入时：AI 已经停在输入框（输出早已静默），`isIdle` 为真，入队会立刻写。正文插进用户打到一半的那一行，`\r` 再把拼在一起的内容提交。`lastInputAt` 已经记了按键，只是没人看。

超时强制更严重：确认框或转圈只要让 `isIdle` 一直为假，8 秒一到仍写。偶发的光标重绘会把静默判断拖过 1500ms，然后被超时打穿。

### 2.2 Claude hooks：能区分，但 Notification 太晚

`claude --help`（2.1.220）原文：`--settings <file-or-json>` 是 “Path to a settings JSON file or a JSON string to load additional settings from”。这是本次启动额外加载，不是把设置写回 `~/.claude`。`--setting-sources` 用来限制 user/project/local，不要用它关掉用户自己的登录配置。`--bare` 会跳过 hooks，角色窗口不能加 `--bare`。

官方 hooks 文档（code.claude.com/docs/en/hooks，与 hooks-guide 一致）：

| 事件 | 何时 | 能不能当「现在可以回车」 |
|---|---|---|
| `PermissionRequest` | 即将向用户要权限时立刻触发。不返回 `decision` 则对话框照常出现 | **能当「禁止写」**。钩子只许退出 0、不输出 `behavior: allow`，否则会替用户批准 |
| `Stop` | 主回合结束、回到输入框 | **能当「回合已结束」**。还要再看本机 `lastInputAt`，避免写进用户正在打的字 |
| `UserPromptSubmit` | 用户提交了一句 | 标记为忙 |
| `Notification` / `permission_prompt` | 权限框出现后约 6 秒，且用户没打字。打字会推迟。文档写明：要在每次询问当下触发，用 `PermissionRequest`，不要用这个 | 太晚。本单 8 秒强制写入会赶在它前面 |
| `Notification` / `idle_prompt` | 回应结束约 60 秒且期间没打字 | 太晚，不能当投递条件。可以留给 T10.7 做「人离开很久」的补充提醒 |
| `elicitation_dialog` | MCP 征询框，同样约 6 秒 | 与权限框一样，期间禁止写 |

`permission_prompt` 与 `idle_prompt` 分得开，但它们是「人好像不在」的通知，不是「TUI 现在处于哪种模态」。用输出静默去猜模态，会把「正在等批准」和「正在等下一句」看成同一种静默。

### 2.3 Codex：`notify` 不够，hooks 可行

`codex --help`：`-c` 覆盖本会从 `~/.codex/config.toml` 读到的值，值按 TOML 解析，失败才当字面量。帮助没有说 `-c` 会写回用户目录。本轮所有 Codex 探针都设了 `CODEX_HOME=%TEMP%\ff-t106-codex-home`。

二进制 `codex.exe`（0.159.2）里，外部 notify 载荷的字段名与 `agent-turn-complete` 排在一起：`type`、`thread-id`、`turn-id`、`cwd`、`input-messages`、`last-assistant-message`。`approval-requested` 不在这组字段旁边，而在 TUI 文案（`Approval requested` / `Codex wants to edit`）旁边。这与仍开放的上游问题一致：外部 `notify` 命令只在回合结束时调用，审批等待不调用。

所以 `-c notify=[...]` 可以当作「回合结束」的又一路信号，**不能**表示「正在等审批」。只接 notify、仍用输出静默填补中间的空档，确认框问题还在。

hooks 在本版本可用，而且不必写 `~/.codex`：

- 官方文档：`PermissionRequest` 在即将弹出审批时触发（Bash、`apply_patch` 等）。不返回 decision 就走正常审批框。任何 `deny` 优先；`allow` 会跳过审批框。观察用的钩子必须退出 0 且不输出 allow。
- `Stop` 在回合结束时触发。
- 配置可以是 `hooks.json`，也可以是 `config.toml` 里的 `[hooks]`。`-c` 能传后者。
- 本轮在隔离 `CODEX_HOME` 下：`codex debug prompt-input -c features.hooks=notabool` 退出码 1，错误是 `features` 里期望布尔、得到字符串。同一命令加上 `features.hooks=true` 和 `hooks.Stop=[{hooks=[{type="command",command="cmd /c exit 0"}]}]` 退出码 0，提示词仍能渲染。类型校验会拒绝坏值，所以这条 Stop 配置是被接受了，不是被静默丢掉。
- 非托管钩子默认要在 `/hooks` 里信任，信任记录进 Codex 家目录。为了不改用户 `~/.codex`，窗口启动加 `--dangerously-bypass-hook-trust`（帮助原文：本次调用不要求已持久化的钩子信任）。这个旗标只许配我们自己的、只报事件、不返回 allow 的脚本。

### 2.4 必须改成的投递规则

删掉 8000ms 强制写入。超时仍不空闲：继续排队或丢掉这一次敲门，toast 说明没写进去。不要写 PTY。T10.7 的正文在收件箱和 `.md` 里，敲门丢了可以再敲，不能靠回车闯关。

每个窗口维护三态，只在 `idle` 且输入也静默时写：

1. **blocked**：收到 `PermissionRequest`（以及 Claude 的 elicitation）。禁止写。对话框还在。
2. **busy**：`UserPromptSubmit`，或工具继续跑（`PostToolUse` 之后模型还没 `Stop`）。禁止写。
3. **idle**：`Stop`（Codex 还可以用 `notify` 的 `agent-turn-complete` 作同一状态的旁路）。然后还要 `lastInputAt` 静默满 1500ms，避免串进用户正在打的字。再写正文，单独写 `\r`。

Claude 启动参数增加 `--settings <本窗口临时 JSON>`，里面只有上述观察钩子。文件放 `%TEMP%`，随窗口退出删除。不要写 `~/.claude`。

Codex 用 `-c features.hooks=true` 加上内联 `hooks.PermissionRequest` / `hooks.Stop`，并加 `--dangerously-bypass-hook-trust`。钩子命令用绝对路径，只向主进程报事件。不要写 `~/.codex`，不要在项目里放 `.codex/hooks.json`。

钩子进程没起来、或启动后一直没有任何事件：保持排队并提示，**不要**退回输出静默。输出静默只能当调试信息，不能当写回车的条件。

`Notification.idle_prompt`（约 60 秒）可以留给 T10.7 做「人离开很久」的补充，不能替代 `Stop`。

## 3. B · 注入正确性

### 3.1 Claude

`claude --append-system-prompt-file` 不带参数时，进程立刻退出，错误是 `option '--append-system-prompt-file <file>' argument missing`。没有进入会话。帮助正文里的 `--bare` 说明也写了 `--append-system-prompt[-file]`。这是追加，不是 `--system-prompt` 那种替换。

`buildInteractiveClaudeArgs` 在新开（`--session-id`）和续接（`--resume`）两条路径上，只要有文件就追加 `--append-system-prompt-file`。E2E「T10.6：worker 说明书注入」看到 argv 里有这个旗标，文件正文含「只改 brief 范围内的文件」；运行中改管理者后，回放里出现 `manager.md`；设置页把 worker 覆盖成哨兵后，新窗口的提示文件含该哨兵。

临时文件目录是 `%TEMP%\ffpane-workbench-role-prompts\<窗口 id>.md`，目录名固定，不是 `mkdtemp`。内容是说明书，没有密钥和令牌（启动前 `assertSecretAbsent` / `assertTokenAbsent` 扫过正文）。窗口退出时按 `windowId` 删除；应用退出时 `releaseAll`。同一窗口再次启动会覆盖同一路径。

启动在 `manager.create` 抛错时会吊销令牌并删 MCP 临时目录，**不会**删这份提示文件。文件已 `track`，要等进程退出才删。没有密钥。列为建议：失败分支里一并 `release`。

### 3.2 Codex `developer_instructions`

`buildInteractiveCodexArgs` 把正文做成一个 argv：`-c` 与 `developer_instructions=` + `JSON.stringify(正文)`。新开和 `resume`（带 id 或不带 id）都追加，不替换已有的 `-c`。

隔离 `CODEX_HOME` 下用 `node.exe` 直接跑 `codex.js`（与工作台一样不经 `cmd.exe`），命令是 `debug prompt-input`，约 2 秒，退出码 0，没有模型请求。正文用了引号、反斜杠、中文和换行：`角色 "引号" \反斜杠 中文` 加换行再加 `第二行`。

| 探针 | 结果 |
|---|---|
| 带 `developer_instructions` | 第一条 developer 消息的第一段就是这段正文，引号、反斜杠、中文、换行都在。后面仍有 `<skills_instructions>`。整段里 permissions、collaboration 仍在 |
| 不带该键 | 第一条从 `<skills_instructions>` 开始 |
| `-c experimental_instructions_file=...` | 与不带时一样，该键没有出现。未知 `-c` 被忽略。stderr 只有「拒绝在临时目录创建 PATH 别名」，没有报这个键 |

这与计划里的结论一致：是追加到开发者说明前面，不是整段替换。`model_instructions_file` 没有使用。没有写项目 `AGENTS.md`，没有改用户 `~/.codex`。

续接走同一函数，argv 形如 `resume <id> -C <cwd> ... -c developer_instructions=...`。单测锁了这个形状。本轮没有对真实会话做 `resume`（那会碰用户的会话库）。

### 3.3 引号、反斜杠、非 ASCII

工作台启动走 `resolveDirectCliTarget`：Claude 进 `claude.exe`，Codex 进 `node.exe` + `codex.js`，参数是数组。`PtyManager` 在 `direct` 分支把数组原样交给 node-pty，不拼进 `cmd.exe`。`JSON.stringify` 负责把引号和反斜杠放进**一个**参数。上面的 `prompt-input` 用同样的 argv 数组，特殊字符原样出现在模型可见文本里。

没有为了验证 node-pty 的 Windows 命令行引号再拉起真实 TUI（那会变成一次会话）。node-pty 的引号规则与 T10.4 已经在用的其它 `-c` 参数是同一条路。

建议：单份覆盖上限 8192 字，base 与角色两份都顶满时，再加上 MCP 的 `-c`，要自己量一下是否逼近 Windows 32767 的命令行上限。当前内置说明书远小于这个上限。

## 4. C · canSetRole、注册表、布局

### 4.1 纯函数

`canSetRole` 与单测矩阵一致，本轮按代码又对了一遍：

- 合法角色且 id 非空时，`kind: "user"` 对树内、树外窗口的五种角色都允许。
- 窗口把自己设为 `manager`：仅 `openedBy === "user"` 且没有父窗口。空白父 id 视为顶层。父已关闭但 `parentWindowId` 还在，不能自设。
- 窗口可以给任意后代设任意角色。环上 `isDescendantOf` 为假，不能借环去设对方。
- 树里已有的父级优先于调用方传入的 parent。空 actor、空 id、非法角色拒绝。

`workbench:set-role` 固定 `setWindowRole({ kind: "user" }, ...)`。渲染端不能传 actor。渲染进程就是用户，合同已允许用户改任意窗口。这条不能被子窗口的 AI 直接调用，除非它能打到 Electron IPC。可接受。

shell 窗口只改布局，不注入、不投递。

### 4.2 启动成功后角色被抹掉（必须修复）

### 4.3 冷读布局里的 manager（移交 T10.7）

### 10.1 A · 投递状态机

**结论：通过。** 没有超时强写，也没有「静默即空闲」回退。手动发送在 `PermissionRequest` 时被拒。自动路径上每条消息都要等一次新的回合结束。确认框上的单键不会把状态放成空闲。

`createIdleDeliverQueue` 的自动条件是 `phase === "idle"`，并且（若用户曾经输入过）输入静默达到 1500ms，并且输出静默达到该条消息的静默时间。`phase` 只有 `unknown | idle | busy | blocked`。源码和单测都断言文件里没有 `forced` / `timeout`。`unknown`、`busy`、`blocked` 上把时钟拨 60 秒，写入次数仍是 0。

`PermissionRequest` 把 phase 设成 `blocked`。`deliverNow` 在 `blocked` 返回 `refused/blocked`，在 `busy` 返回 `refused/busy`。单测覆盖了这两条，包括权限阻塞后再提交回车，phase 仍是 `blocked`。

用户按键从 `terminal:write` 进 `onUserInput`。只有数据里含 `\r` 才调用 `noteSubmit`。`'1'`、`'y'` 这类不含回车的单键只刷新 `lastInputAt`，不改 phase。已经是 `blocked` 就继续 `blocked`，已经是 `busy` 就继续 `busy`，直到后来的 Stop。这比「保持 busy」更严：权限等待期间连回车也不会把它改成 busy。Claude 的 `PermissionRequest` 先到，用户再按选项，队列不会写。

Codex 按决定 (2) 没有 `PermissionRequest`。回合进行中的确认框安全，靠的是「已经提交过回车所以是 busy」：用户按了 Enter，或队列自己写出了 `\r`，之后单键不会把 phase 打回 idle，自动投递和「立即发送」都拒绝，直到 `agent-turn-complete`。首轮还没有任何回合结束时 phase 是 `unknown`，自动投递关闭；这时若画面上已经有确认框，用户仍可以点「立即发送」。这是决定 (2) 留下的残余，不是单键回归。界面文案要让人知道这个按钮会真的往终端里写回车。

自动多条：一条 Stop 只写出队首（正文和 `\r` 分两次），然后 phase 变成 `busy`，下一条要再等一次 Stop。单测「多条按序」锁住了这条。E2E「Codex notify 的 agent-turn-complete 之后才自动投递」也过了。

**移交 T10.7（不阻断本单）：** `deliverNow` 在 `unknown`（以及 IPC 直接调用时的 `idle`）里用 while 把整个队列同步写完，中间不再看 phase。界面上的按钮只在 `mode === "manual"`（也就是 `unknown`）出现。同一轮同步写完，插不进一个新的 `PermissionRequest`。角色切换通常只有一条。T10.7 把多条提醒接到这条队列之前，应改成一次只发队首，其余继续等下一次回合结束或用户再次点击。

真实 CLI 的 Stop 不会在权限框还开着时发出。`noteHook("stop")` 会无条件把 phase 设成 `idle`，包括从 `blocked` 覆盖过来。这和「最近信号是回合结束」一致。伪造的 Stop 才能在框还开着时把阻塞清掉，见 §10.4。

### 10.2 B · 注入面

**结论：通过。** 工作台启动、hook、notify 都不把命令交给 shell，argv 里没有 `--dangerously-bypass-hook-trust`。

工作台 CLI 走 `resolveDirectCliTarget` + PTY `direct.args` 数组。解析不到原生 exe 或 node 脚本就拒绝启动，错误文本写明拒绝 cmd.exe 回退。`resolveHookNodeExecutable` 只接受 shim 已经确定的 `node.exe`，或 PATH 上的 `node.exe`（其它平台是 `node`）。PATH 上只有 `node.cmd` 时返回空，调用方不装配 hook / notify，该窗口保持手动。单测锁住「不退回 cmd」。

Claude settings 里每条 hook 是 `{ type: "command", command: <node.exe 绝对路径>, args: [<脚本绝对路径>, <固定事件名>] }`。事件名只有 `PermissionRequest` / `Stop` / `UserPromptSubmit` / `SessionStart`。Codex 是一个 argv 元素 `-c` 加上 `notify=[` + 两段 `JSON.stringify` + `]`，不是拼出来的 shell 行。

角色正文走 Claude 的提示文件，或 Codex 的 `developer_instructions`（整段 `JSON.stringify` 后作为一个 argv 元素）。hook 脚本只认固定事件名；Codex 附带的 JSON 只看 `type === "agent-turn-complete"`，正文不执行、不落盘。

`apps/desktop/src/main/workbench` 与 `src/mcp/workbench-hook.ts` 里，`cmd.exe` / `.cmd` / `.bat` / powershell / `shell: true` / `windowsVerbatimArguments` 只出现在「拒绝 cmd 回退」的注释和错误文案。`windowsVerbatimArguments` 把参数拼成命令行的分支在终端管理器的非 direct 可执行路径，工作台启动不走它。普通终端的 shell 白名单和 smoke 的 PTY 自检仍会用到 cmd / PowerShell，那不是工作台 CLI、hook 或 notify。

`--dangerously-bypass-hook-trust` 只出现在文档（含本记录首轮建议）和「argv 不得包含它」的测试里，不在启动参数构造里。

### 10.3 C · Claude 2.1.220 的 exec 形态

**结论：本机版本支持 `args`。** 当前写法就是无 shell 写法。`--settings` 临时文件没有令牌明文。

本机包 `@anthropic-ai/claude-code` 版本 `2.1.220`，二进制在 `%APPDATA%\npm\node_modules\@anthropic-ai\claude-code`。官方 hooks 文档写明：带 `args` 时是 exec 形态，`command` 解析成可执行文件后直接 spawn，`args` 每个元素原样成为一个参数，不经 shell；`shell` 字段在有 `args` 时被忽略。该字段从 2.1.139 起就有，早于 2.1.220。本机 `claude.exe` 里能搜到 schema 原文 “Argument list for exec form. When present, `command` is resolved as an executable and spawned directly…”，运行时代码同时读取 `hook.command` 和 `hook.args`。Windows 上 exec 形态要求 `command` 是真正的 `.exe`；我们传的是 `node.exe` 绝对路径，符合文档。

若某个更老的构建不认识 `args`，字段会被忽略，`command` 只剩 node.exe 路径，脚本不会跑，收不到信号，phase 停在 `unknown`，只剩手动发送。那是安全失败。2.1.220 不走这条。不需要再改成 shell 字符串。

`prepareWindowHooks` 写出的 JSON 只有上述 hook。启动前 `assertTokenAbsent` 扫描这个文件。单测读 settings 正文，断言不含窗口令牌、不含 `.cmd` / `cmd.exe` / powershell / `ELECTRON_RUN_AS_NODE`。令牌和管道名在 PTY 环境变量里，不在 settings，也不在 argv。

### 10.4 D · 控制通道

**结论：通过（评估项如下，都不阻断）。** 子窗口拿不到父窗口令牌，就不能伪造父窗口的 Stop。

用和实现相同的 `net.createServer` + `server.listen("\\\\.\\pipe\\...")` 在本机建了一根探针管道，读它的安全描述符（探针已停，临时文件已删）：

| ACE | 权限 |
|---|---|
| SYSTEM、Administrators、创建者用户 | `0x001F01FF`（完全控制） |
| Everyone、ANONYMOUS LOGON | `0x00120089`（`FILE_GENERIC_READ`：能读，不能写，也没有 `FILE_CREATE_PIPE_INSTANCE`） |

SACL 不存在。没有显式完整性标签时，对象按中等完整性处理，低完整性进程不能向上写。其它登录用户连上来写一行会被拒绝。同一用户的其它进程可以连接；闸门是令牌。管理员和 SYSTEM 也可以连接，这是默认命名管道描述符的范围，本单没有收紧 ACL。

`resolveCaller` 是 `Map.get`，不是常时比较。令牌 32 字节，经本地管道做计时爆破不成立。和 T10.5 一样，记为建议，不阻断。

非法、吊销、畸形、超 16KiB、超过每秒 30 条：回错误并断开。限流按连接，不是全进程。合法令牌的未知类型交给 `onRequest` 或回 unsupported，不断开。日志路径不接收正文和令牌，单测断言响应和日志都不含令牌。

`will-quit` 调用工作台层 `dispose`，其中 `control.close()` 毁掉已连接 socket 并 `server.close()`。Windows 管道随句柄关闭消失，没有文件要删。`will-quit` 不等待这个 Promise；进程退出时句柄仍会被系统收回。

`onHook` 的窗口 id 来自 `resolveCaller(token)`，不采用消息体里的窗口 id。子窗口环境里是子窗口自己的令牌。没有父窗口令牌就只能打到自己的队列。

管道名和令牌都在 CLI 进程环境里，不在 argv。Codex 二进制里默认排除模式含 `*KEY*`、`*SECRET*`、`*TOKEN*`，`FF_PANE_WINDOW_TOKEN` 会被 shell 环境策略去掉；`FF_PANE_WB_PIPE` 不匹配 `*TOKEN*`，管道名可能出现在 Codex 的 shell 里。没有令牌，连上管道也是 `unauthorized`。Claude 的 Bash 工具从 Claude 进程拉起子进程（子进程会被标上 `CLAUDE_CODE_CHILD_SESSION`）。Windows 上 Git Bash 的登录快照会改 PATH，不会清掉它不认识的变量。模型因此有机会读到**本窗口**的令牌和管道名，只能冒充自己：伪造本窗口 Stop，把 phase 打成 idle。若当时有排队消息，自动投递会写进去。权限框还开着时，待批准的那条命令还没开始跑；要利用这一点，得事先已经有一个能跑的后台进程。影响限在本窗口，不跨窗口。T10.7 若要收紧，可以让 Stop 不要覆盖尚未结束的 `blocked`，或让 shell 环境同时去掉管道名。

### 10.8 给 Tony 的补充试用

超时强写已经去掉。Claude 窗口停在「是否允许」时，软件不会自己往终端里写，手动的「立即发送」也不会出现。可以在确认框还开着时改一次角色，确认那一行停在「待投递 / 等待权限」，而不是被写进去。

Codex 窗口看不到权限事件。它正在问你能不能执行时，不要点「立即发送」。那个按钮只在还没收到回合结束时出现，点下去会把排队的字和回车写进当前画面。

确认框上用 `1` 或 `y` 自己选，软件应继续等这一轮结束，再投递下一条。不要在它还在刷字时连续改两次角色再点一次「立即发送」——那一次点击会把已经排上的几行一起写出去；多条提醒接上之前会改成一次只发一条。
