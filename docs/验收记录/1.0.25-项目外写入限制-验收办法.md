# 1.0.25（T11.8）项目外写入限制：改动与验收办法

**日期：** 2026-11-07
**状态：** 已提交（2026-11-07，版本 1.0.25），尚未验收。
**计划：** [项目外写入限制计划.md](../项目外写入限制计划.md)。

## 1. 改动

- **Claude 窗口**（含 DeepSeek 窗口）：写文件工具（Write、Edit、MultiEdit、NotebookEdit）和命令工具（Bash、PowerShell）执行前，hook 先检查要写的地方。不在允许的目录里就拒绝，并告诉它「停下来用 ffpane_report 报上级，由用户加项目外可写目录」。全部权限（YOLO）照样拦。
  - 命令只认常见写法：`>`、`>>`、`tee`、`mkdir`、`touch`、`cp`、`mv`、`rm`、`cd` 之后的相对路径、`Set-Content`、`Add-Content`、`Out-File`、`New-Item`、`Copy-Item`、`Move-Item`、`Remove-Item`、`Tee-Object`。读项目外（调用别处的 blender.exe、从外面拷进来）不拦；heredoc 正文不当命令。脚本里再写哪里拦不住。
- **Codex 窗口**：全部权限（YOLO）不再用 `--dangerously-bypass-approvals-and-sandbox`，改成 `workspace-write` 沙盒 + 不审批。系统级拦截，项目外写不进去。
  - **沙盒里的命令连不上网**（0.166 实测，`network_access=true` 也不行，要等 Codex 的网络代理功能）。模型本身照常。原来的「可改+跑命令」本来也连不上。
- **允许的目录**：项目目录、系统临时目录、Claude 的 `~/.claude/plans`、Claude 自己记忆的那个目录（记忆搬完前先留着，T11.8b）、「项目外可写目录」。
- **项目外可写目录**：项目卡片 →「配置」对话框里新加一栏，一行一个。存在用户目录的 `projects.json`，不在项目里，AI 改不了。改完重开窗口生效。Codex 经 `writable_roots` 放行。
- 权限说明和 YOLO 确认的文字跟着改。
- 2026-11-07 已清理：3 个空目录（`C:\gather`、`C:\M_ITM_01_StoneAxe`、`D:\WorkWork\_jobs`）和 `~/.codex/generated_images` 里 143 个空子目录，都在回收站。`C:\Users\admin\edh` 的 9 个脚本、198 张旧图在项目里找不到，保留。

## 3. 验收办法（dev 模式，《海上生存日记》）

改了主进程、hook 和权限表，要重启 FF-pane；已经开着的窗口重开或续接一次才用上。

| # | 做法 | 应该看到 |
|---|---|---|
| 1 | 全部权限的 Claude 执行窗口，让它往 `D:\WorkWork\Assist\` 下写个文件 | 被拒绝，它说明原因并报上级；目录里没有新文件 |
| 2 | 同上，让它用命令 `mkdir -p /c/gather/x` | 被拒绝 |
| 3 | 让它在项目里正常干活（写代码、跑脚本、调 blender） | 不受影响 |
| 4 | 全部权限的 Codex 窗口往项目外写 | 「拒绝访问」 |
| 5 | 项目卡片 →「配置」，在「项目外可写目录」填一个目录，保存，重开窗口，再让 1、4 往那里写 | 能写 |
| 6 | 再打开「配置」 | 刚填的目录还在 |
| 7 | 让 Codex 窗口跑一条要联网的命令 | 连不上（已知限制） |
