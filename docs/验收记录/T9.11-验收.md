## 7. 走查续集修复（2026-09-16）

**现象：** 活干完了、`notes.md` 在、Run `end=completed` / `effort=high`，任务却是 `failed`。编排器把 `completeTask` 的 `DoneEvidenceError` 吞掉后只 `failTask()`，界面和结算摘要看不出为什么；摘要还会写成「原因 completed」。

**根因（对照计划页截图 + 代码）：**

1. 规划者把验收里的 `git status` 写进了 `verifyCmd`。完成门槛规则 2：合同一旦带 `verifyCmd`，必须有 `Run.verifyResult`，报告不能充数。
2. Windows 上 Codex 的 `command` 是完整 `powershell.exe -Command "…"` 串（适配器注释与 fixture 均如此）。编排器原先 `event.command.trim() === verifyCmd.trim()`，对不上就不写 `verifyResult`。
3. `settleTaskAfterRun` → `completeTask` 抛 `verify-result-missing`，`catch` 空块直接失败。

**未改：** `completeTask` 三条门槛（有 verify 必须过验证；无 verify 必须有报告；没有第三条路径）。未改 generate-plan 草稿行为，未对真实 `~/.aiworkbench` 清场。

**改了什么：**

| 点 | 落点 |
|---|---|
| 认出 powershell / bash / `cd &&` 包装，命中后 `VerifyResult.command` 仍写成合同原文 | `packages/core/src/task/verify-cmd.ts`；编排器 drain + 证据回扫 |
| 失败原因落盘；再次派发清掉 | `Task.failReason`；`failTask(task, reason)` |
| 结算不再写「原因 completed」 | `composeSettlementSummary` |
| 任务卡显示失败原因 | `TaskCard` + locales |
| 规划合同：纯写文件不要写 `verifyCmd`，不要用 `git status` 充数 | `PLAN_OUTPUT_CONTRACT` 第 5 条 |
| 执行者第 4 层写明完成门槛（审查者不含） | `assemble.ts` `renderTaskContract` |

**单测：** `matchesVerifyCommand`（包装 / 不认子串）+ `failReason` 派发清除 + 结算文案 + 编排器「包装命令 → done」/「没跑到 → failed + reason」+ 规划合同 / Prompt 门槛句。
