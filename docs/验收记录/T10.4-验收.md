## 2. A · 命令注入（最高优先级）

### 2.1 实现路径

- PTY：`manager.create({ executable, args })` → `resolveSpawnTarget`（`packages/adapters/.../windows-command.ts`）。
- 命中 `.cmd/.bat`：`cmd.exe /d /s /c` + `buildCmdShimCommandLine`（命令一层 `^`，参数 MSVCRT 引号 + **双层** `^` 元字符）+ `windowsVerbatimArguments`。
- node-pty：`factory` 接受预转义 CommandLine **字符串**（`target.args.join(" ")`），语义等价 child_process verbatim 数组拼接。
- 本机 PATH 命中：`claude.CMD` / `codex.CMD`（均 `viaCmdShim: true`）。真实 shim 内容：
  - `claude.CMD` → 直接 `"%dp0%\...\claude.exe" %*`
  - `codex.CMD` → `node` + `"%dp0%\...\codex.js" %*`

### 2.2 独立注入探针（%TEMP%）

脚本：`%TEMP%\ff-pane-t104-inject-*\probe3.mjs` / `probe-nl.mjs`。假 `.cmd` 同形 `%*` 转发到 node 打印 argv；副作用标记文件 `MARKER`。

| 载荷 | 额外命令执行？ | 环境变量展开？ | argv 是否原样 | 判定 |
|---|---|---|---|---|
| `hello & echo … > MARKER` | 否（无 MARKER） | — | 是 | 通过 |
| `a" & echo … & "` / PWNED 变体 | 否 | — | 是 | 通过 |
| `hello & calc` | 否 | — | 是 | 通过 |
| `%USERPROFILE%` / `%PATH%` | 否 | **否**（字面 `%…%`） | 是 | 通过 |
| `!x!` | 否 | 否（delayed expansion 默认关 + `^`） | 是 | 通过 |
| `a \| echo …` / `a > MARKER` / `(echo…)>MARKER` / `a^&echo…` | 否 | — | 是 | 通过 |
| 含 `\r\n` / `\n` 的多行（含第二行 `& echo PWNED`） | **未见** MARKER | — | **否**：只收到第一行 | **参数错乱 → 必须修** |

既有仓内单测亦钉住垫片路径：`packages/adapters/tests/process.test.ts`（元字符原样抵达）、`generic-exec.test.ts`（`a & echo INJECTED…` 不产生第二条命令）。

### 2.3 与「绕开 cmd.exe」对照

- headless/适配器层**当前同样**走 `resolveSpawnTarget` → `.cmd` 仍经 `cmd.exe`（转义方案共用，并非「解析 shim 后直接 node」）。
- **建议（强烈）**：对 npm 全局垫片解析出原生目标后直接 spawn：
  - Claude：`…\claude.exe` + argv（本机已是 `.exe`，无 node 脚本）
  - Codex：`node.exe` + `…\codex.js` + argv  
  可消除 cmd 二次解析、多行截断与 CVE-2024-27980 垫片面；失败时再回退现转义路径。

### 2.4 A 小结

- **未发现**单行元字符导致的额外命令执行或 `%PATH%` 类展开 → 转义对主攻击面有效。
- **必须修复**：多行 `initialPrompt`（及任何用户可控含换行的 argv）在 `.cmd` 路径下静默截断；至少应拒绝含 `\r`/`\n` 的 prompt，或改 stdin/临时文件投递，或绕开 cmd。

## 3. B · Codex 多窗口续接正确性

### 3.1 现状（代码）

- Claude：新开预分配 UUID → `--session-id`；续接 `--resume <uuid>`；布局可存 `nativeSessionId`。
- Codex：新开**不**写 `nativeSessionId`；续接有 id 用 `codex resume <id>`，否则 **`resume --last -C <cwd>`**（`cli-args.ts` / `launch-cli.ts` 与单测锁定）。

### 3.2 官方与本机帮助

- `codex resume --help`：`[SESSION_ID]` 或 `--last`；另有 `--all`（取消 cwd 过滤）。
- 官方文档：[Command line options](https://developers.openai.com/codex/cli/reference) —— **`resume --last` 作用域为当前工作目录下最近一条会话**（除非 `--all`）。
- **无**交互式新开「预设 session id」的公开 flag（与 Claude `--session-id` 不对称）。
- 本机 `codex --version`：`codex-cli 0.159.2`（live 脚本，不耗额度）。

### 3.3 `~/.codex` 只读结构（可行认领面）

| 路径 | 观察 |
|---|---|
| `sessions/YYYY/MM/DD/rollout-<ISO时间>-<uuid>.jsonl` | 首行 `type:"session_meta"`，`payload.id` / `payload.session_id` / `payload.cwd` / `payload.timestamp` |
| `session_index.jsonl` | `id` + `thread_name` + `updated_at`（**无 cwd**） |
| `history.jsonl` | 含 `session_id` 文本行（不适合精确认领） |

同 cwd 多会话时，文件名时间戳 + 首行 `cwd` + `id` 可区分；`--last` **必然**在同项目多窗口下指向「该 cwd 全局最近一条」，与「本窗口」无关。

### 3.4 可行修复方案（列为必须）

1. **启动后认领（推荐）**：`launchCliWindow` 记下 `t0` + 规范化 `cwd`；短轮询（或 `fs.watch`）`CODEX_HOME/sessions/YYYY/MM/DD/` 下 mtime≥t0 的新 `rollout-*.jsonl`；读首行 `session_meta`，匹配 `cwd`，且 id **未被其它窗口认领**；将 `payload.id` 写入窗口 `nativeSessionId` 并 persist。超时则 UI 标明「未绑定，续接可能不准」。
2. **续接**：一律 `codex resume <nativeSessionId> -C <cwd>`；**禁止**在已绑定失败时静默 `--last`（或仅作显式「接最近一次」菜单项）。
3. **备选**：若未来 CLI 支持命名会话 / 环境变量预设 id，再改为启动前预设；当前 help/文档未见可靠预设口。
4. **不要**依赖 TUI 输出刮取 id（脆弱）；不要用无 cwd 的 `session_index.jsonl` 单独匹配。

### 3.5 B 小结

产品核心「同一项目同时多个 Codex 窗口」下，当前 `--last` **设计性错误** → **必须修复**；认领 rollout 元数据方案在本机数据形态上可行。

### 12.3 B · 日期目录时区（复验重点）

只读证据（本机 UTC+8）：

| 文件目录 | payload.timestamp (UTC) | 本地日历日 |
|---|---|---|
| `sessions/2026/10/01/rollout-2026-10-01T00-02-10-….jsonl` | `2026-09-30T16:02:10.612Z` | **2026-10-01** |

→ Codex 目录名与文件名时间戳按**本地时区**；payload 为 UTC。
