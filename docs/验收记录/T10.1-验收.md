### 2.3 退出后记录清理（缺口）

`handleExit` 将 `exited=true` 后**仍保留** session（含环形缓冲）——对「切页回放活终端」合理。

但 `terminateSession` / `kill`：**首次 kill 只标记退出，不 `sessions.delete`**；仅对**已退出** session 再 kill 才删除。`TerminalView.restart` 只 kill 一次 → **每次重启在 Map 中遗留带缓冲的退出记录**。`killAll` 同样把所有会话标退出但不清空 Map。

→ **必须修复：** `kill`（用户主动终止 / 重启）后应从 Map 移除；或提供显式 `forget(id)` 并在 restart 调用。自然退出若仍需短时回放，可保留，但应有上限或与「活终端」槽位解耦，避免无限堆积。

### 2.4 环形缓冲 UTF-8 / ANSI 边界

`ByteRingBuffer` 按**字节**丢弃整块 chunk；单 chunk ≥ max 时从尾部截 `subarray`，注释已承认「截断边界可能落在多字节字符中间」。

| 场景 | 风险 |
|---|---|
| 多字节 UTF-8（中文/emoji）落在截断点 | **中低**：回放开头可能出现 `` 或替换字符；xterm 通常可容忍；非整屏永久乱码 |
| ANSI CSI 序列被拦腰截断 | **中低**：回放开头可能短暂错误着色/模式，随后新序列会纠正 |
| 正常未触顶缓冲 | **无** |

**风险等级：中低（可接受为环形缓冲固有语义；建议文档/注释保持；可选：截断后丢弃不完整 UTF-8 前缀）。不单列为必须修复。**

### 2.5 风格与其它

- `handlers.ts` create 的 try/catch 原样重抛——**无意义，可删**（可选）。

### 11.2 退出快照与 UI 交互（反向核对）

约定（`manager.ts` 头注）：自然退出 `remove:false` + `pruneExitedSessions`；kill / killAll `remove:true`（killAll 再 `clear`）。

| 场景 | 主进程 | UI | 判定 |
|---|---|---|---|
| 壳内 `exit`（自然退出） | `onExit` → `handleExit(..., {remove:false})` → 推送 `terminal:exit`，session 留 Map（≤8） | `useSubscription` 写 `exitCode` 到 React state，底部条显示；**不依赖**后续 Map 查询退出码 | **正确** |
| 点「重新启动」（已退出） | `kill(id)`：已 exited → 仅 `sessions.delete`，不再二次推送 | `restart`：kill → 清空 info → `spawnTerminal`（`setExitCode(undefined)`）→ `terminal:create` 新 id | **正确**；不会因 Map 删除丢退出码（码已在 state） |
| 点「重新启动」（仍存活） | kill → 推送 exit(code=1) → 删 Map | 同上；exit 事件若晚到且 `infoRef` 已空则 handler 早退 | **正确** |
| 反复重启 | 单测「重启路径：反复 kill + create 不堆积」`size()===0` | — | **正确** |
| 自然退出 >8 | 按 `createdAt` 淘汰最旧 exited；单测 `maxExitedSessions:2` 覆盖 | 当前 UI 单槽，触及上限概率低；淘汰只影响已弃用 id 的 get-replay | **可接受** |

**结论：** kill 后删 Map **不会**导致「拿不到退出码」或「重启失败」。退出码靠事件进 React state；重启走 kill（幂等删）+ create，与工作台 create 载荷兼容。
