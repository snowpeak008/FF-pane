## 1. 起因

Tony 发现两件事：

1. 「全放开」窗口能不能真的全放开，要看他本机的 Claude 设置文件。
2. 管理者开出来的执行窗口会不停地问权限。

## 2. 查到的（2026-11-21，测试在 `test-results/scratch/permtest/`，跑完已清理，只留 `probe.cjs`）

### 2.1 Claude 的「全放开」：跑起来不靠本机设置，启动那一步靠

- FF-pane 给 Claude 全放开窗口传的是 `--dangerously-skip-permissions`（`packages/core/src/workbench-permission/mapping.ts`）。
- 用 `claude -p` 实测（2.1.302）：本机设置里没有任何放行规则时，照样跑命令、写 `.claude/`、写 `.git/`，一次都没拦。
- **但启动时有一个确认画面。** 用隔离的 `CLAUDE_CONFIG_DIR` 实测（`probe.cjs`）：本机设置里没有 `skipDangerousModePermissionPrompt: true` 时，全放开窗口一启动就停在「WARNING: Claude Code running in Bypass Permissions mode」，默认选中「No, exit」。FF-pane 不处理这个画面。Tony 本机设置里现在有这一行，所以平时看不到。
- FF-pane 用自己的 `--settings` 传这个键，同样能跳过（同一个脚本实测）。FF-pane 本来就给 Claude 窗口传一份 `--settings`（`main/workbench/hook-launch.ts` 的 `prepareWindowHooks`）。
- 项目自己 `.claude/settings.json` 里的 `deny` 规则，全放开时照样生效（《海上生存日记》禁了 `git push`、`git reset`、`rm -rf` 等），不动。

### 2.2 执行窗口一直问权限：Claude 的 edit-exec 只自动批准改文件

- 管理者的说明写的是：执行、检查开 `edit-exec`（`resources/workbench-roles/manager.md` 第 5 行）。**这本身符合 Tony 的要求，不改。**
- 问题在于 `edit-exec` 在各 CLI 上的意思不一样：

  | CLI | edit-exec 现在是 | 跑命令 | 能不能写项目外 |
  |---|---|---|---|
  | Claude | `--permission-mode acceptEdits` | **每条都问** | 改文件工具：钩子拦得死；命令：钩子只认常见写法，脚本里写哪里看不出来（`mcp/write-guard.ts` 开头的说明） |
  | Codex | `-s workspace-write -a never` | 不问 | 系统沙盒拦（T11.8 实测「拒绝访问」） |
  | Cursor | `--force` | 不问 | 只有钩子（同 Claude 命令那一条），没有系统沙盒 |

- 《海上生存日记》的 `.claude/settings.local.json` 里有 11 条逐条点过「以后不再问」的命令，就是 Claude 执行窗口一直问攒出来的。
- Claude 全放开（`--dangerously-skip-permissions`）也只有这个钩子挡项目外，所以只靠它挡不住脚本往外写。

### 2.3 Claude Code 自带 Windows 沙盒（2.1.302），本机没装

- `claude.exe` 里有 sandbox-runtime 的 Windows 后端（`srt-win`）：命令以单独的沙盒账户（默认 `srt-sandbox`）运行，写入限制在允许的目录，网络经它自己的代理，按 `allowedDomains` 放行。
- 要装一次：在 Claude 里 `/sandbox install`，或 `npx sandbox-runtime windows-install`，要过 UAC 提权。本机现在没有 `srt-sandbox` 账户（只有 Codex 的 `CodexSandboxOffline`、`CodexSandboxOnline`），即**没装**。
- 相关设置（字符串里读到的，未实测）：
  - `sandbox.enabled`；
  - `autoAllowBashIfSandboxed`：沙盒里的命令不问；
  - `allowUnsandboxedCommands: false`：不许绕出沙盒跑；
  - `failIfUnavailable`：沙盒起不来就报错退出，不悄悄退回不受限；
  - `filesystem.allowWrite`：额外可写目录；
  - `network.allowedDomains` 和 `deniedDomains`。
- 它不在用户主目录、包含主目录的文件夹、Claude 配置目录里启动。项目在 `D:\WorkWork\gamedesign\…`，没有这个问题。
- 官方安装命令（sandbox-runtime 的 README，2026-11-21 读）：`npx @anthropic-ai/sandbox-runtime windows-install`，自己提权，弹一次 UAC。npm 上这个包是 Anthropic 的（维护者都是 anthropic.com 的人，0.0.83）。会建：
  - `srt-sandbox` 本机账户，密码随机，加密存在 `HKLM\SOFTWARE\sandbox-runtime`；
  - `sandbox-runtime-users` 本机组；
  - 只针对这个账户的 WFP 出站过滤；
  - 在项目目录上给这个账户加写权限（ACL）。
  可以重复运行（会换密码、对齐过滤规则），升级也是再运行一次。卸载命令 README 里叫 `windows-uninstall`，完整写法没给，推测是 `npx @anthropic-ai/sandbox-runtime windows-uninstall`，要实测。Windows 支持还是 Alpha。
- 已知限制（README）：沙盒里用 Windows 自带 TLS（schannel）的工具上不了 HTTPS，比如 `System32\curl.exe`、`Invoke-WebRequest`、`winget`、`http.sslBackend=schannel` 的 git。**Tony 本机 git 就是 schannel**（`git config --get http.sslBackend`），沙盒里 `git fetch` / `git clone` 会失败，要给沙盒里的 git 改用 openssl（`-c http.sslBackend=openssl` 或环境变量），见 §5。
- 它只管 Claude 跑的命令（子进程）。Claude 自己连模型的流量在 `claude.exe` 主进程里，用 Tony 的账户，不经过沙盒，中转地址也不受影响。

## 3. 怎么改

### 3.1 各档的意思（改完以后）

| 档 | 给谁 | 意思 | Claude | Codex | Cursor |
|---|---|---|---|---|---|
| 只读 | 规划、监管者、调研小窗 | 不改、不跑 | 照旧 | 照旧 | 照旧 |
| 可改可跑命令（`edit-exec`） | **执行、检查（管理者默认开这档）** | **项目内放开**：不问；写不到项目和项目外可写目录以外的地方 | `acceptEdits` + Claude 沙盒（见 3.2）+ 现有钩子 | 照旧 `workspace-write` + `never`（已是系统沙盒） | 照旧 `--force` + 钩子；**没有系统沙盒，见 §4 第 3 条** |
| 全放开（`yolo`） | 只有 Tony 指定时，比如要跑 Unity 的集成窗口 | 不受限；只挡改文件工具往项目外写 | 照旧 `--dangerously-skip-permissions`，并由 FF-pane 跳过启动确认（3.3） | 照旧（T11.8） | 照旧 |

- 管理者只开执行、检查对应的 `edit-exec`。`manager.md` 加一句：全放开只在 Tony 指定时开，并写进说明。
- 封顶规则照旧：子窗口不超过调用者。
- 不改档的名字，界面上的说明文字跟着改成「项目内放开」的意思。

### 3.2 Claude 的 edit-exec 加沙盒（按 §5.1 实测结果写）

只对 **edit-exec 档的 Claude 窗口**（含 DeepSeek 那一路，同样是 Claude CLI）生效，其他档、其他 CLI 不动。

1. **进程环境：** 加 `CLAUDE_CODE_NANKEEN_KESTREL=1`（Tony 2026-11-21 定用这个内部开关，见 §5.2）。只放进这个窗口的进程环境，不写进 Tony 的设置文件。
2. **命令行：**
   - `--permission-mode acceptEdits` 照旧；
   - `--allowedTools` 合并成一个参数：MCP 工具（现有的 `mcp__ffpane-workbench`）、`PowerShell`、`Bash`。不能两个参数互相覆盖。
3. **`--settings` 文件**（`hook-launch.ts` 的 `prepareWindowHooks`，和 hooks 同一份）：
   ```json
   "sandbox": {
     "enabled": true,
     "failIfUnavailable": true,
     "allowUnsandboxedCommands": false,
     "autoAllowBashIfSandboxed": true,
     "windows": { "backend": "sandboxuser" },
     "filesystem": { "allowWrite": ["<项目外可写目录>"] },
     "network": { "allowedDomains": ["<默认名单 + 项目加的>"], "strictAllowlist": true }
   }
   ```
   - `autoAllowBashIfSandboxed` 在 Windows 上不起作用（§5.1 第 3 条），留着是为了以后 Anthropic 支持时不用再改。真正让命令不问的是第 2 条的 `--allowedTools`。
   - 项目目录本身不用写进 `allowWrite`，工作目录默认可写（实测）。
   - `allowWrite` 和给 Codex 的 `writable_roots`、给钩子的 `FF_PANE_WRITE_ROOTS` 用同一份来源（`projects.json` 的 `outsideWriteDirs`）。
   - `strictAllowlist`：名单外的域名直接拒，不弹问。这个键是 sandbox-runtime 的，Claude 的设置里认不认要在开发时实测；不认就去掉，看名单外的会不会弹问，并记下来。
4. **默认网络名单**（Tony 2026-11-21 定）：`pypi.org`、`files.pythonhosted.org`、`registry.npmjs.org`、`github.com`、`*.github.com`、`*.githubusercontent.com`。
   - 项目卡片里加「沙盒可联网的域名」，和「项目外可写目录」放在一起，存进 `projects.json`；
   - 写法照 sandbox-runtime 的规则（`*.example.com`，不能写 `*` 或 `*.com`），存之前校验。
5. **开窗前检查**，不过就不开这个窗口，在窗格里写清原因和办法：
   - Claude 版本 ≥ 2.1.329（`claude --version`）：「Claude Code 版本太旧，沙盒起不来。在终端运行 `npm i -g @anthropic-ai/claude-code@latest` 后重开」；
   - 沙盒已装（本机有 `srt-sandbox` 账户）：「Claude 沙盒没装，执行窗口开不了。到设置 → Claude 沙盒里安装，或者让 Tony 给这个窗口全放开」。
   - 不能悄悄退回成一直问的旧样子，也不能悄悄改成全放开。
6. **启动后还是起不来**（内部开关失效、过滤规则坏了之类）：Claude 会打 `sandbox required but unavailable: …` 并退出。FF-pane 认出这段文字，在窗格里照第 5 条那样提示，并把 Claude 给的原因原样附上。
7. 现有的项目外写入钩子保留：管改文件工具往项目外写，直接拒绝（§5.1 第 4 条）。
8. 沙盒里不能留后台进程（§5.1 第 3 条）。要起开发服务器、跑 Unity 的窗口由 Tony 指定全放开。`manager.md` 加一句：这类活先问 Tony，要不要开一个全放开的窗口。

### 3.3 全放开窗口不靠本机设置

Claude 全放开窗口的 `--settings` 里一定带 `"skipDangerousModePermissionPrompt": true`。现在没装 hooks、又没有中转来源时 `prepareWindowHooks` 不写这份文件，要改成全放开时也写。续接、改权限后重启、管理者重启窗口都走同一条路。

### 3.4 设置里加「Claude 沙盒」状态，卸载时可选一起卸

- 参照 1.0.36 的 Cursor 一节：设置里显示 Claude 沙盒装没装、Claude 版本够不够（≥ 2.1.329）。没装给「安装」按钮：跑 `claude sandbox install`，用 Claude 自带的那一版，免得版本对不上（§5.1 另外第 2 条）；先确认，会弹 UAC。装了给「卸载」（`npx @anthropic-ai/sandbox-runtime windows-uninstall`，实测写法见 §5.1 第 7 条；开发时确认 Claude 自己有没有卸载命令，有就用它的）。
- **Tony 定（2026-11-21）：** 打包后的卸载程序（`electron-builder` 的 NSIS）里加一个勾选项「同时卸载 Claude 沙盒（srt-sandbox 账户）」，**默认不勾**：这个沙盒是 Claude Code 自己的，Tony 在 FF-pane 外面用 Claude 也可能用到。勾了就跑卸载命令（弹 UAC）。FF-pane 是用户级安装、不要管理员，所以只在勾了时才提权。

**另外查到、和计划不一样的四件事：**

1. **Claude 的 Windows 沙盒还没正式开放。**
   - 2.1.302 和 2.1.329 都要服务器那边的开关 `tengu_nankeen_kestrel`，或者内部环境变量 `CLAUDE_CODE_NANKEEN_KESTREL=1`，才会启用。现在开关是关的，没设变量时报「Windows sandbox is not active on this session (feature gate off)」。
   - 设了变量就能用（下面第 4 条全过）。但这是没写进文档的内部开关，Claude 更新后可能变。
2. **版本要对上。**
   - 用 `npx … windows-install` 装的是 sandbox-runtime 0.0.83（安装标记第 3 版）。本机 Claude 2.1.302 自带的版本只认第 2 版，起不来（`setup marker version mismatch (have 3, expected 2)`）。
   - Claude 2.1.329 能用，但要多一个设置 `sandbox.windows.backend: "sandboxuser"`。另一个后端 `mxc` 要 Windows 11 24H2，本机是 23H2，用不了。
   - 结论：Claude 要升到 2.1.329 或更新，不用重装沙盒。
3. **Windows 上「沙盒里的命令不问」那个设置不起作用。**
   - `autoAllowBashIfSandboxed` 写明「macOS and Linux/WSL only」。只开沙盒时，`python …` 照样要批准。
   - 办法：再加 `--allowedTools PowerShell Bash`，把两个命令工具都放行。
   - 实测放行以后命令**仍在沙盒里跑**：往项目外写照样「Permission denied」，往允许的目录写成功，pypi 能连，命令全程不问。
4. **用 Claude 的写文件工具往项目外写，Claude 会问**（`acceptEdits` 只自动批准工作目录内的）。FF-pane 现有的写入钩子会直接拒绝，所以在 FF-pane 里不会弹问题。开发时用真窗口确认一次。
