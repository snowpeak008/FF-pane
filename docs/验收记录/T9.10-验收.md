### B. 合同逐项核对 —— 通过

**①**：`composeSettlementSummary`（core/report/settlement.ts）纯函数规则拼装无模型调用；done 带尝试次数 + 验证结论 + 报告首行、failed 带尝试次数 + endReason、blocked 等待语；60/120 字符截断。接缝在 `session/index.ts` `onTaskSaved`——与 T9.7 `taskSettledEventOf` 同一 `isTaskSettledStatus` 口径、同挂 saveTask 绑定点（编排器 + repair 两处），四条落定路径覆盖；入队先于事件推送；catch 兜底不上抛。去重按 taskId 替换有单测。

**队列落盘**：`.workbench/planner-report.json` `{version:1, baseline?, queue[]}` 原子写；50 条硬上限丢最旧；JSON 损坏 fs 层隔离归空、结构不符归空 + `onInvalid` 留痕，均有单测。

**②**：注入落点在编排器讨论轮分支（planner-message / planner-plan，含自定义角色讨论轮）——**判轮不判人**属实，Worker/审查轮物理走不到注入代码。小节款式照 rebuild.ts（`# 任务看板增量` + `## 待汇报结算摘要`（最近 10 条标注 N/总数）+ `## 看板变化`（20 行 + 单行 200 字符截断））；无战况 `undefined` 不占提示词；基准为「上次 Planner 轮开始时 taskId→status 快照」（Task 无时间戳，论证成立）。**出队语义**：`consumePlannerReport` 位于 `adapter.startTurn()` 之后——Profile 缺失 / 互斥拒绝 / spawn 抛错三条受理失败路径都触达不了消费（各有单测）；消费失败仅记日志不挡轮。

**③**：`PlannerReviewButton` 发起普通 planner-message 轮（复用 ② 注入管线，无独立通路）、不传 sessionId 开新会话、用户显式点击。

**红线（独立核验）**：settlement.ts 与 planner-report.ts 是纯数据写入——不 import 编排器、无 `session:start`（源码钉子单测）；`onTaskSaved` 只入队 + 推事件；渲染层唯一 `tasks:settled` 订阅方 ProjectAlertsBridge 只维护高亮 store 不发起轮次；行为面守卫单测（落定入队后 started 恰一次 + activeCount 0）。**全仓无任何「落定 → 自动发起 Planner 轮」路径。**

**preload 修复（半成品埋的白屏回归）**：contracts.ts 确认为纯 `import type` + `export type` 再导出；独立重新 build 后 preload 产物 `index.cjs` 4.76 kB 仅含 `require("electron")`。探针 ④ 独立复现根因（改回运行时再导出 → 产物立现 `require("@ff-pane/shared")`），修复有效性确认。
