  - **落点** `packages/rag/src/chunk/`：`tokens`（token 估算 + 按预算硬切）· `split`（行→句→硬切三级切点，供超长段切分与重叠取尾）· `trim`（保留缩进的边缘修剪）· `markdown`/`code`/`plain`（三套分段器）· `pack`（与格式无关的打包 + 重叠）· `chunker`（按格式派发 + 参数校验 + `toKnowledgeChunks`）· `types`。
  - **「分段」与「打包」两步分离**：分段器按格式识别语义单元（只切不合），打包器与格式无关地合并到目标尺寸。故新增格式只需写一个分段器，块尺寸/重叠的规则不必再抄一遍。
  - **产物是 `ChunkDraft` 而非直接的 `KnowledgeChunk`**：分块是纯函数（无 IO/时钟/随机，同输入恒同输出——快照测试与「按内容哈希增量索引」§8.3.2 都依赖这一点），而 `KnowledgeChunk` 需要条目 ID 与块 ID，那是收录流程注入的。由 `toKnowledgeChunks(drafts, {entryId, newId})` 完成最后一步，沿用 core 既有的「ID 生成注入」写法。
  - **token 估算是启发式，不引分词器**：真 tokenizer 随嵌入模型而变（cl100k / Qwen / Ollama 各不相同），引一个 WASM 分词器既重又仍对不上号。规则：宽字符（汉字/假名/全角）1 字 1 token、其余 4 字符 1 token、空白不单独计费；**刻意略微高估**——宁可块偏小，也不撑爆下游上下文。手写码位扫描（含代理对），O(n) 无正则。
  - **上限是硬约束**：把 `maxTokens` 拆成「内容预算 = 上限 − 重叠预算」+「重叠预算」，内容按前者打包、重叠再补上去，合起来天然不越界。参数不自洽（如扣掉重叠后内容预算低于下限）立即抛 `RangeError`，不静默纠偏。
  - **重叠只补在被大小切开的地方**：重叠是为了救「切在半句话上」丢失的上下文；标题与换页本身就是语义边界，把上一节尾巴拖进来只会污染出处、稀释相关度。故结构边界处收口的相邻块之间**不重叠**（有单测钉住）。
  - **结构边界优先收口，但不制造碎块**：遇到结构段且当前块已达下限就收口（块与标题/页/函数对齐，`headingPath`/`page` 因此干净）；当前块还没到下限则跨边界续合，出处取块首段所在小节——宁可出处粗一格，也不要一堆几十 token 的碎块把检索结果冲散。
  - **Markdown 按标题树**：ATX + setext 标题、围栏代码块、文首 YAML frontmatter；围栏内的 `#` 与 `---` 一律不当标题（否则代码示例的注释行会凭空造出标题层级）。标题行留在段内，块正文自带标题——对 BM25 与嵌入都是有效信号。
  - **源码按顶层声明（明确是启发式）**：要吃 30 种扩展名，为每种接 parser 与「自研量可控」相悖。两条信号：① 顶格且首个非修饰词是声明关键字；② C 家族兜底「顶格 + 含参数表 + 以 `{` 结尾」。声明前紧邻的注释/装饰器归属该声明。关键词匹配**手写扫描而非正则**——修饰词可任意叠加，`(?:mod\s+)*keyword` 正是 Gemini 适配器那次回溯炸弹的形状。识别不出 2 个以上边界（配置文件、SQL）退回按空行分段。
  - **切分不用 `String.trim()`**：块正文里有源代码，切点常落在缩进行上，`trim()` 会吃掉那行缩进，用户在检索结果里看到的就是错位的代码。改用 `trimBlankEdges`——去首尾空行与行尾空白，保留首个非空行的缩进。
  - **已知取舍**：html/docx 的标题在 T6.1 抽出的纯文本里与普通段落无从区分，故这两种格式的块不带 `headingPath`（`ChunkProvenance` 对此的约定本就是「非 Markdown 缺省」）；若日后要补，应在 T6.1 侧让 html/docx 输出保留标题标记，而不是在分块层猜。

## 5. 关键技术事实备忘

- **pnpm 11**：allowBuilds 是「包名: true」映射（数组无效）；安装失败会自动改写 pnpm-workspace.yaml 插入提示行；.npmrc 只承载 auth/registry；`pnpm add` 失败时 package.json 变更会回滚——预装依赖后必须验证包真实存在（T0.5 首派终止的教训）
- **better-sqlite3 13.x**：Node-API 预编译，ABI 与运行时解耦，无需 electron-rebuild（R1 已解除）；trigram tokenizer 中文子串检索实测有效（R4 已解除），但 <3 码点查询恒不命中
- **T2.0 调研核心结论**：三家 CLI（Codex/Claude/Gemini）均实测存在"权限拒绝伪装成功"→ W2.7 自建权限层为强制路径；OpenCode 适配器必须走 Server(HTTP/SSE) 模式；Claude resume 绑定 cwd（Native Session ID 与 cwd 成对登记）；Codex 每轮一进程、file_change 无 diff（Run 前后 git 快照采集）；spawn 时必须清洗 OPENAI_* 等环境变量
- **工程约定**：exactOptionalPropertyTypes 全开（可选字段用条件展开）；品牌 ID 在 JSON 边界 as 收窄一次；录制 fixtures 目录已排除出 Biome 格式化（录制证据逐字节保真）；renderer 内禁止硬编码 CJK（check-i18n 扫描器把关），开发者日志一律英文
