## 2. 代码抽查发现

**未发现声明与实现不符之处，也未发现红线在实现上被绕开。** 以下四条是抽查中记录的偏差与事实补充，均**不影响事实正确性**，不构成不通过理由。

1. **`--no-detect-urls` 是实际下发的第八个「不许动用户仓库」开关，但未入 `aider.md §1.2` 那张表。**
   `command.ts` 的第二组固定下发 8 项（`--no-gitignore` / `--no-auto-commits` / `--no-dirty-commits` / `--no-analytics` / **`--no-detect-urls`** / `--map-tokens 0` / `--chat-history-file` / `--input-history-file`），而调研文档 §1.2 第二组只列 7 行、代码注释与单测标题也仍写「七条」。fixture 各份 `meta.json.args` 里都有它，说明录制与实现一致，**只是文档表没跟上**。
   方向是安全的——它拦的是 aider 主动抓取提示词里 URL 的联网行为，属**多一道**网络护栏而非少一道。建议把它补进 §1.2 表并统一「七条/八条」的口径，否则日后重录 fixture 时这一项无从核对来源。

2. **单测子项计数有 ±1 的搬移（总数 65 无误）。**
   声明「命令行 10 · 扫描器 9 · fixture 回放 24 · git diff 8 · 适配器本体 14」，实际逐个 `it` 计数为
   **命令行 9 · 扫描器 10 · fixture 回放 25（成功流 9 + 退出码撒谎 5 + 截断与红线 6 + 真机事实 5）· git diff 8 · 适配器本体 13**，合计仍是 **65**。
   偏差来源是摘要把多个 `it` 并成一条描述（如「resume 三种非法输入」实为 3 个 `it`），与 T7.3a 记录的同类问题同一性质，纯口径。

3. **真机冒烟脚本里的判据分组注释编号已过期。**
   `live-aider.mjs` 的注释写 `// 1~4` / `// 5~6` / `// 7~10` / `// 11`，而第三组实为 6 条、最后一条实为第 14 条。**判据总数 14 与红线 6 条都对**，纯注释，不影响执行与判定。

4. **用户真实 HOME 里存在 `~/.aider/`——本次验收未新增，创建于交付期间（如实登记）。**
   实测内容与时间戳：`analytics.json`（117 B）、`installs.json`（128 B）均为 **2026-08-31 20:55:37**，`caches/model_prices_and_context_window.json`（约 **2.0 MB**）为 **20:55:46**；而交付提交时间是 **21:21:25**，本验收会话始于 21:24。
   即：**交付调研期至少有一轮 aider 调用发生在用户真实 HOME 下、且未带 `--no-analytics`**（并因此拉取了 litellm 的模型价格表，产生过一次联网）。
   需要分清两件事：
   - fixture README 的「用户的 `~/.aider*` 分毫未动」是**对录制而言**成立的——各份 `meta.json.homeFiles` 均为 `[]`，录制确实走的临时 HOME；
   - 但作为「整个 T7.3b 期间用户 HOME 未被写」的陈述则**不成立**，文档未披露这一项。
   风险评估：`analytics.json` 里 `permanently_disable: null`、`asked_opt_in: null`，**没有留下遥测同意，也没有任何 OAuth / 凭据文件**；`installs.json` 只记了一个版本-解释器对。内容是良性的。
   **受管执行路径本身照旧干净**：本次真机冒烟跑前跑后 HOME 条目数均 **87**、列表逐项一致，`~/.aider` 三个文件的 `LastWriteTime` 未变——`--no-analytics` 在受管路径上确实生效。是否清理这三个残留文件，列入 §6 待主管理员决策。

### 另记两条加分核实（非偏差）

- **`commandEvents:"no"` 与「mapper 仍为 `Running <cmd>` 保留 command 分支」不矛盾，且经独立加验。** 该分支是刻意的「不说谎」留法；验收另从两侧证明它在 headless 下不可达：源码侧 `explicit_yes_required=True` + `io.py:867` 的 `res="n"`，fixture 侧 `real-shell-declined` 是**带着** `--suggest-shell-commands` 录的而命令仍未执行。
- **兜底方向恒为「当正文」这一取舍在扫描器里落得干净。** 抽查 `scanAiderLine` 的每个分支：路径为空、缺 `(--dry-run)` 后缀、行首有缩进或 `> ` 前缀的「像标记」行一律回落 `answer`（单测逐形态断言）。即模型在正文里复述 `Applied edit to a.ts` 不会凭空多出一条文件变更证据。
