## 2. 输入框里有你的字就不投

### 改动

- **先看你有没有按过键。** 上次确认输入框是空的之后（真正开始一轮，或看屏幕看到框是空的），这个窗口里你没按过键，框里不可能有你的字，照常马上投。窗口之间互相发消息都走这条，和以前一样快。
- **按过键才看屏幕**（`idle-deliver.ts`、`prompt-ready.ts` 的 `inputHasText`）：
  - 框里有字：不投，窗格提示条显示「输入框里有你没发完的字，等你发完这句再投」，每 2 秒再看一次。你回车、这一轮做完后再投。
  - 框是空的（比如打了又删光）：马上投。
  - 看不出框里有没有字：你 60 秒内按过键就先等着，之后再投。
- **怎么区分你的字和提示文字**（`output-text.ts` 的 `solidOnly`）：真机核对，空输入框里的提示文字（Codex 的「Ask Codex to do anything」、Claude 的「Try "…"」）是暗色显示，光标格是反色，你打的字是正常颜色。看屏幕时只认正常颜色的字。
- **输入法选词算在打字**：界面把选词开始、结束告诉主进程（新通道 `terminal:composing`），选词期间不投。
- **「立即发送」**：框里有字或正在选词时拒绝，弹提示「先发出或清空，再点立即发送」。
- **窗格获得、失去焦点不算打字**（`terminal/reply-gate.ts`）：Claude、Codex 打开了焦点报告，点别的窗格时终端会写 `ESC[I` / `ESC[O`，以前被当成按键。照常写给 CLI，但不算输入。
- 发消息的窗口收到的说法：「用户在对方的输入框里打过字，提醒等用户发完（或确认框是空的）再自动送达」。

### 顺带修的一个旧问题

看屏幕时会把折行拼回一行。Windows ConPTY 遇到占满一整行的内容（Claude 输入框上下的横线）不换行，靠自动折行接着写下一行，下一行被标成折行，一拼就把横线和「❯」行拼成一行，认不出 Claude 的输入框。真机核对：修之前，真实 Claude 屏幕上「是否停在输入框」和「输入框里还有没有那段字」都认不出来；修之后都能认出来。看输入框时改为按屏幕上的行读（`keepRows`）；`ffpane_read_output` 给 AI 看的输出照旧拼行。

### 已验证

- 真机（不发提示词，只开窗、打字、清空）：Claude、Codex 各测空框、打了 `abc`、清空、打了「中文」四种，`inputHasText` 依次是 false、true、false、true；「停在输入框」两边都认得出。
- 单测：没按过键当场投、半句停下不投、发出并做完后再投、删光后投、看不出时 60 秒、选词、立即发送拒绝、真正开始一轮后不再看屏幕、暗色提示和反色光标不算字、ConPTY 横线不换行的样子。
- e2e：原有投递相关的用例全过（提交核对、括号粘贴、Codex 回车间隔、Codex 回合结束后才投）。

## 3. 画板是项目图库

### 改动

- **删图进回收站**（新模块 `main/workbench/canvas-library.ts`）：`.ffpane/canvas/.trash/`，`trash.json` 记谁删的、什么时候、原因、原来在哪一页哪一行、当时的标注。
- **画板界面**：选中一张图后有「标为不要」「删除（进回收站）」「从画板移除」；顶部「回收站（N）」能看、能恢复（回到原来的页和行，行没了放到页末，同名文件已有就换名放回）、能彻底删除和清空（要二次确认）。缩略图上标出「不要」「申请删除」；图的说明里显示「已导出到 …」。
- **AI 删图**（`ffpane_delete_canvas_file`，现在必须写 `reason`）：
  - 你标过「不要」的图：进回收站；
  - 没标的：不删，图上挂「某窗口申请删除这张图：原因」，你点「同意删除」进回收站，点「保留」撤销申请。
  - 恢复、彻底删除、清空只有画板界面能做，AI 工具调用不到。
- **导出**：新工具 `ffpane_export_canvas_image`，把图复制到项目里的相对路径，原图留在画板，图上记下导出到哪里。不能出项目、不能放进 `.ffpane`、扩展名要和原图一致，目标已有文件要 `overwrite: true`。
- **生图不再报假超时**：控制通道给 `ffpane_generate_image` 单独放宽到 5 分钟（原来 20 秒，出图要 25 到 60 秒）。同一窗口上一张没出完再调，直接返回「上一张还在生成」，不重复出图。
- **画板写入排队**（`canvas-files.ts` 的 `withCanvasLock`）：自动收图、放图、标注、删图、界面操作都排同一条队。界面不再整份覆盖画板：切页和改标注只改那一处。
- **不留临时文件**：写入失败时删掉临时文件；Windows 上改名遇到短暂占用（EPERM、EBUSY、EACCES）重试 5 次；打开画板时清掉超过 10 分钟的 `.board.json.*.tmp`。
- **说明书**：`base.md` 写「要放进项目用 `ffpane_export_canvas_image`，不删原图」。为了不超过 2KB 上限，同一段里「按 revisions 里的文字和绘制改原图」缩成「按它返回的 marks 和 markedImage 改原图」（工具本来就会返回这两项）。`manager.md` 没改：删图已经由代码拦成申请。

### 已验证

- 单测：删进回收站再恢复（回到原页、标注回来）、恢复时同名换名、彻底删除和清空、没标「不要」只挂申请、保留和同意、标了「不要」直接进回收站、不写原因不行、导出和覆盖、导出越界、12 张图同时收图和放图不丢行、不留 `.tmp`、清旧临时文件；生图一次一张、删图要原因。
- e2e（新加 `canvas-library.spec.ts`，真跑应用）：标不要、删进回收站、恢复、处理删图申请、二次确认后彻底删除，都核对了磁盘上的文件。

## 5. 验收办法

在 dev 模式（FF-pane.exe）下：

1. **Codex 记忆**：开一个 Codex 窗口，问它「你的系统说明里有没有 Memory 段、有没有别的项目的内容」；续接一次再问。自己在终端里开 `codex`，记忆照常，里面没有 FF-pane 监管的内容，过几天也不回来。`~/.codex/config.toml` 没变。
2. **输入框**：
   1. 在一个 Claude 窗口里打半句停下，让别的窗口给它发消息：消息不进框，窗格提示条显示等你发完；你回车、做完这一轮后消息再进去。
   2. 用输入法打中文，选词时停一会儿：不投。
   3. 打字后全删掉：消息很快就进去。
   4. 框里有字时点「立即发送」（新开、还没跑过一轮的窗口才有这个按钮）：拒绝并提示。
   5. 在 Codex 窗口重复 1 到 3。
   6. 多个窗格之间来回点：别的窗口发来的消息照常马上投，不会因为点了窗格就等。
3. **画板**：
   1. 让一个执行出图，再让它删掉：图还在，图上显示申请和原因；点「保留」或「同意删除」。
   2. 先把一张图标成「不要」，再让执行删：直接进回收站。
   3. 回收站里恢复一张：回到原来那一行。彻底删除要确认。
   4. 让执行用 `ffpane_export_canvas_image` 把图导出到项目里：原图还在画板，说明里显示导出位置。
   5. 订阅出一张图：工具一次返回成功和路径，不再报「控制通道超时」。
   6. 一边出图一边改标注：画板不丢行，目录里不留 `.tmp`。
4. **回归**：开几个窗口互相发消息、做完汇报，投递和以前一样。
