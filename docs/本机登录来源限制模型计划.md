# 本机登录来源限制模型计划

> 状态：2026-11-28 方案已和 Tony 对齐，只写计划，没动代码，等 Tony 说开工。
> 起因：Tony 配了一个本机登录的 agy Provider（「agy---codex谷歌号」，读到 7 个模型），发现开窗根本没用它；追问后确认 Codex、Claude 的本机登录 Provider 也是一样。

## 1. 现状（2026-11-28 读代码和 Tony 本机数据确认）

- 开窗取路线在 `apps/desktop/src/main/workbench/resolve-config.ts`：本机登录（`local_cli`）这一路只读配置里的 `model` 字段，**不读 Provider**；只有中转（`relay`）才取 Provider。
- 配置编辑器 `ConfigEditorDialog.tsx:168` 把 `templateId === "local-login"` 的 Provider 整个过滤掉，配置里根本选不到本机登录的 Provider。
- 配置里本机登录的模型下拉来自现场调 CLI 枚举（`providers:list-local-models`），不是 Provider 里存的清单。
- Tony 的 `configs.json`：`gemini`、`codex` 都是 `{connectionMode:"local_cli"}`，没有模型，也没指向 Provider；所以 agy 用自己的默认模型（`Gemini 3.8 Flash (Medium)`），Codex 用 `~/.codex/config.toml`。
- 本机登录 Provider 的模型清单现在只有两处用到：中转配置里的模型候选、旧的「档案（Profile）」编辑器的模型下拉。工作台开窗不读它。
- Provider 页本来就能给本机登录的模型逐行删（垃圾桶），所以「留下的模型」这一步现在就能做，缺的是开窗时去读。

这和「Provider 是模型来源，订阅登录和中转都算」的口径不一致，是设计缺口。

## 2. 规矩（Tony 定）

1. **Provider 里留下的模型 = 允许使用的模型集合**，可以有多个，不是只留一个。要区分的是「这个来源能用哪些模型」。
2. **清单为空 = 不限制。** 免得清单忘了填就开不了窗。
3. 默认模型（`defaultModelId`）是可选的：设了，没单独指定模型时用它；没设，不传模型，用 CLI 自己的默认模型。
4. **只管 FF-pane 自己指定的模型。** 用户本地登录的 CLI 能用就行，不去干预：不拦用户在终端里自己切模型，也不检查 CLI 自己的默认模型在不在清单里（Tony 2026-11-28 定，理由：这样最合规）。

## 3. 设计

### 3.1 配置里本机登录这一路可以选一个来源

- `ProjectConfigRoute` 的 `local_cli` 变体加可选 `providerId`（只能是 `local-login` 模板的 Provider）。共享类型 `packages/shared/src/domain/project-config.ts`，存储 `packages/storage/src/project-configs/store.ts`（`pickRoute` 现在会丢掉本机登录的 `providerId`，`normalizeRoute` 要放行并校验格式）。
- 不选来源：和现在完全一样，不限制，已有配置不受影响。
- 一视同仁：Claude、Codex、Grok、Cursor、Gemini 都支持。DeepSeek 只有中转，不适用。

### 3.2 开窗时的取值（`resolve-config.ts`）

- 选了来源：读 Provider。
  - Provider 不存在：报错「配置「…」的 X 本机登录来源不存在」（同中转的口径），不悄悄放行。
  - Provider 被停用（`enabled:false`）：报错。
  - 允许集合 = Provider 里 `kind` 为 chat 的模型 id。
- 模型取值：配置里填的 `model` 优先；没填，用 Provider 的 `defaultModelId`；都没有，不传，用 CLI 自己的默认模型。
- 检查：允许集合非空，且上面取到的模型不在集合里 → **拒绝开窗**，提示「模型 xxx 不在来源「yyy」允许的模型里」。
- `LaunchCliRoute` 记下 `providerId` 和允许集合，窗口布局里记 `routeProviderId`，供开窗之后的检查用。

### 3.3 CLI 自己的默认模型：不管（Tony 定）

不填模型、Provider 也没设默认模型时，我们不传模型参数，CLI 用它自己的默认（agy 现在是 `Gemini 3.8 Flash (Medium)`）。FF-pane 不检查它在不在清单里，**不提示、不拦**：用户本地登录的能用就行。

### 3.4 开窗之后换模型也要查

- 管理者 `ffpane_open_window` 的 `model` 参数、`ffpane_set_model`（`handlers.ts` 的 `setModelEffort`）：按窗口记下的 `routeProviderId` 查 Provider，模型不在允许集合里就拒绝，返回里写清楚允许哪些。

### 3.5 界面

- 配置编辑器：本机登录那一块多一个「来源（可选）」下拉（只列本机登录模板的 Provider）。选了之后，模型下拉只列这个来源的模型；手填的不在集合里，保存时就提示。
- 新建窗口对话框：显示「使用配置 xxx（本机登录 · 来源 yyy · 模型 zzz）」。
- Provider 页：本机登录的 Provider 加一句说明「这个来源只决定能用哪些模型；账号仍是 CLI 自己登录的那个」。
- 管理者自配置工具 `apps/desktop/src/mcp/config-tool.ts`：本机登录的路线接受可选 `providerId`，且必须是本机登录模板的 Provider。

## 4. 做不到的边界（要写进界面说明）

- **不拦用户在终端里自己敲 `/model` 切模型**（Tony 定：不需要拦，也拦不住）。限制只管 FF-pane 自己指定的模型：开窗、配置编辑器、管理者开窗和管理者换模型。界面说明里写明。
- **一个 Provider 区分不了账号**：登录信息在 CLI 自己那里（agy 在凭据管理器里），所以它能区分的是「用哪些模型」，不是「用哪个账号」。

## 5. 开发顺序（Tony 说开工后）

1. 类型和存储：`providerId` 进本机登录路线 + 单测（保存、读回、旧文件兼容）。
2. 开窗取路线：读来源、取默认模型、检查允许集合 + 单测（含来源不存在、停用、清单为空、模型不在集合）。
3. 开窗后检查：`ffpane_open_window` 的模型参数、`ffpane_set_model` + 单测。
4. 配置编辑器和新建窗口对话框 + i18n + e2e。
5. 管理者自配置工具 + 单测。
6. Provider 页说明、计划文档补实现记录。
7. 在真窗口里验证（见 §7）。

## 7. 验证清单

1. 不选来源：和现在一样，所有 CLI 的本机登录窗口照常开，不限制。
2. 选了来源且清单有 N 个模型：配置编辑器的模型下拉正好是这 N 个。
3. 指定允许的模型：开窗成功，`--model` 带的就是它；没指定模型且设了默认：用默认。
4. 指定不在清单里的模型：开窗被拒，提示写清是哪个来源允许哪些。
5. 清单为空：不限制，任何模型都能开。
6. 来源被删或停用：开窗被拒，提示清楚。
7. 管理者开窗带不允许的模型：被拒；允许的：通过。`ffpane_set_model` 同理。
8. Claude、Codex、Cursor、Grok、Gemini 各一次，真窗口里看启动参数里的模型（agy 看 `--model`，Codex 看 `-m`，Claude 看 `--model`）。
9. 终端里手敲 `/model` 切到清单外的模型：不会被拦（预期，界面说明里写明）。
10. 不指定模型、Provider 也没设默认：开窗不报错、不提示，不传模型参数，CLI 用自己的默认。

## 9. 真窗口验证（2026-11-28，agy 用户目录指到临时目录）

## 10. 踩到的坑（都已处理）

1. **打包前必须先重新构建 `packages/*` 的产物。** 桌面端打包和 e2e 读的是 `packages/storage`、`packages/shared` 的 `dist`，只改源码不重建，会把旧代码打进去。第一次 e2e 里配置保存后丢了 `providerId`，就是这个原因（单测直接走源码，发现不了）。发版前跑一遍 `pnpm build`（或至少 `pnpm --filter @ff-pane/shared run build` 和 `@ff-pane/storage` 的）。
2. **开发构建 / e2e 去动了用户真实的 agy 插件（我造成的，已修）。** 用户装了 2.0.9 并添加了 agy 插件后，我跑的 e2e 用的是开发构建，启动时自动更新把已装插件判成「过期」（路径和开发构建不同），尝试重装；管理者的 agy 窗口占着插件目录，重装失败，agy 在用户的插件目录里留下 12 个 `.install-数字` 临时暂存目录。真实插件内容没被改。已清掉这些临时目录。
   - 根因：启动自动更新对任何构建都开着。改成**只有打包后的安装版才自动更新**，开发构建和自动化测试一律不碰（`shouldAutoUpdateAgyPlugin`，有单测）；已用 e2e 在装了插件的机器上验证插件目录不变。
   - 教训：在用户机器上跑 e2e，不能让它去动用户真实的用户目录（`~/.gemini`、`~/.codex` 等）。
3. 测试里查 agy 启动参数，要按测试目录过滤：机器上可能有别的 agy 窗口（比如管理者正在用的），按进程名查会查到别人的。
