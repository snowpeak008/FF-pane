## 2. A · 密钥安全（最高优先级）

### 2.1 明文不得进入的通道

| 通道 | 判定 | 证据 |
|---|---|---|
| 命令行参数 / `configOverrides` | **通过** | `resolveProviderInjection`：密钥只进 `env`；Codex `env_key` = JSON 字符串变量名（`OPENAI_API_KEY`），非明文。`assertSecretNotInOverrides` + 单测锁定 |
| `providers.json` / `.bak-v1` | **通过** | 领域类型仅 `apiKeyRef`；迁移复制原文件作备份，不把密钥写入 JSON |
| MCP `config_list_providers` | **通过** | `sanitizeProvider` 显式字段构造，`apiKeyConfigured` 布尔；schema/白名单无 apiKey/apiKeyRef；E2E sidecar 脱敏钉死 |
| 渲染端 IPC 返回 | **通过** | `providers:list` 返回含 `apiKeyRef`（引用，非明文）；`secrets:masked-tail` 仅尾码；`revealSecret` 注释声明永不上渲染通道 |
| 日志 / 错误信息 | **通过（抽查）** | 密钥错误走 `Secret*` 家族、cause 链；注入错误消息不含明文；grep 未见把 apiKey 打进 `console.*` 的业务路径 |
| 密钥输入框回显 | **通过** | `ProviderEditorDialog` / `ConfigDraftDialog`：`type="password"` |

### 2.2 extraEnv

- 注入时：`mergeExtraEnv` 拒绝 `PATH`/`ComSpec`/`SystemRoot`/`NODE_OPTIONS`/`ELECTRON_RUN_AS_NODE` 等；与 `secretEnvKeys` 同名项跳过（不可覆盖密钥变量）。
- **缺口（建议）**：`validateProviderDraft` 只检查 extraEnv 形态，**不**调危险名单 → 可落盘危险键，到启动才抛。MCP draft 同理可写入。
- **建议**：补 `LD_PRELOAD` / `DYLD_INSERT_LIBRARIES`（Windows 主战场次要，跨平台仍应封）。

### 2.3 其它

- Adapter spawn 清洗宿主敏感 env（`isApiKeyEnvName`）仍在；local-login 不注入本轮密钥。
- Probe / 保存路径：渲染→主进程可短暂传 `apiKey` 明文（既有设计，用完存 safeStorage）；返回体不含明文。

## 3. B · 注入正确性（官方文档 + 本机 help）

### 3.1 Claude Code

对照：[Authentication](https://code.claude.com/docs/en/authentication)、[Environment variables](https://code.claude.com/docs/en/env-vars)、本机 `claude --help`。

| 变量 | 官方语义 | 本实现 | 判定 |
|---|---|---|---|
| `ANTHROPIC_API_KEY` | `x-api-key`；直连 Anthropic | anthropic-official / openai-\*×claude / anthropic-compatible 选 api_key | **正确** |
| `ANTHROPIC_AUTH_TOKEN` | `Authorization: Bearer`；网关/中转默认推荐 | anthropic-compatible **默认** | **更正确**（产品决策） |
| `ANTHROPIC_BASE_URL` | 指向网关/自定义端点 | 有 baseUrl 时注入 | **正确** |
| `ANTHROPIC_MODEL` | 模型覆盖（env 表） | 有 model 时注入（旧 env.ts 无） | **增强 / 更正确** |

### 3.2 Codex

对照：[Environment variables](https://developers.openai.com/codex/environment-variables)、Codex `model-provider-info` 源码、本机 `codex --help` / `codex exec --help`。

| 点 | 官方 | 本实现 | 判定 |
|---|---|---|---|
| 非交互密钥 | 公开文档：`CODEX_API_KEY` 供 exec | 产品决策 / 旧流程：`OPENAI_API_KEY`；自定义 provider 的 `env_key` 指向它 | **有 baseUrl 时正确**；无路由时与旧等价、与公开文档略有落差（建议） |
| `model_providers.<slug>.{name,base_url,env_key,wire_api}` | 字段名正确；`env_key` = 变量名 | 一致；`-c` 值 JSON 字符串化 | **字段名正确** |
| `wire_api` | 现行源码：**仅 `responses`**；`"chat"` 反序列化报错并指引改 responses | 模板默认 **`chat`**；options 仍列 chat | **必须修复（回归）** |
| `preferred_auth_method` | 已移除（≥0.35） | 未使用 | **正确（不依赖）** |

**必须修复细节：** 旧 `resolveRuntimeConfigOverrides` 在 openai_compatible+baseUrl 时写 name/base_url/env_key，**不写 wire_api** → 现行缺省 `Responses`。新解析器默认写入 `"chat"`，对当前 Codex **启动即失败**。单测 `session-env` / `provider-injection` 目前锁定 chat，需一并改。
