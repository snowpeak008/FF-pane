### 2.4 上限语义

- Renderer：`countRunningWindows()` = **布局窗口数**（全项目合计）；UI 先拒。
- Main：`manager.aliveCount() >= max` 拒 `terminal:create`。
- 双通道一致目标不同（布局 vs 存活 PTY），正常 UI 路径够用；并行连点新建存在「布局先 +1、某一路 create 被拒」的软竞态——非阻断，建议后续原子化。

### 2.5 风格与其它

- 中文文件头注、`readonly`、空态、标题栏可改名/状态、角色权限位仅注释预留（无假数据）——符合合同。
- 关标签有运行中确认；关窗直接杀 PTY——与合同「关闭(有运行中确认)」对标签、「关窗杀 PTY」一致。

## 5. 重启后布局恢复 E2E（E）——必须修复

**合同要求：** 重启应用后布局恢复，并在原 cwd 重启 shell（cwd 不存在回退项目根并提示）。

**现状：**

- 产品路径：`hydrate` ← `workbench:get-layouts`；`TerminalView` 按窗口 cwd/`fallbackCwd` 再 spawn——实现意图正确，但**无自动化锁死**。
- 执行者承认未做该 E2E；本轮 E2E 仅覆盖进程内切换 / 关窗 / 上限。
- **技术可行性：可行。** `apps/desktop/tests/e2e/_launch.ts` 已增加 `dataRoot` / `retainDataRoot`（注释写明「T10.2 重启恢复布局」），可复用同一 `FF_PANE_DATA_ROOT` 二次 `launchApp`。仓库内亦有「经重启仍…」先例（如 `ui-language.spec.ts` 跟随系统持久化）。**不构成「技术上不可行」例外。**

**实现建议（供执行者）：**

1. 在 `workbench-terminal.spec.ts` 新增独立 `test`（或 `test.describe`）：
   - `launchApp({ retainDataRoot: true })` → 建项目 → 开标签/分屏 → `echo MARKER_RESTART` → 可选改标签名；
   - 记录 `dataRoot` 与窗口数/标题；
   - `await cleanup()`（保留 dataRoot）→ 再 `launchApp({ dataRoot, retainDataRoot: false })`；
   - 进工作台：断言窗口数/分屏结构/标题恢复；断言新 PTY 可 `echo`（输出为新会话，**不要求**跨进程保留环形缓冲——合同是布局+cwd 重启 shell）。
2. 可选第二条：把窗口 cwd 指到已删目录，断言回退项目根 + toast/`workbench.cwd.fallback`。
3. 退出前若补了布局 flush，E2E 在 `app.close()` 前可先 `await page.waitForTimeout(500)` 或显式 IPC `workbench:save-layout` 作双保险；但产品仍须默认 flush，不能只靠测试等待。

### 10.2 退出 flush（重点审阅）

| 场景 | 行为 | 判定 |
|---|---|---|
| 渲染端卡死、永不 ack | `QuitCoordinator.flushLayouts` → `raceBudget(800ms)` → 记日志继续 quit | **不会拖住超过预算** |
| `mainWindow` 已销毁 / `isDestroyed` | `requestFlush` 立即 `resolve`（不发事件） | **不阻塞** |
| `publishEvent` 抛错 | catch 后立即 resolve | **不阻塞** |
| flush 与 prepare 并行 | `Promise.all([flushLayouts, prepare…])`，各预算独立；flush **不并入** 3s 收尾 | **正确** |
| 有 `flushLayouts` 时无在飞也拦截 | 与「零成本放行」相比，每次退出多一轮 flush IPC（通常很快；卡死上限 800ms） | **可接受**（合同优先落盘） |
| 用户点窗关闭（X） | `closed` 先把 `mainWindow=null`，随后 `window-all-closed`→`quit`→`before-quit` 时 flush 桥已无 webContents；依赖此前 `pagehide`/`beforeunload` 的 **fire-and-forget** `flushWorkbenchLayouts` | **残留观察**：关窗路径不如「窗仍在时 app.quit」稳；E2E 走 `app.close()` 覆盖的是后者。见 §10.6 |

单测：`session-quit` 覆盖「有 flushLayouts → preventDefault，flush 后 quit」。**缺**「flush 超 800ms 仍 quit」专测（同款 `raceBudget` 已在 runtime close 超时用例验证）——建议补，不挡。

### 10.3 PTY 对账（重点审阅）

`planTerminalReconcile` 约定：

- **无 `metadata.windowId`（或空）→ 跳过，不当孤儿。** smoke/`runPtyCheck` 自建短命 `PtyManager` 且不带 windowId；共享管理器上未来非工作台 PTY 只要不写 `windowId` 就不会被杀。
- 布局中无对应 windowId → 孤儿杀；`projectId` 与布局不一致 → 孤儿杀；同 windowId 多存活 → 保留先到、其余孤儿。
- hydrate 时 `rememberLiveTerminal` 后 TerminalView `attachExisting`，避免重 spawn。

| 风险 | 判定 |
|---|---|
| 误杀 smoke / pty-check | **否**（无 windowId / 独立 manager） |
| 误杀未来其它用途 PTY | **否**，前提是不借用工作台的 `metadata.windowId`；若误用且不在布局中会被杀——约定写清即可 |
| 误杀「正在创建中」的 PTY | **低**：hydrate 仅一次（`hydrated` 门闩）；创建发生在布局写入与挂载之后。理论窗口：对账 `list` 之后、挂载前极短窗口内另开 create——实际路径难触发。同窗双 PTY 时下次对账会收掉多余者 |
| reload E2E | **真实**：同 `terminalId` + `list` 该 windowId 存活数 === 1 + 回放仍含标记 |
