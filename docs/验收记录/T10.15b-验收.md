## 2. 伪造和撞车

**两份都只有同一记号：不认。** 立刻返回未识别，两份会话都不进入已认领集合，不会挑较新的那份。别人的记号、错目录里的记号、以及单独一份里同时塞了本窗口记号和别的记号，都不会被认成本窗口的。空等超时也一样。

反向探针：把「多份就撞车」改成挑第一份合格的。同一记号立刻被认成 `copy-a`。还原后重新拒绝。还原后的文件指纹和探针前一致。

**必须修复：记号出现在两份里，但其中一份还带了别的记号。** 一份 rollout 只有本窗口记号，另一份同时有这个记号和另一个记号。认领返回了那份干净文件的会话编号。实现把「一份里有多个记号」排除在配对之外，于是只看见一份干净文件，就当成唯一。检查清单写的是：同一记号出现在两个 rollout 里，不得挑一个认领。带了额外记号的那份仍然算出现过。应收紧为：前缀里只要出现这个记号，就计入份数；多于一份就标未识别，两份都不认。

## 3. 识别失败不得接最近一条

**只开选择器。** Claude 没有编号时参数是单独的 `--resume`。Codex 没有编号时是 `resume`，后面不跟会话编号。两边都没有 `--last`，也没有 `--continue`。新开的 Claude 仍带 `--session-id`。源码里没有把 `--last` 或 `--continue` 放进参数。界面上编号未识别时，即使还握着旧编号，续接计划也是选择器。没有编号时，模型强度不会自动续接。

反向探针：给两条选择器路径加上 `--last`。对应断言立刻变红。还原后通过。还原后的文件指纹和探针前一致。

历史只保留编号、开始时间、最后活动时间，超过 24 条丢掉最久没活动的。短编号取前 8 位。

## 4. 管理者和全放开

**第一次续接要确认，不会自己重启。** 管理者、全放开在这次进程里还没确认过时，确认函数返回要问。普通编辑窗口不问。模型强度在空闲、已有编号、且需要确认时，结果是确认，`launch` 为假，发出的是确认而不是续接。普通窗口才会发出续接。

反向探针：把确认函数改成恒为不问。管理者那条立刻变红。还原后通过。还原后的文件指纹和探针前一致。

建议（不挡这次）：同一个窗口在这次进程里确认过一次之后就记住，之后再续接不再问。这是原来的确认规则。模型强度若在一次已经确认、正在续接的过程中又收到新值，这次结束后会再续接一次，不再弹第二次确认。若希望每一次都问，要另定，不要塞进这次收紧撞车的修复里。

## 5. 窗口令牌

**令牌不进 argv、日志、文件。记号可以出现在开发者说明里。** 假令牌和记号是两串不同的值。Codex 参数里的 `developer_instructions` 含有 `ffpane-claim:` 加记号，不含假令牌。把假令牌塞进表面时，启动前的检查会抛错。Claude 的 MCP 临时文件和 Codex 的转发规格里都没有令牌明文；Claude 文件里只有 `${FF_PANE_WINDOW_TOKEN}`。钩子设置文件和 notify 参数也不含假令牌。认领扫描失败时的日志只有错误摘要，没有令牌，也没有记号。
