## 1. 现状和问题

Tony 提的事：顶部标签太小；换分辨率不适配；拖动后界面不一样；窗口多了排不整齐。代码里的原因：

| 现象 | 原因 | 位置 |
|---|---|---|
| 标签难点 | 标签栏 32px（`h-8`），标签 24px（`h-6`），字 12px，没有最小宽度，「Tab 1」只有约 50px；关闭按钮悬停才出现 | `pages/workbench/TabBar.tsx` |
| 窗口越开越窄 | 新窗口一律在目标窗口右边切一半（管理者开的子窗口也是），同一标签满 4 个才开新标签，所以排不成网格 | `shared/workbench/place-child.ts`（`WORKBENCH_TAB_WINDOW_SOFT_LIMIT = 4`） |
| 换小屏后窗格太窄 | 最小尺寸是父容器的 15%（`minSize={15}`），不是像素 | `pages/workbench/SplitLayout.tsx` |
| 拖完各窗格高低不齐 | 窗口标题栏和信息条用 `flex-wrap`，窄了就折成两三行，终端被挤矮 | `pages/workbench/WindowPane.tsx` |
| 拖一条线好几个窗口一起变 | 布局是二叉切分树，拖外层分隔线，里面所有窗格按比例一起缩放 | `PaneSplit`（`packages/shared/src/domain/workbench.ts`）、`shared/workbench/pane-tree.ts` |
| 同一布局换显示器样子不同 | 布局只存比例，加载时不按像素校正；没有横竖屏的概念 | `~/.aiworkbench/workbench-layouts.json`（version 4） |
| 不能把窗口拖到别处 | 工作台没有窗格拖放 | — |

参考：superset 和我们同栈（Electron + React + xterm + react-resizable-panels），借它的标签尺寸（48px 栏、160px 标签）和像素最小尺寸（260×160）。只借思路，不用它的代码（Elastic License 2.0）。

## 2. 第一批：标签与标题栏

### 2.1 标签栏

- 标签栏 32px → **48px**；标签占满高度，**固定 160px 宽**，名字过长截断并悬停显示全名。
- 字 12px → 14px。
- 选中的标签：一直显示关闭按钮，底边或顶边一条主色线，背景与终端区同色，看起来和下面连成一片。未选中的悬停才显示关闭按钮。
- 重命名输入框跟着变大；「新建标签」按钮跟着变大。
- 标签多了横向滚动（现有），滚动时选中的标签保持可见。

### 2.2 窗口标题栏只占一行

- 标题栏固定一行，不折行。按窗格宽度分三档（用容器查询，Tailwind 4 自带）：
  - 宽：标题、角色、模型、状态、按钮全显示；
  - 中：模型和次要徽标收起；
  - 窄：只留标题、状态点和「更多」，其余进「更多」菜单。
- 标题栏下面的信息条（投递、团队暂停、待处理等）也不折行，放不下的截断并可展开；能浮在终端上沿的就浮着，不占高度（1.0.8 投递条已是这样）。
- 结果：同一行的窗格，终端区顶边对齐。

### 2.3 验收

1. 1366×768、1920×1080、2560×1440，缩放 100%、125%、150% 各看一遍。
2. 一行 3 个窗格时，每个标题栏都是一行。
3. 标签 10 个以上能滚动，选中项可见；双击重命名、关闭照常。
4. e2e 选择器（`workbench-tab`、`workbench-tab-bar` 等）不变。

## 3. T11.2b：每页固定格子

「页」就是现在的标签页。

### 3.0 代码怎么组织（Tony 要求精简、独立、少依赖）

- **一个纯函数模块** `shared/workbench/grid.ts`：格子数据、放哪、换方向、关窗、旧树转格子，全在这里。只依赖 `@ff-pane/shared` 的类型，不碰 React、store、IPC，单测直接测它。
- **一个界面组件** `GridLayout.tsx` 取代 `SplitLayout.tsx`：只负责把格子画出来、把拖线的比例交回去，不管放哪。
- store、`place-child.ts`、`detach-window.ts` 只调 `grid.ts` 的函数，不自己算位置。
- 不加新库。拖分隔线用现有的 react-resizable-panels（一组里放多个面板，原生就是只动相邻两格）。
- 旧的 `pane-tree.ts` 只留「旧树按顺序取出窗口」这一个用途，其余删掉。

### 3.1 格子和方向

- 每页 **6 个格子**，编号 1–6。窗口记的是自己在第几格。
- **横向**（工作台区域宽 ≥ 高）：3 列 × 2 行。
  ```
  ┌───┬───┬───┐
  │ 1 │ 2 │ 3 │
  ├───┼───┼───┤
  │ 4 │ 5 │ 6 │
  └───┴───┴───┘
  ```
- **竖向**（高 > 宽）：2 列 × 3 行。
  ```
  ┌───┬───┐
  │ 1 │ 2 │
  ├───┼───┤
  │ 3 │ 4 │
  ├───┼───┤
  │ 5 │ 6 │
  └───┴───┘
  ```
- 看的是**工作台区域**的宽高，不是显示器：竖着放的显示器、或者把主窗口拉成窄长条，都算竖向。宽高接近（比例在 0.9–1.1 之间）时保持当前方向，免得拖主窗口时来回跳。
- 换方向时格子编号不变，只是位置重排；终端不重启。
- **空格子留着**，显示「＋ 新建窗口」，点了就在这一格开。
- 关掉一个窗口，那一格变空，别的窗口不挪。
- 最大化照旧：一个窗口占满整页，再点一次回到原来的格子。

### 3.2 新窗口放哪

| 怎么开的 | 放哪 | 没地方时 |
|---|---|---|
| 「新建窗口」、管理者开子窗口 | 当前页（子窗口是管理者所在的页）编号最小的空格 | 开新页，放第 1 格；子窗口的新页仍叫「团队：管理者名」 |
| 窗口上的「向右分屏」 | 同一行、这个窗口右边最近的空格 | 右边没有空格（已经在最右，或右边都占了）→ 开新页，放第 1 格 |
| 窗口上的「向下分屏」 | 同一列、这个窗口下面最近的空格 | 下面没有空格 → 开新页，放第 1 格 |

- 取代现在「在右边切一半、满 4 个开新标签」的规则（`place-child.ts`）。
- 开到新页时自动切过去，焦点给新窗口。

### 3.3 拖分隔线：只改相邻的

Tony 要求拖动只改变自己。网格里横线和竖线不能同时都只动两格（会互相重叠），定成（Tony 已认可）：

- **每一行是独立的一条。** 拖行里的竖线，只改它左右相邻的两格，别的行不动。例：横向拖 1 和 2 之间的线，只有 1、2 变宽变窄，3、4、5、6 都不动。
- **拖两行之间的横线，只改这两行的高度**，别的行不动。
- 竖向同理。
- 拖不到太窄：每格不小于 10%（1366 宽横向约 135px 起，够看标题）。不做按像素换算。
- 比例按页、按方向分别存：横向调过的比例不影响竖向；没调过就均分。
- 双击分隔线恢复均分。

### 3.4 数据

- `WorkbenchTab` 加 `slots`（6 个，每个是窗口编号或 `null`）和 `sizes`（横向、竖向各自的行高和每行列宽，可缺省为均分）。
- 存档升到 version 5，照现有 v1→v4 的做法读旧版：读到没有 `slots` 的旧标签，按旧树从左到右、从上到下的顺序排进第 1–6 格，超过 6 个的放进新页（标题加「(2)」）。不另做备份文件和只读回退，第一次保存时按新格式写出。
- 旧树只在读旧档时用一次，之后不再存。

### 3.5 验收

1. 用 Tony 现在的布局文件打开：窗口都在、顺序对、终端不重启。
2. 新建窗口依次落到 1、2、3、4、5、6 格；第 7 个开到新页第 1 格。管理者连开子窗口同样如此。
3. 向右分屏：右边有空格就落进去；在最右一格点 → 开新页。向下分屏：下面有空格就落进去；在最下一行点 → 开新页。
4. 关掉第 2 格的窗口，第 2 格变空，别的窗口不动；点空格的「＋」在这一格开。
5. 拖 1、2 之间的线，只有 1、2 变；拖两行之间的线，只有这两行变；双击恢复均分。
6. 横竖切换：把主窗口拉成竖条，变成 2 列 × 3 行，编号顺序不变；拉回来恢复横向，比例还是原来的。
7. 1366×768、1920×1080、2560×1440 和竖屏各看一遍。
8. dev 模式（StrictMode 会把挂载执行两遍）和打包版都过一遍。
9. `grid.ts` 单测覆盖放置、分屏、换方向、关窗、读旧档。

## 4. T11.2c：拖窗口换位置

- 按住窗口标题栏拖动：
  - 落到另一个窗口上 → 两个**对调**；
  - 落到空格子上 → 移过去，原来那格变空；
  - 落到别的标签上 → 移到那一页编号最小的空格；那页满了就不让放，并提示「这一页满了」；
  - 落到「新建标签」按钮上 → 开新页，放第 1 格。
- 拖动时目标格高亮。
- 拖动期间在终端上盖一层透明遮罩，免得 xterm 吃掉鼠标事件。
- 只改布局，不动 PTY：窗口进程不重启，`live-terminals.ts` 的复用照旧。
- 拖动和拖分隔线期间，终端尺寸变化做节流，松手再按最终尺寸调一次伪终端。1.0.8 查过：系统 ConPTY 每调一次尺寸都整屏重画。
- 同样不加新库：用指针事件自己做，对调、移动的计算放进 `grid.ts`。

验收：拖到另一个窗口上对调；拖到空格移入；拖到别的标签移入；拖到满的标签被拒绝并提示；全程窗口不重启、终端内容不丢；Claude、Codex 窗口不出现整屏闪烁。

## 5. 风险

- 以前手动切出来的不规则布局（比如一个大窗口加三个小窗口）读进来会变成整齐的格子，样子会变：验收办法里写明。
- 拖放和 xterm 的焦点、输入法冲突：遮罩只在拖动时出现；松手后焦点回到被拖的窗口。
- 横竖方向在临界尺寸来回跳：用 0.9–1.1 的回差。
- e2e 里用切分树结构断言的测试要随数据结构改。
