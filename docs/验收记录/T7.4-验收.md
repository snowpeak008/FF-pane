## 2. 代码抽查发现

**未发现声明与实现不符之处，未发现红线被绕开，未发现真实失败。** 以下四条是抽查中记录的偏差与事实补充，均**不影响事实正确性**，不构成不通过理由。

1. **单测子项计数有 ±1 的搬移（总数 21 无误）。**
   声明「当前计划 3 · 进行中任务数 3 · 最后活动 6 · 降级 4 · 整表 5」，实际逐个 `it` 计数为
   **当前计划 3 · 进行中任务数 3 · 最后活动 6 · 降级 5 · 整表 4**，合计仍是 **21**。
   偏差来源是「读不到的源不伪装成 0」这条被摘要归到了「整表」，而它实际写在 `describe("summarizeProject —— 降级")` 里。
   与 T7.3a / T7.3b 验收记录的同类问题同一性质，纯口径。

2. **契约注释把「命令面板的项目切换」列为 `projects:list` 的第二个消费者，当前并不成立。**
   `contracts.ts:823` 写「`projects:list` 的另两个消费者（`useActiveProject` 与命令面板的项目切换）」。
   实测命令面板**不自己调任何 IPC**——`CommandPalette.tsx` 的项目列表由挂载方经 `projects` prop 注入
   （文件头注释即写明「项目列表由挂载方注入（本工单不新增 IPC 通道）」），而命令面板迄今**未挂进 `App.tsx`**（§0 既有遗留）。
   即今天 `projects:list` 的真实消费者只有 `useActiveProject` 一个。
   这**不影响那条设计决策的正确性**（把磁盘扫描塞进轻通道确实不该），只是注释把一个"将来的消费者"写成了现在的，
   属文档口径。命令面板一旦挂进去，它注入的正是 `projects:list` 的结果，注释届时即成立。

3. **`SETTLED_TASK_STATUSES` 与领域侧 `TASK_TERMINAL_STATUSES` 内容相同但未复用（工程建议，非偏差）。**
   `project-summary.ts` 自定义了一份 `["accepted","cancelled"]`，而 `packages/shared/src/domain/task.ts`
   已导出同内容的 `TASK_TERMINAL_STATUSES`。今天两者逐字相同，故当前结果正确；
   但若日后领域侧改动终态集合（如给 `cancelled` 之外再加一个终态），本文件不会跟着变，
   表现为"任务看板认它是终态、项目卡片仍把它算成进行中"。
   本地常量的注释确实论证了"为什么不是只数 running"，但没有说明"它与领域终态集合恰好一致"这件事——
   建议或改为 import 领域常量，或在注释里显式钉住这层一致性。**不构成不通过理由**（当前无事实错误）。

4. **冒烟模式 stderr 有一行 `No handler registered for 'projects:summary'`——性质与改动前一致，不影响冒烟判定。**
   本次实录该行确实出现（在 `main-sqlite` 与 `ipc-ping-pong` 两条 PASS 之间）。
   成因：`--smoke` 只装配 `app:*` / `diagnostics:*` / `smoke:*` 少数通道，却加载**真实 renderer**（`?smoke=1`），
   默认路由即项目页，于是页面照常发起它的数据查询而主进程没有对应 handler。
   **改动前同一位置报的是 `projects:list`**——已用 `git show 9962630 -- ProjectsPage.tsx` 核实该行原为
   `useInvokeQuery("projects:list")`，即这行噪声在 T7.4 之前就存在、只是通道名换了，性质未变。
   冒烟判定由七条 check + 退出码决定，本次 **七项全 PASS、exit 0**，未受影响。
   （如实登记：这行噪声本身是既有的可改进点——冒烟模式加载全功能 renderer 却只装配 4 个通道，
   任何页面级查询都会留一行 stderr。是否处置属冒烟基建范畴，不在本单。）
