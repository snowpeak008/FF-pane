## 2. 抽查发现

**未发现协议正确性缺陷，未发现红线被绕开。** 以下如实登记：

1. **（单测覆盖缺口，不影响结论但建议补钉）「半包逐字符」用例实际未测到跨 chunk 半包。** `acp-connection.test.ts:513-528` 对 PassThrough 同步循环逐字符 write，流会把它们合并成一个 chunk 投递——帧仍以整块到达行解码器。探针③（读取循环改按 chunk `split("\n")`，破坏跨 chunk 缓冲）后 46 条**全绿不红**；以「逐字符且每字符间 await 宏任务」的真半包临时探针验证，破坏版当场红（5 s 超时）、还原后绿。实现正确（`createLineDecoder` 缓冲真实生效，且其自身边界另有 events.test.ts 钉住），缺口只在本测试文件的这条用例名不副实。建议改为字符间 `await settle()` 的真跨 chunk 形态（三行改动）。
2. **（断言强度观察，本次已由验收补足）schema 字面量对照组是自洽断言。** `acp-protocol.test.ts:282-301` 的「对照官方 schema-v1.21.0」实为与测试内第二份手写清单比较（StopReason）与长度断言（SessionUpdate 11）——防手滑改 src 有效，防「源头就抄错」无效。本次验收以实际下载的官方 schema.json 完成了独立对照（§1-B，全部逐字吻合），正确性已证；是否引入 schema 节选 fixture 让单测自带独立数据源，量级与收益请主管理员裁量（fixtures 目录红线也需一并考虑）。
3. **（边界观察，b 单提醒）握手版本谈不拢抛 `AcpHandshakeError` 但不自动 close 连接。** 规范说客户端 SHOULD close the connection；实现把断开动作留给调用方（错误必然上抛，b 单 spawn 侧 catch 后应 close + 杀进程）。协议层不擅自管生命周期与「不 spawn」分层一致，语义可接受——b 单接线时勿漏。
4. **（声称核实，不影响结论）交付方所称 usage_update「与文档渲染页不一致」在当前渲染页未复现。** 本次抓取 agentclientprotocol.com/protocol/schema，SessionUpdate 节**含** usage_update（「Context window and cost update for the session」）——可能交付方查阅时渲染页尚未同步，或其所指为其他页面。关键事实不受影响：schema JSON 原文含该变体，实现收录正确，独立确认完成。
5. **（正面观察）畸形入站不回包的取舍论证扎实。** 与 MCP 服务端刻意不同的三条理由（id 无从关联 / 回声噪声 / 缺陷证据留档）读码后成立，且规范恰有「client MUST NOT write anything that is not a valid ACP message」条款——给畸形行回错误响应本身处于灰区，不回更合规（§1-C）。
6. **（正面观察）两个方向的 id 名字空间隔离干净。** 出站 nextId 单调自增、入站权限请求 id 归 Agent 分配住独立 Map，双工通道上最易踩的 id 冲突面结构性不存在（§1-C）。
