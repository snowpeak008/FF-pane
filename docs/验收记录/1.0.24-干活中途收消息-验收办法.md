# 1.0.24（T11.7）干活中途收消息：改动与验收办法

**日期：** 2026-11-07
**状态：** 已提交（2026-11-07，版本 1.0.24），尚未验收。
**计划：** [干活中途收消息计划.md](../干活中途收消息计划.md)。

## 1. 改动

- Claude 窗口每调用完一个工具，PostToolUse / PostToolUseFailure hook 问一次平台有没有该现在看的新消息，有就作为附加上下文插给模型，下一步就能看到。不往终端里打字。
- 只插上级和用户本人（「待你拍板」点的选项）的消息；下级汇报、平级消息照旧等这一轮结束。
- 未读全是该插的：插正文，标记已读，空闲时的提醒撤掉。夹着不急的：只插一句「谁发来几条，做完这一步先读收件箱」，不标已读。同一批只说一次。
- hook 每次只等 800ms，取不到就算了。
- Codex 窗口没做，照旧等空闲投递（原因见计划 §5）。

## 2. 已验证

- 单测：新增 `mid-turn-inbox.test.ts`（不插 / 插正文 / 只提一句、同一批不重复、来源多了截断）；`workbench-mcp.test.ts` 加两条（上级消息插正文并标已读；下级消息不插、夹着时只提一句不标已读）；`workbench-hook-digest.test.ts` 真起 hook 进程加两条（PostToolUse、PostToolUseFailure 输出附加上下文；没有要插的不写 stdout）。全量 2800 条通过。
- 真机：`claude -p --model haiku`（Claude Code 2.1.302）带一个 PostToolUse hook，读完文件后插一句带暗号的话，模型在回答里原样复述了暗号，确认工具调用之后插的内容模型看得到。
- `typecheck`、`lint` 通过；e2e 全套 66 条通过（这次改动没有新 e2e）。

## 3. 验收办法（dev 模式，《海上生存日记》或测试项目）

改的是主进程和 hook 脚本，要重启 FF-pane；已经开着的 Claude 窗口要重开或续接一次才会用上新 hook。

| # | 做法 | 应该看到 |
|---|---|---|
| 1 | 让一个 Claude 执行窗口做一件要调好几次工具的活（比如逐个读十几个文件），中途管理者给它发「停下，改成只看 X」 | 它在下一次工具调用后就提到这条消息并改方向，不用等这一轮做完 |
| 2 | 同上，但发消息的是它的下级（汇报） | 不打断，这一轮结束后照旧提醒 |
| 3 | Claude 窗口干活时，你在「待你拍板」里点一个选项 | 它在下一次工具调用后看到你的选择 |
| 4 | 第 1 条之后看它的收件箱 | 那条已读，空闲后不再重复提醒 |
| 5 | 干活时你在它的输入框里打字没发出去 | 你打的字不受影响 |
| 6 | Codex 窗口重复第 1 条 | 和以前一样，等它这一轮做完才收到 |
