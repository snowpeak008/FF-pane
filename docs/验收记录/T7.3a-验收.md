## 2. 代码抽查发现

**未发现声明与实现不符之处。** 以下四条是抽查中记录的偏差与缺口，均**不影响事实正确性**，不构成不通过理由。

1. **拒绝标记实为三条，声明只提两条。** `DENIAL_MARKERS` = `"Denied by permission policy"` / `"User cancelled the execution"` / **`"was not executed"`**。第三条未在交付声明与调研文档里点名。方向是安全的——多一条标记只会把更多「其实没执行」的 failed 归到 denied，漂移时的症状是多记一条阻断证据而不是漏掉一次越界，与 `mapper.ts` 自己写下的取舍一致。建议后续把它补进 `grok-build.md §7.3 坑 1` 的标记清单，以免日后重录 fixture 时无从核对来源。

2. **单测子项计数与实际分组有 ±1 的偏差。** 声明写「fixture 回放 15 · 适配器本体 4」，实际是 fixture 回放 **14** 个 `it`、适配器本体 **5** 个 `it`（声明把「resume 跨目录与空 ID 快速失败」合并成一条描述，实为两个用例）。**总数 28 与 +31 的总账无误**，纯属摘要口径。

3. **`grok-build` 的登录态探测规则没有专属分支单测。** `auth-probe/rules.ts` 新增的 `grokBuildRule` 只被 3 个通用参数化用例覆盖（cli_missing / timeout / 执行器异常），而既有四家（codex / claude-code / gemini-cli / opencode）各有一个专属 `describe` 块逐条验证其 `evaluate()` 分支。交付声明把 `src/auth-probe/` 列为落点但**未声称为其写了测试**，故不算不符；作为覆盖缺口登记。
   验收时在真机上独立验证了该规则赖以成立的前提：`grok models` 在未登录状态下**退出码为 0**、首行输出 `You are not authenticated.` —— 即「只能看文本、不能看退出码」的判断成立，规则的正则 `/not authenticated|not signed in/i` 命中该文本。

4. **`auth-probe.test.ts` 里两处测试标题已过期**：`describe("probeCliLogin：四 runtime 通用三态")` 与 `it("接受四个合法值、拒绝其他")` 现在覆盖的是**五个** runtime。纯文案，不影响断言。
