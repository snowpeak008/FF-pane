# 1.0.39 执行窗口用项目内沙盒、全放开不靠本机设置 —— 验收办法（T11.20）

> 计划：[`docs/全放开与执行窗口权限计划.md`](../全放开与执行窗口权限计划.md) §3（调研结果 §5.1，Tony 的决定 §5.2）。开发 2026-11-21，尚未验收。

## 前提

- **Claude Code 要先升到 2.1.329 或更新**（关掉 FF-pane 后在 PowerShell 里运行 `npm i -g @anthropic-ai/claude-code@latest`）。没升级时，FF-pane 会拦住「可改+跑命令」的 Claude 窗口并提示升级，这本身也是要验的一项。
- Claude 沙盒已装（2026-11-21 装的，`srt-sandbox` 账户在）。
- 改的是主进程和项目卡片。开发模式下改主进程，FF-pane 会整个重启。

## 改了什么

| 档 | Claude 窗口现在 |
|---|---|
| 只读、可改文件 | 不变 |
| **可改+跑命令（edit-exec）** | Windows 上开 Claude 自带沙盒：命令以 `srt-sandbox` 账户跑，**不问**；只能写项目和项目卡片里的「项目外可写目录」；只能连「沙盒可联网的域名」（默认 PyPI、npm、GitHub，再加项目卡片里填的），名单外直接拒、不弹问 |
| **全放开（YOLO）** | 不变，但启动时那个「Bypass Permissions mode」确认画面由 FF-pane 自己跳过，不再靠本机 `~/.claude/settings.json` 里的 `skipDangerousModePermissionPrompt` |

具体做法：

- 可改+跑命令的 Claude 窗口：
  - 进程环境加 `CLAUDE_CODE_NANKEEN_KESTREL=1`，这是 Tony 定用的内部开关；
  - `--allowedTools` 里加上 `PowerShell`、`Bash`，和协作工具合成一个参数；
  - 窗口自己的 `--settings` 里写 `sandbox` 一段：`failIfUnavailable`、`allowUnsandboxedCommands: false`、`windows.backend: "sandboxuser"`、`filesystem.allowWrite`、`network.allowedDomains` + `strictAllowlist`。
- 开窗前检查 Claude 版本（≥ 2.1.329）和沙盒装没装（`srt-sandbox` 账户），不满足就**不开**，提示怎么办。不会悄悄退回一直问，也不会悄悄变成全放开。
- 启动后沙盒还是起不来时（比如内部开关失效），Claude 会自己退出。FF-pane 认出「sandbox required but unavailable」，告诉它的监管者或上级原因和办法。
- 项目卡片「配置」里加「沙盒可联网的域名」，一行一个，存进 `projects.json` 的 `sandboxNetworkDomains`。不合法的写法（`*`、`*.com`、IP 等）整份不存，并报出是哪条。
- 管理者说明：执行、检查照旧开 `edit-exec`；`yolo` 要 Tony 同意才开（跑 Unity、起服务的先问）。
- 权限说明文字（新开窗口时权限下面那段）改成现在的意思。
- **设置 → 工作台 →「Claude 沙盒」**（§3.4）：显示 Claude 版本够不够（≥ 2.1.329）、沙盒装没装；没装给「安装沙盒」，装了给「卸载沙盒」，都要先确认，Windows 会弹一次管理员确认。都跑用户自己那份 Claude 的 `claude sandbox status / install / uninstall`（2.1.329 起才有，带内部开关），所以装的版本和 Claude 自己对得上。版本太旧时显示升级命令，按钮不可点。
- **卸载程序**（`resources/installer.nsh`，`electron-builder.yml` 的 `nsis.include`）：卸载 FF-pane 时问「要同时卸载 Claude 沙盒吗？」，默认「否」。选「是」就跑 `claude sandbox uninstall --json`。静默卸载、升级时的自动卸载不问、不卸。

## 验收步骤

1. **升级前先验拦截**（没升级 Claude 时）：开一个「可改+跑命令」的 Claude 窗口，应当开不了，提示「Claude Code 版本太旧（2.1.302）……npm i -g @anthropic-ai/claude-code@latest」。「可改文件」「全放开」的窗口照常能开。
2. **升级 Claude**：关掉 FF-pane，`npm i -g @anthropic-ai/claude-code@latest`，`claude --version` ≥ 2.1.329，再开 FF-pane。
3. **执行窗口不问、写不到项目外**：开一个「可改+跑命令」的 Claude 窗口，让它：
   - 跑 `python -c "print(1)"` 和一条带管道的命令：都不弹确认；
   - 用 python 往项目外随便一个目录写文件：报 Permission denied，文件没生成；
   - 往项目卡片里填的项目外可写目录写：成功；
   - `pip download six --no-deps -d tmp`：成功（在名单里）；访问名单外的网站：被拒。
4. **管理者开的执行窗口**：让管理者派一个活，开出来的执行窗口是「可改+跑命令」，干活时不弹权限确认，项目外没有新文件。
5. **全放开不靠本机设置**（可选）：把 `~/.claude/settings.json` 里的 `skipDangerousModePermissionPrompt` 删掉或改成 false，开一个全放开的 Claude 窗口，直接到输入框，第一句话照常送达。验完可以改回去。
6. **项目卡片**：「配置」里的「沙盒可联网的域名」填 `*.com` 保存，被拒并说明原因；填 `unity3d.com` 保存成功，重开执行窗口后能连。
7. **跑 Unity 的窗口**：照旧由你指定全放开。沙盒里 Unity 会因为授权在你的账户下而起不来（`No valid Unity Editor license found`），这是预期。
8. **设置里的「Claude 沙盒」**：设置 → 工作台，升级前显示版本太旧和升级命令；升级后显示「可以用」「沙盒已装 ✓」。不用真的点卸载。
9. **卸载程序**（以后出安装包时）：装上安装包再卸载，会问要不要一起卸 Claude 沙盒，默认「否」。

## 已知的

- **内部开关：** `CLAUDE_CODE_NANKEEN_KESTREL` 没写进官方文档，Claude 更新后可能失效。失效时窗口会起不来并提示，不会不受限地跑；到时候看 Anthropic 有没有正式开放。
- **沙盒里不能留后台进程：** 命令结束时，它起的后台进程会被收掉（调研 §5.1 第 3 条）。要起开发服务器的活由你指定全放开。
- **只在 Windows 上：** 其他平台的 edit-exec 不变。
- Claude 的「写文件工具」往项目外写，仍由 FF-pane 的写入钩子拒绝（1.0.25 起就有），不是沙盒拦的。
