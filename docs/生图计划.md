# 生图计划

> 状态：Tony 2026-10-10 要求先写计划。未开工，未改版本。
>
> 这一份只定生图。技能按项目指定是后话，写在 §2，这次不做。

## 1. 做什么

所有项目、所有窗口（管理者、执行、规划、监管、检查、普通终端里的 AI）要出图时，走同一条生图路。

入口是工作台工具，不是 skill，也不新开一个专门画画的聊天窗口。图写入当前项目的 `.ffpane/canvas/`，画板照旧收进去。改已有的图时，带上画板里已经写下的字和标记预览，新图作为这一行右边的版本。原图像素不改，新图里不画气泡。

设置只配一次，对所有项目生效。不放进「配置」里的 Claude / Codex / Grok / DeepSeek 路。那些路继续只管聊天窗口。

## 2. 技能（后话，这次不做）

这个软件自己没有技能系统。项目目录里没有一份可勾选的技能名单。

各家命令行自己有技能。Codex 有 `$imagegen`，Claude 会读用户目录里的 skill。那些归命令行，不归这个软件，也不能当成「某个项目启用了哪些技能」。

以后若要换策略、或某个项目指定技能，做在这个软件里：

- 换生图方案：这次的设置下拉就是换法。改完，下一次出图用新方案。不用重开窗口，不用改项目文件。
- 某个项目要用别的生图方案：以后在项目上加「沿用全局 / 另选」。缺省沿用全局。这次每个项目都沿用全局。
- 某个项目要指定技能：以后做项目级名单，随那个窗口启动写进该窗口的说明。不把技能文件写进 `~/.claude`、`~/.codex`、`~/.grok`，也不在每个项目里复制一份 skill。

## 3. 设置页放在哪

设置页现有顺序：外观、语言、工作台窗口、默认权限、角色说明、**模型来源**、**配置**、知识库、自配置。

在 **模型来源** 和 **配置** 之间加一块 **生图**。

放这里的原因：它是全局的一项，和窗口上限一样整页只有一块。模型来源是聊天和中转的密钥本；配置是每个项目的聊天路。生图两边都不是。不进项目卡片上的「项目配置」按钮，那个按钮仍只绑聊天配置。

## 4. 界面

一块，标题 **生图**。标题下两行说明：

- 所有项目、所有窗口出图都走这里。
- 聊天窗口仍用下面的「配置」，不受这项影响。

第一行用设置页现成的左右行（标签在左，控件在右），和「同时运行的窗口数」同一布局。

| 标签 | 控件 | 说明 |
|---|---|---|
| 方案 | 下拉，三项 | 见下 |

下拉三项，顺序固定：

1. **先不生图**（默认，升级后就是这项）
2. **Codex 订阅**
3. **中转站**

选「先不生图」时，下面不再出现输入框。再一行小字：窗口不能出新图。画板仍可看已经有的图。

选中后立刻保存这一项，并提示「已改用……」。和窗口上限的下拉一样，不用再点一次保存。中转站的地址、密钥、模型名另有保存按钮，因为那是一组字，不能每敲一个字就存。

### 4.1 Codex 订阅

选中后，下面出现一块凹下去的状态框，复用模型来源里已经有的 Codex 登录检查（同一条探测，不另做一套登录）。

框内：

- 左边状态：正在检查 / 已登录 / 未登录 / 未找到 Codex / 查不清
- 右边一个刷新按钮
- 状态下面一行等宽小字，是探测带回的说明（不含密钥）

状态旁边的固定说明，三句，一直显示：

- 用本机已经登录的 Codex 出图，不另填密钥。
- 出图会计入 Codex 用量，大约是普通一轮的 3 到 5 倍。
- 这一次出图会拿掉进程里的 API 密钥。Codex 看到密钥会改走 API 计费，订阅就用不上了。

没有模型名、尺寸、质量。订阅这条由 Codex 自己选生图模型。

没有「在这里登录」按钮。未登录或未找到时，说明写成：先在本机把 Codex 登录好，再回到这里点刷新。这个软件不替用户改 `~/.codex`。

没有「试出一张」。设置里只检查登录。真出图交给项目里的窗口，避免在设置里误扣额度。

已登录就可以用。未登录、未找到、查不清时，方案仍可保存，但窗口调用时会得到明确失败：Codex 还不能出图，原因是上面这一条状态。

### 4.2 中转站

选中后，下面出现一组表单，标签在控件上方（和模型来源的编辑框同一类，不是左右行）：

| 字段 | 要求 | 界面 |
|---|---|---|
| 地址 | 必填 | 单行文本。占位：中转站的生图地址 |
| 密钥 | 必填 | 密码框。已保存过则显示「已保存，尾号 abcd」，留空表示不改。明文只在保存前的输入里出现，保存后不再读回全文 |
| 模型名 | 必填 | 单行文本。占位：`gpt-image-2`。手填，不拉模型列表 |

按钮两个：

- **测试**：用屏幕上这份地址、密钥、模型名试一次，不写入任何项目。按钮文字写明会出一张测试图。成功只显示「通了」和耗时。失败显示原因，原因里不出现密钥。
- **保存**：三项都填了才能点。缺哪项，该框下用一行红字指出。保存成功提示「生图中转站已保存」。

测试不代替保存。没保存之前，窗口仍用上次保存的那份；从未保存过就不能出图。

接口按 OpenAI 兼容的生图来做：生成，以及按原图修改。这家中转不是这个接口时，这次不做第三种接法。

### 4.3 来回切换

方案可以随时改。改到另一项时，原来填过的中转站地址、密钥、模型名留在磁盘上，只是先不用。再选回「中转站」，输入框还在，密钥仍显示尾号，不用重填。

选回「先不生图」同样不删这些。只是窗口暂时不能出新图。

下一次出图才读当前方案。已经开着的窗口不用关掉。

## 5. 窗口侧（界面之外，同一条流程）

工具一个，任何窗口可调用。两个动作：

- **新图**：文字要求 → 程序出图 → 写入该项目 `.ffpane/canvas/`。
- **改图**：指出现有的一张图。程序带上 `.ffpane/canvas/revisions/` 里这份图的字和标记预览。新文件作为同一行的新版本。

Codex 订阅：工作台单独拉起一次很短的 Codex 进程，不新开聊天窗口。不写 `~/.codex`。这个进程的环境里拿掉 `OPENAI_API_KEY`。开工前先在这台已登录的机器上试出最短的一条命令，能出一张 PNG，再写进程序。图先落在 Codex 的临时目录，程序随后搬到当前项目的 `.ffpane/canvas/`，并从 Codex 目录删掉这一张，不留在那里。

中转站：主进程按已保存的地址和密钥发请求。密钥从系统密钥库取出，用完即弃，不进窗口，不进日志。

失败时工具返回原因，不往别的窗口终端里写正文。

角色说明加一句：要生图或改图，调用这个工具。说明仍压在大约 2KB 以内。使用说明改掉「生图没有单独配置」，改成：出图走设置里的生图，图仍进当前项目的画板。
