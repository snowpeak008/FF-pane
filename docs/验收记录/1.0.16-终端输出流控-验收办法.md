# 1.0.16（T11.0d 续）终端输出流控：改动与验收办法

**日期：** 2026-10-27
**状态：** 已提交（2026-10-27，版本 1.0.16），尚未验收。
**计划：** [主进程内存与白屏修复计划.md](../主进程内存与白屏修复计划.md) §4.2 最后一条（1.0.14 时没做的「终端输出推送加背压」）。

## 1. 原来的问题

- 主进程每 12ms 把**每个**终端的输出都推给界面。别的标签页里的终端界面没显示，收到就丢掉，切回去时再取回放。十几个窗口时，大部分推送是白推的。
- 没有流控：界面忙或卡住时（比如 1.0.13 打开画板那次），推送的消息一直堆在主进程里。

## 2. 改动

- 新模块 `main/terminal/output-flow.ts`（纯函数，不碰 Electron）：
  - **只推挂着的终端。** 界面显示一个终端时先 `terminal:attach`，不显示了 `attached: false`。没挂的输出照样进回放缓冲，挂上时界面自己取回放。同一终端被两个视图挂着按引用计数。
  - **按回执流控。** 界面把一批输出写进 xterm 后回执（`terminal:ack`，按字符串长度，50ms 合并一次）。没回执的超过 1MB 就先攒着；攒的超过 1MB 就扔掉，记下要重画；等没回执的降到 256KB 以下，发一次整份回放并带 `reset`，界面先清屏再写。显示不会错，只是那段时间的中间画面跳过了。
  - 终端退出时清掉它的状态。
- `TerminalView.tsx`：四处「取回放」合成一个 `loadReplay`：先挂上再取回放（挂上之后的输出要么在回放里，要么在回放之后到；回放之前到的会被 `reset` 清掉，不丢不重）。换终端时摘掉旧的，卸载时摘掉。收到输出写完再回执；不是这个视图的也回执。
- `terminal-output-ack.ts`：回执合并。
- IPC：新增 `terminal:attach`、`terminal:ack`；`terminal:output` 多一个可选的 `reset`。

## 3. 已验证

- 单测：新增 `terminal-output-flow.test.ts`（没挂不推；到上限攒着、回执后补发；攒着时顺序不乱；攒太多扔掉、缓过来发整份回放要求清屏；引用计数和退出清理）。全部单测 2715 条通过，typecheck、lint 通过。
- e2e 全套 64 条通过，其中「多项目分屏切换后输出还在」「切页面后终端还在」「重载后接回终端不重启」覆盖了挂上和取回放的顺序。

## 4. 验收办法

| # | 做法 | 应该看到 |
|---|---|---|
| 1 | 开两个标签页，每页几个窗口，让后台标签页里的窗口一直有输出（比如在跑任务），切回去 | 切回去时内容完整，接着实时刷新 |
| 2 | 在一个窗口里跑大量输出（比如 `Get-ChildItem C:\Windows -Recurse`），同时拖动、切标签 | 界面不卡死；输出最后的状态正确 |
| 3 | 照常带团队跑一段时间 | 日志里 `[memory]` 行主进程内存平稳 |
