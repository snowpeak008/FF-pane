## 4. 必须修复

1. **`manager.md` 超过说明书上限，`pnpm test` 因此失败。** `apps/desktop/tests/workbench-role-resources.test.ts` 要求每份角色说明书不超过 2048 字节。现在 `manager.md` 是 2921 字节，`worker.md` 是 803 字节，仍在限内。把管理者说明写短，直到测试通过。不要为了压字数删掉「只有用户要求才总结」和「确认后才保存」这两句。
2. **没恢复管理权、或被清洗锁住的管理者，仍会挂上自配置工具。** 挂载只看角色名是不是 `manager`、项目开关是否打开（`config-tool-attach.ts`）。冷读布局不会授予管理权。启动参数在管理权核对之前就装好了。锁住的窗口、父级还没被授予的子管理者，核对结果是不授予或待恢复，工具却已经在本次进程里。这两种窗口应拿不到工具；伪造令牌维持现在的拒绝。
3. **确认框会被误导，密钥也能绕过手输。** 名称和模型不拒绝、不清洗零宽字符、双向控制符和换行，看见的字可以和落盘的字不一样。来源草案的 `extraEnv` 可以带 `ANTHROPIC_API_KEY` 这类密钥，确认框不展示这些字段，确认后仍会写入 `providers.json`。应拒绝或清洗会误导的字符，并且不要让 AI 经隐藏字段写入密钥；确认框里应能看见将要落盘的非密钥字段。
4. **草案没有排队上限，也没有合并。** 短时间投进信箱的合格草案会全部待确认。界面同时只开一个，但处理完立刻弹下一个。要有上限或合并，多出来的应拒绝并说明，不能让用户一直点下去。

1. Codex 的语言和习惯在本次启动参数 `developer_instructions` 里，不是临时文件。不改用户全局 CLI 设置，也不写进 PTY。计划字面写的是临时文件。可以留到以后再改成文件，不必挡这次。

3. 设置里无法识别的输出语言，会被收成简体中文再写进提示。选「跟随」时不写，这是对的。执行说明里「无法识别就不写」和存储层的收口不完全一样。
4. 把一张带范围的配置设为默认：设置页是提示后清空范围，草案是直接拒绝。两种都不会留下「默认配置还有范围」。可以保持拒绝。
5. 语言和习惯在开窗口时写进提示。窗口开着之后再改设置或习惯，要重启该窗口才生效。执行记录已说明。
