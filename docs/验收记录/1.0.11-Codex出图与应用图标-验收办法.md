# 1.0.11 Codex 订阅出图修好、应用有了自己的图标：改动与验收办法

**日期：** 2026-10-24
**状态：** 已提交（2026-10-24，版本 1.0.11），尚未单独验收。
**真机：** codex-cli 0.162.0（Windows 11 22631）。

## 1. 用户报的问题

1. 设置里选 Codex 订阅，窗口经 `ffpane_generate_image` 出图，一直报「Codex 没有出图」。用户自己在 Codex 里出图一切正常。用户怀疑是 GPT 生图只能落在 C 盘。
2. 软件没有自己的图标，用的是 Electron 默认图标。

## 2. 查到的原因（出图）

和 C 盘无关。Codex 的图确实固定落在 `~/.codex/generated_images`（C 盘），但平台本来就是出图后再搬进项目，跨盘搬运走复制再删除（`EXDEV`），项目在 D 盘没问题。

真正的原因有两处，前后叠在一起：

### 2.1 codex exec 一启动就退出

- 平台在 `%TEMP%\ffpane-image-xxxx` 里起 `codex exec --ephemeral "<画面>"`。这个目录不是 git 仓库，也不在 Codex 信任的目录里。
- 本机实测：同样的命令在临时目录里只输出一行 `Not inside a trusted directory and --skip-git-repo-check was not specified.` 就退出，没有请求模型。
- 进程输出原先是 `stdio: "ignore"`，这句话谁也看不到，用户只能看到「Codex 没有出图」。
- 用户自己出图正常，是因为在 Codex 桌面版或终端里，会话开在用户信任过的项目目录里。

### 2.2 图落在会话子文件夹里，平台只看最外层

- 本机 `~/.codex/generated_images/` 下是一个个会话编号文件夹，图在里面：`generated_images/<会话编号>/exec-<编号>.png`。
- 平台原先只列 `generated_images` 这一层的文件，子文件夹一律跳过。就算 2.1 修好，图也拿不到。
- 原有单测的假进程把 PNG 直接写在最外层，所以一直通过。
- 排查时一度把 `01a16926…` 文件夹里 10-24 11:23 的两张图当成 FF-pane 出的。查 `state_5.sqlite` 后确认那是用户在 Codex 桌面版的会话「查看这个动作」，不是平台出的（用户指出）。FF-pane 的出图进程从没走到出图那一步。

## 3. 改动

### 3.1 出图（`apps/desktop/src/main/image-gen/generate.ts`）

- 启动参数加 `--skip-git-repo-check --json`。
- 进程 stdout、stderr 改为接管道。逐行读 `--json` 事件：`thread.started` 取会话编号，`error` / `turn.failed` 取报错，`item.completed` 里的 `agent_message` 留最后一句；stderr 只留尾巴，滤掉「Reading additional input from stdin...」。
- 找图顺序：先找 `generated_images/<这次的会话编号>/`，没有再按旧版找最外层这一次新出现的 PNG。会话编号只认字母、数字、横线、下划线，拼不出 `generated_images` 以外的路径。
- 只拿这次会话的图，用户别的 Codex 会话同时出的图不动。搬走后删掉空的会话文件夹（`rmdir`，里面还有东西就留着）。
- 没出图时报「Codex 没有出图。Codex 说：……」，原因优先级：超时说明 > 报错事件 > stderr > 最后一句回复，截到 300 字。
- 中转站出图没改。

### 3.2 应用图标

- 设计：三个圆角分屏窗口拼成字母 F。竖笔是蓝色终端（主色 `#2563eb`），里面是 `>_`；两横是浅色窗口，下面那个窗口里的蓝色文字行表示窗口之间互相投递。底色取暗色主题。
- `apps/desktop/resources/icon/`：`icon.svg`（正式稿，48px 及以上）、`icon-small.svg`（简化稿，32px 及以下：F 放大、去掉文字行、加浅色外框，深色任务栏上也看得清轮廓）、生成的 `icon.ico`（16/20/24/32/48/64/128/256，每张存 PNG）和 `icon.png`（512）。
- `apps/desktop/scripts/build-icon.mjs`：用本机 Edge（Playwright `channel: msedge`）渲染两张 SVG，拼出 ico。改 SVG 后重跑。
- `electron-builder.yml` 加 `win.icon`，安装包和安装后的 exe 用它；打包后窗口默认取 exe 自带图标。
- `src/main/index.ts`：开发态（`!app.isPackaged`）主窗口设 `icon`，指向 `resources/icon/icon.ico`。
- 根目录 `FF-pane.exe`：`launcher/FF-pane.cs` 没改，用系统自带 .NET 4 `csc` 加 `/win32icon` 重新编译（命令写在 `build-icon.mjs` 开头）。仍是窗口程序（subsystem 2），从 5KB 变成 46KB。

## 4. 已做的验证

- 本机真跑：临时目录里 `codex exec --ephemeral --skip-git-repo-check --json "<出图>"` 出图成功；第一行是 `thread.started`，图在 `generated_images/<该编号>/exec-*.png`。
- 本机真跑整条 `generateProjectImage`（Codex 订阅、真实 `~/.codex`、临时项目）：返回成功，图进了画板；`generated_images` 里没留下新文件夹，用户原有的两个会话文件夹没动。
- 单测：`generate-image` 新增 6 条——图在会话子文件夹里且别的会话同时有更新的图、会话编号带 `../`、带上 Codex 给的原因、输出解析三条。原有两条 Codex 用例补断言 `--skip-git-repo-check`、`--json`。
- 从新编译的 `FF-pane.exe` 取出关联图标，是简化稿的 32px。
- lint（biome + i18n）、typecheck 通过；单测 170 个文件 2644 条通过（1 条原本跳过）。

## 5. 验收办法

### 5.1 Codex 订阅出图

1. 设置 → 生图选 Codex 订阅。双击根目录 `FF-pane.exe` 启动。
2. 在任一窗口让它画一张图（经 `ffpane_generate_image`）。
3. 预期：半分钟到一分钟后图出现在当前项目画板，文件在 `.ffpane/canvas/gen-*.png`。`~/.codex/generated_images` 里不多出新的会话文件夹。
4. 在画板上对这张图打标签，让窗口按标签改图。预期：同一行多出新版本。
5. 失败时提示应带「Codex 说：……」，不再只有「Codex 没有出图」。

### 5.2 图标

1. 双击根目录 `FF-pane.exe`。预期：窗口左上角和任务栏是新图标。
2. 资源管理器里 `FF-pane.exe` 显示新图标。没变的话是 Windows 图标缓存，刷新或稍等；固定在任务栏上的要取消固定再固定一次。
3. `pnpm package` 后，安装包、安装后的 exe 和窗口都是新图标。

## 6. 风险

- 平台依赖 `codex exec --json` 首行的 `thread.started` 和 `generated_images/<会话编号>/` 这个落点。Codex 以后再改落点，会退回找最外层；还找不到就报「没有出图」，并带上 Codex 的原因。
- `build-icon.mjs` 依赖本机装有 Edge。只在改图标时用，不进构建流程。
