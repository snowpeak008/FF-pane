# 1.0.21（T11.2c）拖窗口换位置：改动与验收办法

**日期：** 2026-10-27
**状态：** 已提交（2026-10-27，版本 1.0.21），尚未验收。
**计划：** [面板布局计划.md](../面板布局计划.md) §4。

## 1. 改动

按住窗口标题栏（标题文字或空白处）拖：

| 落到哪 | 结果 |
|---|---|
| 另一个窗口上 | 两个对调 |
| 空格子 | 移过去，原来那格变空 |
| 别的标签 | 放到那一页编号最小的空格；那页满了不让放，提示「这一页满了」 |
| 标签栏的「＋」 | 开新页，放第 1 格 |
| 自己那格、自己这页的标签、别处 | 不变 |

- 拖动时被拖的窗口变淡，目标格子 / 标签 / 「＋」高亮。动了 5px 才算拖，单击、双击改名照旧。Esc 取消。
- 原来那页被拖空了就去掉，跟着窗口到它去的那页；否则停在当前页。团队页的「是谁的团队页」和拖过的比例都留着。
- **只改格子，窗口不重启**：终端编号不变，之前的输出还在。
- 拖动时把指针锁在标题栏上（`setPointerCapture`），终端收不到鼠标事件，不会拖出一片选中文字。计划里写的是盖一层透明遮罩，作用一样，锁指针更简单。
- **调伪终端尺寸改成等停下来再调**：画面跟着变，伪终端等尺寸 150ms 不变后按最终尺寸调一次。拖分隔线时以前每动一下都调一次，ConPTY 每次整屏重画（1.0.8 查过）。
- 不加新库：拖动用指针事件（`pages/workbench/window-drag.ts`），对调、移动的计算在 `shared/workbench/grid.ts` 的 `moveWindowInLayout`（纯函数）。

### 计划里没做的

- 标题栏按宽度分三档收起（T11.2a 遗留）仍没做。

## 2. 已验证

- 单测：新增 `workbench-grid-move.test.ts`（同页对调、移到空格、落回自己不变；移到别的标签放最小空格、停在当前页、满了拒绝、当前页拖空了去掉并跟过去、团队页属性保留；拖到「＋」开新页、只有自己一个时不变；最大化的拖走后取消最大化；从 data-* 读落点）。
- e2e：新增 `workbench-drag.spec.ts`：两个 PowerShell 窗口，拖到另一个上对调、拖到空格、拖到「＋」开新页、拖到别的标签（原页拖空后去掉）；全程终端编号不变、之前打的字还在回放里、移动后还能接着打字；落盘的布局和界面一致。截了拖动中的图：被拖的变淡，目标格和「＋」高亮。
- （和 1.0.20 一起跑）全套 66 条通过。崩溃 dump 有 7 个：1 个是故意让界面崩的那条；另外 6 个落在设置、档案、习惯、重启、隐藏面板、重载这些和本次改动无关的用例收尾时，栈里都是搜狗输入法（`SogouPY.ime`、`PicFace64.dll`）注入进 Electron 的代码，同一个出错地址，判断是本机输入法的问题，不是我们的代码。

## 3. 验收办法（dev 模式）

先关掉 FF-pane 再用 FF-pane.exe 打开。

| # | 做法 | 应该看到 |
|---|---|---|
| 1 | 按住一个窗口的标题拖到另一个窗口上 | 两个对调；Claude / Codex 窗口不重启、内容还在、不整屏闪 |
| 2 | 拖到空格子 | 移过去，原来那格变成「＋ 新建窗口」 |
| 3 | 拖到别的标签上 | 移到那一页的空格；当前页还在（除非拖空了） |
| 4 | 拖到一个已经 6 个窗口的标签上 | 不动，提示「这一页满了」 |
| 5 | 拖到标签栏右边的「＋」 | 开新页放进去 |
| 6 | 拖到一半按 Esc | 不动 |
| 7 | 单击标题、双击标题改名、点标题栏上的按钮 | 和以前一样，不会误拖 |
| 8 | 拖格子之间的分隔线，看 Claude / Codex 窗口 | 拖的过程中不连续整屏闪，停下或松手后重排一次 |
