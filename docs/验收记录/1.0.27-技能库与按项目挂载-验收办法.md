# 1.0.27（T11.9 第 2–5 步）技能库与按项目挂载：改动与验收办法

**日期：** 2026-11-08
**状态：** 已提交（2026-11-08，版本 1.0.27），尚未验收。旧的生图设置和 `ffpane_generate_image` 还在，1.0.28 再去掉。
**计划：** [技能计划.md](../技能计划.md) §3、§4、§6、§8。

## 1. 改动

- **技能库**（设置 → 技能）：导入、显示、改显示名、适用于、打开目录、删除、搜索。
  - 导入是复制到 `~/.aiworkbench/skills/<原名>/`，信息在 `~/.aiworkbench/skills.json`。不写 `~/.claude`、`~/.codex`，不进项目。
  - 选的目录本身有 `SKILL.md` 就用它；没有就看下一层，正好一个子目录有就用那个（GitHub 下的仓库常是这样），多个就让用户选具体那一个。
  - 拒绝并说清原因：没有 `SKILL.md`、头部缺 name / description、名字不是小写字母数字连字符、目录太大（超过 2000 个文件或 50MB）、选的就是技能库里的目录。
  - 同名已存在：先问要不要替换，列出在用的项目。替换时旧目录里用户填的 `*.env` / `.env*` 配置文件搬过去，不被新版本的模板盖掉；显示名、适用于也保留。内容和上次一样时提示「和上次一样」。
  - 状态：可用 / 当前无法激活（SKILL.md 坏了或目录没了、本机找不到 python 或 node）/ 有限制（只用于 Claude 或 Codex、脚本用 curl / PowerShell 访问 https，Codex 窗口里会失败）。
  - 猜作者（有 `agents/openai.yaml` 就是 Codex 写的，有 `.claude-plugin/` 或 Claude 专有头部字段就是 Claude 写的）只当提示。**适用于默认是通用**，用户可改成只用于 Claude / Codex。
  - 删除时一起从各项目的启用名单里拿掉，确认框里列出这些项目。
- **项目启用**（项目卡片 → 配置）：每个技能一个勾选框，旁边写限制。存 `projects.json` 的 `skills`，只有界面能改。新项目一个都不勾。超过 5 个提示 AI 容易选错，不拦。卡片上显示「技能 N 个」。
- **挂载**（开窗、重启、续接都按当时的勾选重新挂）：
  - Claude（含 DeepSeek）：`~/.aiworkbench/skill-mounts/<窗口>/` 插件目录，`skills/<原名>` 是指向技能库的目录链接，启动加 `--plugin-dir`。窗口里技能叫 `ffpane-skills:<原名>`。
  - Codex、Grok：把「名字 + 说明 + SKILL.md 路径」接在角色说明后面（`developer_instructions` / `--rules`）。真机核对 `-c skills.config` 加不进新路径，见计划 §4.2。
  - 只用于 Claude 的不挂给 Codex / Grok，只用于 Codex 的不挂给 Claude / Grok。
  - 关窗、退出删挂载目录（先拆链接再删）；启动时清掉上次崩溃留下的。技能出错不让开窗失败，这次都不挂，标题栏照实写。
- **窗口标题栏**：「技能 N」，鼠标停上去列出挂了哪些、没挂哪些和原因；有没挂上的标黄。不弹窗。
- 设置页多一组「技能」，放在模型和工具之间。
- 开窗口时就开始盯项目的 `.ffpane/canvas/`。以前只有打开画板或旧生图工具出图后才盯，技能脚本直接存进目录的图要等别人打开画板才进画板，作者还会记错成那个窗口。
- 角色说明 `base.md`：生图优先用启用的技能，没有再用 `ffpane_generate_image`。真窗口里 Codex 读了技能，又照旧说明去调 `ffpane_generate_image`，所以这一句不能等到 1.0.28。工具清单里去掉重复的 `ffpane_generate_image`，说明书仍不超过 2KB。
- 退出时同步删技能挂载目录（will-quit 不等异步收尾，原来的异步删除来不及）。
- 使用说明加「技能：自己导入，按项目勾」一节。

## 3. 验收办法（dev 模式）

改了主进程、界面和启动参数，要重启 FF-pane；已经开着的窗口重开才挂技能。

| # | 做法 | 应该看到 |
|---|---|---|
| 1 | 设置 → 技能 → 导入技能，选 `test-results\skills\codex-image-studio`（仓库根，技能在下一层） | 列出 codex-image-studio，标「Codex 写的」「要 Python」，适用于「通用」，「还没有项目在用」 |
| 2 | 改显示名为「生图」，回车 | 标题变成「生图」，下面灰字还是 codex-image-studio；搜「生图」「codex」都能搜到 |
| 3 | 点「打开目录」，确认里面有 `image_api.env`；再导入一次同一个目录，点替换 | `image_api.env` 里你填的内容还在 |
| 4 | 《海上生存日记》项目卡片 → 配置，勾上「生图」，保存 | 卡片上出现「技能 1 个」 |
| 5 | 在这个项目开一个 Claude 窗口 | 标题栏有「技能 1」；鼠标停上去写「已挂：codex-image-studio」 |
| 6 | 对它说「用技能出一张图，存到 .ffpane/canvas/xxx.png」 | 图出来，画板按钮上的待检查数加一 |
| 7 | 开一个 Codex 窗口，让它用技能把刚才那张改一下 | 新图出来，进画板 |
| 8 | 把技能适用于改成「只用于 Claude」，重开 Codex 窗口 | Codex 窗口标题栏「技能 0」标黄，提示没挂的原因是「只用于 Claude」 |
| 9 | 关掉所有窗口后看 `~/.aiworkbench/skill-mounts` | 是空的；技能库里的 `image_api.env` 还在 |
| 10 | 看 `~/.claude/skills`、`~/.codex/skills`、项目目录 | 没有多出技能文件 |

- biome、check-i18n、typecheck 通过。
- e2e 全套 68 条通过（含新增「技能库导入、改名、替换保留配置，项目勾上后 Claude 窗口挂上插件目录」：假 Claude 活着时列出插件目录里的技能，就是 `e2e-probe-skill`）。改说明书后再跑 workbench-cli、设置分组、项目配置 14 条，通过。
- 真机（2026-11-08，Claude Code 2.1.302、codex-cli 0.166.0，Tony 的中转站 `127.0.0.1:18317`、`gpt-image-2.5`）：
  - 只换命令行、不开 FF-pane：Claude `-p --plugin-dir` 出新图 47 秒；Codex `exec -s workspace-write` + 技能清单，沙盒里用改图模式改这张图 68 秒。两边输出里都没有密钥。
  - **用打包出来的 FF-pane 开真窗口**（只隔离 FF-pane 的数据目录，CLI 用本机登录）：全部权限的 Claude 窗口按开场白用技能出图 45 秒；Codex 窗口用技能改这张图 175 秒，没再去调旧工具。两张图都由目录监听收进画板、记待检查（画板按钮「待检查 2」），标题栏两个窗口都是「技能 1」。关掉 FF-pane 后挂载目录是空的。
  - 第一次真窗口跑时发现上面三个问题（Codex 去调旧工具并报「MCP tool call requires approval, but approval policy is never」、图要等别人开画板才进来、退出没删挂载目录），改完重跑通过。
- 已知：
  - 中转站不照 `size` 出图（要 1024×1024，出来 1254×1254 或 1672×941）。
  - Codex 全部权限窗口调 `ffpane_generate_image` 会被拦（上面那句报错），1.0.25 改成 workspace-write + 不审批以后就这样。1.0.28 去掉这个工具。
  - Claude 会在 `~/.claude.json` 记一笔技能和插件用量（`skillUsage`、`pluginUsage`），它对所有技能都这样，不去动。
