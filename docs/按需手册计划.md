# 按需手册计划

> 状态：Tony 2026-10-24 要求写计划。未开工，未改版本。总览见 [`改进计划总览-2026-10.md`](./改进计划总览-2026-10.md)。
>
> 「按需手册」就是 Claude、Codex 的 skill。内部叫手册，提醒大家：它只是给 AI 读的说明，模型可能不读、读了也可能不照做，不是约束。

## 1. 为什么做，做到什么程度

现在每个窗口常驻「base + 角色说明书」，合计约 4KB。画板改图、写请示、记忆总结这些低频的长流程也塞在里面。以后功能越多，常驻的越长；Codex 的说明书走命令行 `-c developer_instructions=...` 传进去，覆盖副本上限 8KB（`MAX_ROLE_MANUAL_OVERRIDE_CHARS`）。

按需手册平时只有名字和一句描述常驻，用到才读全文。

**只放这一类内容：低频、篇幅长、需要判断、漏了也不致命。**

| 内容 | 放哪 |
|---|---|
| 身份和硬规则（并发范围、不还原、不提权、不开子 agent） | 常驻说明书，并用代码拦住 |
| 高频的短规则（汇报格式等） | 常驻说明书，能校验的写进工具 |
| 步骤固定、重复的事 | 代码或 MCP 工具 |
| 低频的长流程 | **按需手册** |

为什么不全做成手册：

- 读不读由模型决定，便宜模型、低思考强度更容易漏；
- 压缩后约束力变弱：Claude Code 2.1.302 会把用过的 skill 重新附上，但标注「之前调用过，仅供参考」，而且有长度预算；系统提示压缩时不会动；
- Claude、Codex、Grok 加载方式不同，Grok 没有原生 skill；
- 和用户自己的 skill 互相干扰（本机 `~/.codex/skills` 已有 `grill-me` 等）。

## 2. 第一批手册

| 手册 | 来源 | 挂给谁 |
|---|---|---|
| `ffpane-canvas-edit` 画板改图 | `base.md` 里画板那段，展开成完整步骤 | 所有角色 |
| `ffpane-decision-brief` 写请示 | `manager.md` 第 1 条，展开成模板 | 管理者 |
| `ffpane-memory-summary` 记忆总结 | `worker.md` 最后一段 | 执行 |
| `ffpane-plan-review` 计划评审 | [计划评审计划](./计划评审计划.md) §2、§3 的模板和规则 | 检查、规划、管理者 |

挪走以后，常驻说明书里只留一句「做 X 时先读手册 ffpane-X」。

## 3. 怎么交给 CLI

**不写用户目录。** 手册放在应用自己的数据目录，每个窗口启动时挂载（`生图计划.md` §2 已定这个方向）。cc-pane 0.12.5 前把 skill 写进 `~/.claude`、`~/.codex`，按前缀删除时误删过用户自己的 skill，后来专门写了按内容哈希回收的迁移。

- 源文件：`apps/desktop/resources/workbench-skills/<名字>/SKILL.md`，和 `workbench-roles/` 并列，随包打包。
- 每次启动把要挂的手册生成到 `<应用数据目录>/skills/<窗口编号>/`：
  - Claude：生成成插件目录（`.claude-plugin/plugin.json` + `skills/<名字>/SKILL.md`），启动加 `--plugin-dir <目录>`。2.1.302 已确认有这个参数。
  - Codex：`-c skills.config=[{path="<目录>/skills/<名字>",enabled=true}]`。0.162.0 程序里有 `skills.config`，具体写法要真机核对。
  - Grok：没有原生 skill，把描述列表拼进 `--rules`，正文按路径让它自己读。
- **按角色挂**：每个角色只挂自己的那几个，不全量挂。
- 窗口关闭时删掉它的临时目录（照 `RolePromptTempRegistry` 的做法）。
- 名字一律 `ffpane-` 开头；Claude 插件机制本身也会带插件前缀。

## 4. 版本与覆盖

- 每个手册在 frontmatter 带版本号。
- 用户可以在设置页改覆盖副本（复用角色说明书的编辑页、覆盖目录和「恢复默认」）。
- 内置版本升级而用户覆盖副本更旧时，设置页标出「你的副本落后于内置版本」。
- 窗口近况里记一笔「本窗口挂了哪些手册、什么版本」，排查时不用猜。

## 5. 顺带：给开发 FF-pane 用的手册

和上面不是一回事。开发 FF-pane 本身时重复的步骤（如「新增一个 MCP 工具要改哪几个文件、补哪些测试」「新增一个 CLI 适配器的清单」），可以写成本仓库 `.claude/skills/` 下的手册，给帮忙写代码的 AI 用。不进安装包，没有上面那些风险，随时可以加。

## 6. 验收

1. 真机 Claude 2.1.302：`--plugin-dir` 挂载后手册出现在可用列表；第一次加载会不会弹信任提示；`~/.claude` 没有任何变化。
2. 真机 codex-cli 0.162.0：`skills.config` 写法生效，手册可见；`~/.codex` 没有变化。
3. 按角色挂载：执行看不到管理者的手册。
4. 挪走后的常驻说明书变短；画板改图、写请示、记忆总结、计划评审各实测一次，行为和挪走前一致。
5. 关窗后临时目录被删；dev 和打包版的资源路径都对。

## 7. 风险

- 模型没读手册就动手：常驻说明书里点名「做 X 先读 ffpane-X」；会出事的规则不放手册。
- Codex `skills.config` 和全局配置合并时留下旧字段（cc-pane docs/18 有过类似故障）：只用会话级 `-c`，并在验收里核对 `~/.codex` 不变。
- 手册多了以后常驻的描述列表本身变成噪音：每个角色控制在五个以内。
