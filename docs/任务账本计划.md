# 任务账本计划（T11.24 草案）

状态：只有设计，没动代码。Tony 2026-11-28 提出。

## 1. 要解决什么

管理者会忘事。原因：任务只存在它自己的对话里，压缩、重启、接任之后就丢；现有「待处理」页每个窗口只留一行，管理者一回话那行就划掉，记的是别人的汇报，不是它还欠的活。

要做一本由 AI 填写、AI 检查、AI 判定、平台保管的任务账本。管理者只盯未完成的。

ccpane 对照（2026-11-28 读了 GitHub wuxiran/cc-pane 的 README 和 docs/guide，没读到源码，细节以文档为准）：

- 它的 Todo：有范围（全局、工作空间、项目）、优先级（高、中、低）、状态（待办、进行中、完成）、子任务、标签、到期日、提醒、循环重复，能拖拽排序、按标签、状态、优先级分组。主要是界面里给人用，AI 也能通过 MCP 增删查。存在全局 SQLite `~/.cc-panes/data.db`。
- 它的指挥和工人（leader、worker）：工人干完自动回报；指挥忙时漏了回报，事后会再核对一遍所有工人的最终状态；工人长时间没动静，由 AI 问要不要重发。Todo 和工人之间没有绑定。
- 它没有的：归档、检查和判定环节、记录汇报是谁写的。备份只是让用户整个复制数据目录。
- 值得学的：「自动回报 + 事后核对」双保险。我们对应的做法是：report 自动记账，再加上每轮提醒和交接清单当作事后核对。
- 不学的：给人看的那些字段（标签、到期日、循环、我的一天）。我们的账本用户看不到、也不加，只给管理者后台用。

## 2. 存哪里

按项目存，不按管理者存，这样接任之后账本还在。

- `.ffpane/tasks/active.json`：只放未完成的任务，管理者读的就是它。主进程串行写，原子写，每次写之前把上一版留成 `active.json.bak`。
- `.ffpane/tasks/archive/YYYY-MM.jsonl`：完成或取消的任务整条移到这里，只追加不修改，作为长期备份。不注入给 AI，要查才读。
- `.ffpane/tasks/账本.md`：从 active 自动生成的人读视图，用户随时能打开，不手改。

## 3. 一条任务的字段

- id、parentId（子任务才有）
- title 标题、detail 内容、acceptance 验收标准（一两句）
- status 状态、createdAt、updatedAt
- createdBy：窗口 id + 标题 + 角色，或 user
- assignee 执行窗口、brief 派活说明的路径
- progress：执行情况，一行最新的
- reportedBy：汇报是谁写的
- reviewedBy、verdict（通过或返工 + 理由）
- events：时间线，每次状态变化追加一行（时间、谁、从什么到什么、一句话）

## 4. 状态

主线：todo 待派 → doing 执行中 → submitted 已汇报待检查 → done 完成。

旁支：blocked 卡住；rework 返工（回到 doing）；failed 失败；cancelled 取消。

未完成 = 除 done、cancelled 之外的全部。failed 也算未完成，管理者必须处理。

## 5. 谁填、谁检查、谁判定

- 建任务：只有管理者。用户看不到账本，也不能在界面里加，用户临时提的事由管理者在后台转成任务（createdBy 记管理者，来源写「用户临时提」）。
- 哪些要建账：要派给别的窗口做、要跨几轮才做完、要检查验收的，才建。查进度、问一句、读一个文件这类一两步能答完的小事不建账，管理者自己判断；说明书里写清这条界线和几个例子，拿不准就建。
- 填执行情况：执行者。平台从 `ffpane_report` 自动改状态（report 带 taskId）：working → doing，blocked → blocked，done → submitted。执行者不能把任务标成 done。
- 检查：检查窗口对照验收标准写 verdict。检查者不能是执行者本人。
- 判定：管理者看 verdict 后标 done；verdict 是返工就回 rework 并写明原因。没有检查窗口的小任务，管理者可以直接标 done，但必须写理由，账本记「免检」。
- 监管者只读。

## 6. 拆子任务

用户临时加的事和未完成任务重合时，不新开一个大任务，也不整个丢给同一个执行者：

- 新建任务前，工具先返回 active 里同主题的未完成任务（按标题和内容关键词匹配），由管理者确认。重合就挂到那条任务下当子任务，parentId 指向它。
- 一条大任务拆成几条子任务，每条一个明确的产出和验收标准，分给不同执行者并行做。大任务本身不派人，状态由子任务汇总：全部 done 才能进 submitted，有一条 blocked 它就显示 blocked。
- 只拆一层，不嵌套，免得账本变成树。
- 子任务有先后依赖时写 after（前一条的 id），前一条没 done 就不派后一条。
- 用户改了大任务的要求：管理者在原任务下追加子任务，同时更新原任务的验收标准，并在 events 里记一行。

## 7. 管理者怎么盯

- 管理者只读 active.json 里未完成的，done 和 cancelled 已经移走，不占它的注意力。
- 工具列表默认按这个顺序排：failed、blocked、submitted 待判定、rework、doing、todo。最该处理的排最前。
- 不设时间阈值，按事件催办。三种情况平台本来就知道：①执行窗口回到空闲，但没有汇报；②执行窗口被关或崩溃，任务还没完成，任务退回 todo；③汇报已到（submitted），过了一轮还没人判定。碰到这三种，就用现有的 nudge 机制催一次，并在 events 记一行。updatedAt 只用来显示和排序，不用来判断卡没卡住。
- 账本由平台保管，管理者说明书里写明：任务以账本为准，不要凭记忆。

## 8. 备份

三层：

1. 每次写 active.json 之前，把上一版存进 `.ffpane/tasks/backup/`，只留最近 20 份，坏文件时能回滚。
2. 完成或取消的任务整条追加到 `archive/YYYY-MM.jsonl`，只追加不修改不删除，这就是长期备份。
3. 应用启动时校验 active.json：解析失败就用最近一份备份恢复，并在账本.md 顶部写一行说明。

archive 不注入给 AI，要查才读（比如用户问上个月做过什么）。

## 9. 工具和自动记账

新增工具 `ffpane_tasks`，用 action 区分：list、add、split、assign、verdict、close、cancel。权限：管理者全部可用；执行者只能 list 自己的和 report；检查者能 list 和 verdict；监管者只读。

自动记账，管理者不用记着去写：

- `ffpane_open_window` 多一个 taskId 参数：派活时把任务标成 doing、记下 assignee 和 brief。没带 taskId 且角色是执行或检查时，平台提示管理者先建任务。
- `ffpane_report` 多一个 taskId 参数：working 改 doing 并刷新 progress，blocked 改 blocked，done 改 submitted，failed 改 failed；reportedBy 记发汇报的窗口。
- 窗口被关掉但任务没完成：任务退回 todo，events 记一行，进管理者的提醒。

## 10. 提醒

- 每次一轮开始（Claude 的 UserPromptSubmit、Cursor 的 beforeSubmitPrompt、agy 的 PreInvocation 这些现有钩子），给管理者附一行：未完成 N 条，其中 M 条要你处理，最先看哪条。
- 重启、新对话、接任三种交接消息里，直接带未完成清单（只列标题、状态、负责人，最多 20 行，超出的指向账本.md），不再只让它去读近况文件。
- 压缩之后：Claude 的 SessionStart 在压缩后是否再触发要实测；不触发就靠上一条每轮附一行兜底。
- 管理者想结束一轮、账本里还有没人在做的未完成任务时，只提醒一次，不强拦，避免死循环。

## 11. 开发顺序（Tony 说开始之后）

1. 先去读真实的管理者对话记录，确认它到底是压缩后、长等待后还是接任后忘事，调整下面的优先级。
2. 共享类型和账本存储：读写、串行、原子写、备份、归档、启动校验，带单测。
3. `ffpane_tasks` 工具，权限按 §9。
4. `open_window` 和 `report` 自动记账。
5. 提醒和交接带清单；管理者说明书加一段。
6. 账本.md 人读视图只留给开发和排查时打开看；界面里不做任务面板，用户看不到账本，也不能加任务。
7. 真机验收：派活、汇报、检查、返工、拆子任务、重启后接回、接任后账本还在。

**真实的忘事证据**（读 `项目2--海上生存` 那个管理者 Claude 16 的对话，7118 行、5 次压缩）：

- 压缩时待办没有整体丢，但每次都是模型自己重写摘要，越压越含糊：「查船跑约 55 秒触发沉船链的原因」被压成「船约 55s 冻住」，「查原因」这个动作没了。

**接线**

- `ffpane_open_window` 和 `ffpane_report` 各加一个可选 `taskId`：派活带就把任务标执行中、记负责窗口和 brief；汇报带就按状态改账本（progress → 执行中、blocked → 卡住、done → 待检查、failed → 失败）。记账失败只附一句说明，不影响开窗和汇报。
