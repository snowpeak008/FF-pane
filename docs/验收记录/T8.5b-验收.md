## 2. 抽查发现

**未发现影响结论的缺陷，红线全部未破。** 以下如实登记：

1. **（注释-实现轻微不一致，不影响结论）`pickAcpPermissionOption` 的「once 缺席退回同前缀，此时留档由调用方负责」承诺未落实。** `acp-turn.ts:265` 注释说退回 always 类选项时留档由调用方负责，但调用处（:424-435）只在 pick 为 undefined 时留档，命中 always 退路时**静默使用**。真机选项面恒含 once（fixture 两帧实证），该退路实际不可达，风险为零；建议将来顺手补一条 raw 留档或删注释半句。
2. **（fixture 边界观察，不影响结论）录制机环境元数据泄进 fixture。** 三份 real-acp-*.jsonl 的 `available_commands_update` 带出录制机用户自装的 claude skill 条目（`C:\Users\USER\.claude\skills\grill-with-docs\SKILL.md` 与其描述文案）。路径已按口径脱敏、无凭据无账号信息，且「stdout 原样逐行留档、未做删行」正是 README-acp 声明的录制纪律——如实保留比删行可信。仅登记形态供将来重录时知悉。
3. **（覆盖缺口观察，不影响结论）降级链单测未覆盖「initialize 静默超时」与「spawn 直接失败」两个入口形态。** 假 Agent 脚本定义了 `"silent"` 形态但无用例消费；stdin null 恒抛写口的降级路径亦无直接用例。两者与已覆盖形态走同一个 catch → degrade 通道（读码核实），且探针①证实该通道被 3 条用例钉死，风险低。
4. **（回归异常登记，复跑排除）全量单测第 1 跑异常：98 文件 / 2010 条 + 1 error，exit 1。** 少的恰是一个文件 3 条（形态与某测试文件加载失败一致，错误详情未能截获——输出管道截断）；随后连续 5 跑全部 99 文件 / 2013 条全绿（含 3 次正式计数跑），无法复现。不在两条已知 flake 名单内，如实登记待观察；不影响「独立 3 连跑全绿」判据的达成（第 2~6 跑取其三）。
5. **（正面观察）「降级前零事件」是结构性保证而非纪律约定。** 事件全进 sink 队列、门面先 await outcome 才消费流（B/C 项）——握手期任何诊断/garbage 行都不可能漏出去，比「小心别 push」的实现强一档。
6. **（正面观察）close → kill 的收尾顺序在两条路径一致。** degrade（:468-469）与正常收尾（:532-533）都是先 close 连接再 kill 进程——T8.5a 验收 §2-3 的接线提醒不仅在降级路径落实，正常路径同款。
7. **（口径观察，不影响结论）gracefulCancel=yes 的真机证据载体是 fixture 而非 live 判据。** live-grok-acp.mjs 九判据不含取消场景（脚本不 cancel）；优雅取消的 CLI 全真证据在 real-acp-cancel.jsonl（MidTurnAbort 实录）+ 回放单测。证据链成立，登记载体口径备查。
