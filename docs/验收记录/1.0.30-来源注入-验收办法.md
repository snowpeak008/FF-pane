# 1.0.30 来源注入 —— 验收办法（T11.11）

> 计划：[`docs/来源注入修复计划.md`](../来源注入修复计划.md)。开发 2026-11-12，尚未验收。

## 前提

- 重启 FF-pane（改动在主进程和 hook 脚本，重启后新开的窗口才生效；已开着的窗口不变）。
- `~/.claude/settings.json` 保持现状（里面有本机中转的 `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN`）。
- 设置里有一个和本机不同的 Claude 中转来源（地址、密钥都填好）。

## 步骤

1. **中转生效**：测试项目的配置里 Claude 选这个中转来源和一个模型，新开 Claude 窗口问一句。
   - 中转那边的后台能看到这次请求（或换一个只有这个来源才认的模型名，能正常回答）。
   - 窗口开头显示的模型是配置里选的。
2. **子 agent / 别名**：在窗口里 `/model opus`（或让它开一个子 agent），请求仍发到这个来源，模型名是配置里选的那个。
3. **密钥不落盘**：在 `%TEMP%\ffpane-wb-hooks-*\claude-settings.json` 里能看到 `env` 和 `apiKeyHelper`，`ANTHROPIC_AUTH_TOKEN` 是空串，**找不到密钥明文**。关窗后这个目录被删。
4. **本机登录不变**：配置改成 Claude 本机登录，新开窗口，行为和以前一样（走本机 settings 里的中转）。
5. **DeepSeek**：开 DeepSeek 窗口问一句，正常回答，请求去 DeepSeek（不是本机中转）。
6. **填错会报错**：故意把来源密钥改错，新开窗口应报认证错误（以前会被本机配置掩盖，看上去能用）。
