## 2. 实测

- **Claude 2.1.302**：开着 `--dangerously-skip-permissions` 时，PreToolUse hook 返回 `permissionDecision: "deny"` 仍然生效。让它用 Write 写项目外，被拦下，文件没写出去。
- **Claude 的命令行**：hook 看得到命令，但看不出脚本里再去写哪里。真正的系统级隔离要用 Claude 自带的 Windows 沙盒（`/sandbox install`，要管理员授权，建沙盒用户和网络过滤），可能影响 Unity / Blender，这次不做。
- **Codex 0.166**：`-s workspace-write` 在 Windows 上是系统级拦截。实测往项目外写返回「拒绝访问」，项目里照常写，`writable_roots` 里的目录能写。**沙盒里的命令连不上网**：`network_access=true` 和 `false` 实测一样（沙盒外正常），要等 Codex 还在开发的网络代理功能。

## 4. 代码

- 新纯函数模块 `mcp/write-guard.ts`：路径是否在允许的目录里（大小写不敏感，认 `C:\`、`C:/`、`/c/`、`~`）；从命令里找写的目标；给出拒绝原因。
- `mcp/workbench-hook.ts`：PreToolUse 只做这道检查，不上报主进程、不连管道。
- `hook-launch.ts`：Claude 的 `--settings` 加 PreToolUse（Write、Edit、MultiEdit、NotebookEdit、Bash、PowerShell）。
- `launch-cli.ts`：算出允许的目录，经环境变量 `FF_PANE_WRITE_ROOTS` 交给 hook；Codex 把「项目外可写目录」交给 `sandbox_workspace_write.writable_roots`。
- `packages/core` 权限表：Codex 的 YOLO 改成 `workspace-write`、`never`、`network_access=true`。
- `packages/storage` 注册表加 `outsideWriteDirs`；IPC `projects:set-outside-write-dirs`；项目卡片「配置」对话框里加一栏，一行一个目录。

## 6. 2026-11-08 更正与补充

- **「沙盒里的命令连不上网」不准。** 重测（真 Codex 会话、同样的启动参数）：Python 访问 `https://` 和 `http://127.0.0.1` 都通；`curl.exe`、PowerShell `Invoke-WebRequest` 访问 `https://` 失败，报 `SEC_E_NO_CREDENTIALS`。拦住的是 Windows 自带的 HTTPS（沙盒进程拿不到当前用户的凭据），不是网络。`network_access=false` 时 Python 照样能连。详见 [技能计划](./技能计划.md) §2.3。写项目外照样「拒绝访问」，这一项结论不变。
- **还有一个口子没堵：** `~/.codex/rules/default.rules` 里以前点过「总是允许」留下的规则（本机有 `git push`、`npm.cmd install`、`python -m pip install --user`、几条带 `Remove-Item` 的 PowerShell 长命令等）。照官方说明，`decision="allow"` 的命令「不提示，直接在沙盒外跑」，FF-pane 的 Codex 窗口也会读这些规则，所以这些命令不受「不写项目外」限制。没有实测，没改用户的文件。Tony 2026-11-08 定：不需要处理，只留这条记录（技能计划 §7 D8）。

## 7. T11.8b 实现记录（2026-11-28，待真机验收）

照 §3 第 5 条做，三步都在：

1. **旧记忆转成项目记忆候选。** `apps/desktop/src/main/workbench/claude-memory-migrate.ts`：读 `~/.claude/projects/<cwd 转义>/memory/*.md`（跳过 `MEMORY.md` 索引），把 frontmatter 的 `description` 当标题、`metadata.type` 映射成项目记忆类别（user/feedback → rule、project → decision、reference → lesson），一律写成 `candidate`、`confidence: low`、`source: agent_proposed`，id 为 `claude-<slug>`。**原来的文件不删。**
2. **接入点。** `data.ts` 的 `memory:list`：项目记忆为空时，先把旧记忆导入成候选再返回。搬过以后项目记忆非空，不会再生成（按 id 跳过已有的），单条写失败只跳过那一条。
3. **关掉 Claude 自己的记忆。** `launch-cli.ts` 的 Claude 分支设 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`；`write-roots.ts` 去掉 `~/.claude/projects/<cwd>/memory` 这两条写入例外。

**没做的**：§3 第 5 条里「过期的、和现在规矩冲突的（如「一任务一子代理」）列出来」没有单列——它需要判断哪条过期，不是机械规则，交给用户在记忆页逐条看更稳。旧记忆一共 19 个项目目录、数量不小，先让用户自己过一遍。

**注意**：导入只看每个 Claude 项目目录自己的记忆，不会把 A 项目的记忆倒进 B 项目；`claudeProjectDataDir` 按项目根路径算目录名，和 Claude 自己的规则一致。

**测试**：`claude-memory-migrate.test.ts` 10 条（解析、类别映射、跳过空/重复/索引文件、目录不存在）；`write-roots.test.ts` 加了「记忆目录不再放行」一条，改掉原来断言「能写」的那条。

**真机验收要看的**：打开一个以前用 Claude 写过的项目，记忆页里出现候选；点通过后进入生效记忆；`~/.claude/projects/…/memory` 里的文件还在；FF-pane 的 Claude 窗口不再往那个目录写。
