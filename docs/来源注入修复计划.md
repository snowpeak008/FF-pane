# 来源注入修复计划（T11.11）

> 状态：Tony 2026-11-12 报：项目配置里选的来源（Provider）在 Claude 窗口里不起作用，实际用的是本机 Claude 的配置；CC-Panes 没有这个问题。Tony 说开工，选择交给我定。已开发，尚未验收。总览见 [`改进计划总览-2026-10.md`](./改进计划总览-2026-10.md)。

## 1. 原因

FF-pane 只把来源的地址、密钥、模型放进 Claude 进程的环境变量（`launch-cli.ts` → `resolveRuntimeEnv` → `buildAgentEnv`）。Claude 启动后读 `~/.claude/settings.json` 和项目 `.claude/settings*.json` 里的 `env`，**这些会盖掉进程环境**。Tony 的 `~/.claude/settings.json` 里正好有 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 和 `ANTHROPIC_DEFAULT_*_MODEL`，所以中转来源的地址和密钥全被换成了本机那一套，只有 `ANTHROPIC_MODEL` 留下（本机没设）。DeepSeek 窗口也是 Claude，同样受影响。

`buildAgentEnv` 剥掉主进程里的 `ANTHROPIC_*` 只管得到进程环境，管不到 settings 文件。

Codex 不受影响：填了地址就用 `-c model_provider=…` 覆盖 `config.toml`，和 CC-Panes 一样。

## 2. 实测（Claude Code 2.1.302，本机假服务器看请求落到哪）

| 做法 | 结果 |
|---|---|
| 只放进程环境（旧做法） | 假服务器收不到；请求去了用户 settings 里的中转，带的是那里的密钥 |
| `--settings <文件>` 里写 `env`（CC-Panes 做法） | 地址、密钥、模型都是给的值 |
| `--setting-sources project,local` + 进程环境 | 生效，但整份用户 settings 都不读，项目 settings 里的 env 仍会盖过 |
| `--settings` 的 env 里写 `${变量}` | 不展开，原样当密钥发出去 |
| `--settings` 里 `apiKeyHelper` 读进程环境，`ANTHROPIC_AUTH_TOKEN` 留着 | 用户 settings 的旧密钥压过 apiKeyHelper |
| `apiKeyHelper` + 把 `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` 清空 | 用 apiKeyHelper 的密钥；交互窗口里不弹确认 |
| apiKeyHelper 用 `$变量`（不经 node） | Windows 上不展开 |
| 模型变量设成空串 | 当没设，回到 Claude 默认 |

参考：CC-Panes `cc-cli-adapters/src/claude.rs` `generate_provider_settings`（密钥写进文件）；Tom（`snowpeak008/Tom_doc`）中转来源自己发 HTTP，不经命令行，命令行只用于订阅登录，不可直接借用。

## 3. 做法

1. Claude / DeepSeek 窗口走中转来源时，本窗口原有的 `--settings` 临时文件（放 hooks 的那份）里加：
   - `env`：先把 `ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、`CLAUDE_CODE_USE_BEDROCK/VERTEX/FOUNDRY`、`AWS_REGION`、`AWS_PROFILE`、`CLOUD_ML_REGION`、`ANTHROPIC_VERTEX_PROJECT_ID` 清空；用户和项目 settings 里出现的其他 `ANTHROPIC_*`（如 `ANTHROPIC_CUSTOM_MODEL_OPTION`）也清空；再写来源的地址。官方来源没填地址时写 `https://api.anthropic.com`，免得落到用户 settings 的中转。
   - 模型：`ANTHROPIC_MODEL`、`ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL`、`ANTHROPIC_SMALL_FAST_MODEL`、`CLAUDE_CODE_SUBAGENT_MODEL` 都设成配置里选的模型（没选就清空，用 Claude 默认）。
   - `apiKeyHelper`：`"<node>" "<workbench-hook.mjs>" ApiKey`，脚本只打印本窗口进程环境 `FF_PANE_CLAUDE_KEY`。没有 node 时用系统 PowerShell 读这个变量。**密钥不落盘**，启动前照旧扫描文件和命令行里不得含密钥。
2. 密钥仍放进程环境（原有的 `ANTHROPIC_AUTH_TOKEN` 等不变），另加 `FF_PANE_CLAUDE_KEY`。
3. 本机登录不变：照旧用用户自己的 Claude 配置（包括用户 settings 里的中转）。
4. 用户 settings 里非路由的设置（思考强度、`modelSettings`、免确认提示等）照常生效。
5. Codex、Grok、Cursor 不动。

代码：`apps/desktop/src/main/workbench/claude-provider-settings.ts`（纯函数 + 读 settings 键名）、`hook-launch.ts`（同一份 settings 写 env / apiKeyHelper）、`launch-cli.ts`（中转时组装）、`src/mcp/workbench-hook.ts`（`ApiKey` 模式）。
