# 1.0.20（T11.1）子 agent 管控：改动与验收办法

**日期：** 2026-10-27
**状态：** 已提交（2026-10-27，版本 1.0.20），尚未验收。
**计划：** [子agent管控计划.md](../子agent管控计划.md)。

起因：《海上生存日记》里管理者两天开了 62 个后台子 agent，改了 212 个文件，绕过了 brief、锁和监管者。Tony 2026-10-24 定：除普通窗口外一律不留子 agent，小调研改由看得见的调研小窗来做。

## 1. 改动

### 启动参数（`main/workbench/role-tool-policy.ts`，纯函数）

| 角色 | Claude | Codex |
|---|---|---|
| 管理者、监管者、规划、检查、执行、调研 | `--disallowedTools Agent,Task` | `-c features.multi_agent=false -c features.multi_agent_v2=false` |
| 普通（用户自己开的） | 不限 | 不限 |

- Claude 的 `--disallowedTools` 放在参数最前面，新开、续接都带。权限档本来就有的 `--disallowedTools Bash PowerShell`（只读档）另起一个，两个都生效（见 §2）。
- Codex 走现有的 `-c` 覆盖，不改 `~/.codex/config.toml`。
- Grok 没有对应参数，只靠说明书（计划 §5 已知缺口）。

### 运行中改角色（`set-role.ts`）

- 新旧角色的限制不一样（普通 ↔ 其他角色）时，Claude / Codex 窗口重启生效，走改模型那条重启路线：能续接就续接，没聊过就冷重启，在忙就排队、空闲后自动重启。界面提示「重启后生效」。
- 和改模型不同，**不弹确认框**，管理者、yolo 窗口也不弹：改角色本身就是决定；而且常见的是 AI 自己调 `ffpane_set_role` 把普通窗口改成管理者，这时弹框就是 AI 的动作打断你。只在空闲时重启；状态不明的当作在忙，不会在一轮中间冷重启；Codex 不用 `/model` 代替重启（那样启动参数不变）。
- 限制没变（比如执行改成管理者）照旧往终端投一行说明，不重启。
- 现在没法重启的（没在运行等）照旧投说明，下次启动生效。

### 调研小窗

- 新角色「调研」（researcher）：只读，只答一个问题，结论写成 brief、附 `文件:行号` 或命令输出，`ffpane_report` done 后自关。说明书 `researcher.md`。
- 新工具 `ffpane_request_research`：执行、检查、规划要查资料时用。请求发给自己在线的监管者；没有或不在线就发给最上面的管理者。消息里写明怎么开调研小窗（role researcher、read-only、思考强度 low、researchFor 填提问的窗口）。
- 监管者也能用 `ffpane_open_window`，但代码里拦：只能开调研、只能 read-only、同时最多 2 个。`researchFor` 只能配调研角色，而且必须是同一项目里的窗口。
- 调研小窗交 done：结果照常交给开它的窗口，同时抄送提问的窗口（只传路径）。
- 说明书：`base.md`、`worker.md` 写明没有子 agent、要查资料用 `ffpane_request_research`；`manager.md` 加「只读的小调研开调研小窗」；`supervisor.md` 加「收到调研请求就开，结果回来先看证据齐不齐」。都在 2KB 以内。

### 计划里没做的

- 计划 §3.5 说调研「默认用便宜模型」：没有在代码里定默认模型（模型名随 CLI 和账号变），只在请求消息里写思考强度 low；用哪个模型由开窗的人定。
- 计划 §4 第 6 条要求 e2e 覆盖整条调研链路：用 MCP 工具层的单测覆盖了（请求 → 监管者收到 → 开调研小窗 → 交回提问的窗口并抄送），没有起真 CLI 的 e2e。

## 2. 已验证

- **真机 Claude 2.1.302**（只读启动、看初始化时的工具列表就退出，不花 token）：带 `--disallowedTools Agent,Task` 后工具里没有 Task；和权限档的 `--disallowedTools Bash PowerShell` 同时出现时，Task、Bash、PowerShell 都没有（22 个工具 → 20 个），两个参数是叠加的，不用合并；`--dangerously-skip-permissions` 下同样生效。
- **真机 codex-cli 0.162.0**：带两个 `-c` 后 `features.multi_agent` / `multi_agent_v2` 都是关，新开和 `resume` 都带上；`~/.codex/config.toml` 前后 md5 相同（`7fccc8a918a7f44c00550b98b642aa4c`）。
- 单测：新增 `role-tool-policy.test.ts`（七个角色 × 限制；改角色时什么时候要重启；参数位置、开场白还在最后、续接也带；Codex 新开和续接都带）、`set-role-subagent-restart.test.ts`（普通 ↔ 管理者重启、在忙排队、限制没变不重启、没法重启时投说明、没运行或 Grok 不重启）；`workbench-mcp.test.ts` 加调研请求（发给在线监管者、监管者不在线转管理者、管理者 / 监管者不能发）和监管者开窗限制（开执行、可写、第 3 个调研都被拒，原因写清；结果抄送提问的窗口）；说明书测试改成七份并检查新增的句子。apps/desktop 单测 990 条通过，typecheck、lint、i18n 通过。顺手修了 `workbench-config-draft` 里那条负载下偶发失败的用例（等界面和回包文件都出现再断言）。
- e2e：`workbench-cli.spec.ts` 看主进程拼出的 argv：执行窗口开头是 `--disallowedTools Agent,Task`；普通窗口没有 `Agent,Task`；普通 Codex 窗口没有 `features.multi_agent`。`model-effort.spec.ts` 新增一条：普通窗口里的 AI 自己改成管理者、这一轮结束后，窗口带着 `--disallowedTools Agent,Task` 用 `--resume` 续接，界面上没有弹框。
- 第一次跑全套 e2e 时「隐藏面板」那条失败：AI 自己改成管理者后，那时还走改模型的确认，弹出了确认框挡住界面——就是上面说的打断，于是改成不弹框。改完后 `workbench-mcp.spec.ts` 里「管理者开窗口……」那条又失败：假 CLI 改成管理者、模拟一轮结束，平台按设计续接重启了它，测试读的旧终端没了。这个文件里的 8 条测的是管理者开窗、汇报这些事，不是改角色，改成在新建窗口时直接选「管理者」（「重启后子窗口仍被封顶」那条除外：它的假 CLI 靠「已经是管理者」认出是第二次启动，保持从普通窗口开始）。
- （加上 1.0.21 一起跑）全套 66 条通过。崩溃 dump 有 7 个：1 个是故意让界面崩的那条；另外 6 个落在设置、档案、习惯、重启、隐藏面板、重载这些和本次改动无关的用例收尾时，栈里都是搜狗输入法（`SogouPY.ime`、`PicFace64.dll`）注入进 Electron 的代码，同一个出错地址，判断是本机输入法的问题，不是我们的代码。

## 3. 验收办法（dev 模式）

先关掉 FF-pane 再用 FF-pane.exe 打开。

| # | 做法 | 应该看到 |
|---|---|---|
| 1 | 让管理者（Claude）开一个子 agent（比如「用 Task 工具查一下……」） | 它说没有这个工具，改开窗口或调研小窗 |
| 2 | 自己开一个普通 Claude 窗口，让它开子 agent | 照常能开 |
| 3 | 把那个普通窗口改成执行 | 提示「重启后生效」，窗口续接重启；再让它开子 agent，开不了 |
| 4 | 执行在忙时改角色 | 提示排队，空闲后才重启 |
| 4b | 普通 Claude 窗口里跟它说「你是管理者」 | 它调 `ffpane_set_role`；这一轮结束后窗口自己续接重启，不弹确认框，对话还在 |
| 5 | 让执行查一处代码 | 它用 `ffpane_request_research`；监管者开一个「调研」小窗（只读），查完自关；执行和监管者都收到结论路径 |
| 6 | 关掉监管者后再让执行要调研 | 请求到管理者那里 |
| 7 | 让监管者开一个执行窗口 | 被拒，说只能开调研小窗 |
| 8 | Codex 执行窗口里让它开子 agent | 没有 spawn_agent；续接后也没有 |
